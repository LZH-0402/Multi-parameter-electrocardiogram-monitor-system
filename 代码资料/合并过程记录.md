## 4. 冲突分析与解决

### 4.1 `main()` 冲突（两份都有）
- **冲突**：SPO2 与 BP 各自有 `int main(void)`，直接合并会重定义。
- **解决**：`USER/main.c` 重写为唯一入口，串行初始化后再跑合并主循环：
  1. `SysTick_Init()`（仅一次，1ms 节拍累加到 `uwTick`）
  2. `DEBUG_UART_Init()`（USART1 @115200 调试口）
  3. 按 `merge_cfg.h` 走 SPO2 屏路径或 BP 屏路径（见 §5）
  4. `USART6_UNO_Init(57600)`（SpO2 传感器，始终接 USART6）
  5. `app_init()`（BP 子系统：USART3 血压模块 + 屏初始化）
  6. 主循环：每秒心跳打印 + `HMI_Poll()`/`on_uno_frame()`/血氧显示任务（SPO2 模式）+ `app_loop()`（BP 始终运行）

### 4.2 `SysTick_Handler` 与 `g_tick` vs `uwTick` 冲突
- **冲突**：
  - SPO2：`sys.c` 定义 `volatile uint32_t uwTick`，`SysTick_Handler` 累加它；
  - BP：`app_bp.c` 定义 `volatile uint32_t g_tick`，`SysTick_Handler` 累加它，并自己调 `SysTick_Config()`。
  - 两份都实现 `SysTick_Handler` → 重定义；两份都有自己的计数器 → 语义重复。
- **解决**：
  - 仅保留 **一个** `SysTick_Handler`（在 `USER/stm32f4xx_it.c`），内部 `uwTick++`。
  - `app_bp.c` 删除 `g_tick` 定义与 `SysTick_Config` 调用（节拍已由统一初始化提供）。
  - 在 `HARDWARE/app_bp.h` 增加：
    ```c
    extern volatile uint32_t uwTick;
    #define g_tick uwTick          /* BP 旧代码里的 g_tick 全部指向同一个计数器 */
    ```
  - 结果：两套子系统共用同一 `uwTick`，符号冲突全部消除。

### 4.3 `USART2_IRQHandler` 冲突（屏驱动硬件互斥）★核心难点
- **冲突**：
  - SPO2 屏用 `dc_hmi` 驱动：USART2 @115200、RXNE 中断、回调 `HMI_RxByte()`；
  - BP 屏用 `hmi_dacai` 驱动：USART2 @9600、DMA+IDLE 中断、回调 `on_uart_rx_idle()`。
  - 两者都占用 USART2，且**波特率/中断方式不同，硬件上同一时刻只能接一块屏** → 不可共存。
- **解决**：**编译期二选一**（见 §5 `merge_cfg.h`）。
  - 删除 `HARDWARE/USART/usart.c` 中的 `USART2_IRQHandler`，集中到 `USER/stm32f4xx_it.c`：
    ```c
    #ifdef HMI_SCREEN_SPO2
    void USART2_IRQHandler(void){ /* RXNE -> HMI_RxByte */ }
    #else
    void USART2_IRQHandler(void){ /* IDLE -> on_uart_rx_idle（或 RXNE 回退） */ }
    #endif
    ```
  - `app_bp.c` 中 USART2 的外设初始化（USART_Init / ITConfig / DMA 流 / DMACmd）用 `#ifndef HMI_SCREEN_SPO2` 包裹，避免 SPO2 模式下重复初始化 USART2；USART3（血压模块）初始化始终保留。
  - `hmi_send_cb`（BP 屏的写屏回调）体用 `#ifdef HMI_SCREEN_BP` 包裹——SPO2 模式下 BP 屏不发数据，仅跑传感器逻辑。

### 4.4 `USART6_IRQHandler` 归属
- SPO2 的 USART6（接 UNO/AFE4490）中断原在 `HARDWARE/USART/usart.c`，与 BP 无冲突，保留不动；`stm32f4xx_it.c` 仅留注释说明，不重复定义。

### 4.5 Keil 工程文件 `*.uvprojx`
- 目标工程原本只有 `USER / CORE / FWLIB` 三组，无 HARDWARE 组、无 HARDWARE 头文件路径。
- 已补：
  - HARDWARE 组，含 10 个文件：`sys.c / debug.c / usart.c / dc_hmi.c / app_bloodoxygen.c / hmi_ids.h(头) / uno.c / app_bp.c / hmi_dacai.c / bp_sensor.c`
  - IncludePath 追加：`..\HARDWARE` 及 `..\HARDWARE\SYS;..\HARDWARE\DEBUG;..\HARDWARE\USART;..\HARDWARE\HMI;..\HARDWARE\UNO`
    （同时含根目录与各子目录，兼容 BP 头文件在 HARDWARE 根、SPO2 头文件在子目录两种布局）


1. 注释 `#define HMI_SCREEN_SPO2`，取消注释 `#define HMI_SCREEN_BP`；

## 9. 双屏双传感器并行改造（血氧屏 + 血压屏 同时工作）

> 本章**取代 §6 的 USART 资源分配表**（§6 是“两块屏共用 USART2、编译期二选一”的旧方案）。

### 9.1 目标
让血氧与血压**同时测量**、两块屏**同时刷新**：一次烧录后，血氧屏与血压屏各接一路串口，互不干扰。

### 9.2 新的 UART 分配（关键：血压传感器让出 USART3）

| 外设 | 引脚 | 用途 | 波特率 | 中断 | 驱动 |
|------|------|------|--------|------|------|
| USART1 | PA9/PA10 | 调试口 | 115200 | — | `debug.c` |
| USART2 | PA2/PA3 | **血氧屏** | 115200 | RXNE→`HMI_RxByte` | `dc_hmi` |
| USART3 | PB10/PB11 | **血压屏** | 9600 | RXNE→`on_uart_rx(USART3)` | `hmi_dacai` |
| UART5 | PC12/PD2 | **血压传感器 HKB-08B+** | 115200 | RXNE→`on_uart_rx(UART5)` | `bp_sensor` |
| USART6 | PC6/PC7 | 血氧传感器 UNO(AFE4490) | 57600 | RXNE→`UNO_ParseByte` | `uno.c` |

- 血压传感器由 **USART3 改接 UART5(PC12/PD2)**，从而把 USART3 让给第二块血压屏。
- 两块屏的物理通道：USART2→SP3232 通道1→`COM_M`；USART3→SP3232 通道2→`COM_G`。
- 两屏波特率须与各自屏工程 `DeviceBaudRate` 一致：血氧 `=7`(115200)、血压 `=3`(9600)。

### 9.3 硬件接线要点
- **血压屏（RS232）**：接 `COM_G`（第二路 DB9）——Pin2=屏RXD、Pin3=屏TXD、Pin5=GND。
- **血压传感器（TTL）**：接扩展口 `PC12(UART5_TX)→模块RX`、`PD2(UART5_RX)←模块TX`、共地。
- 若血压屏改走 P5（TTL 电平），须把屏的“串口类型”设为 TTL；且 P5 与 P1 蓝牙共用同一路 USART3，接屏时不要插蓝牙模块。

### 9.4 代码改动
| 文件 | 改动 |
|------|------|
| `HARDWARE/app_bp.c` | `SCREEN_UART`=USART3、`SENSOR_UART`=UART5；`uart_gpio_init/uart_periph_init/nvic_init` 改为配置 USART3+UART5；`hmi_send_cb` 去掉 `#ifdef HMI_SCREEN_BP`；接收去掉对 USART2 的占用 |
| `HARDWARE/app_bp.h` | `RX_USE_DMA_IDLE` 默认改为 **0**（BP 两路改走 RXNE，数据量小、实现简单、免抢 DMA 流） |
| `USER/stm32f4xx_it.c` | `USART2_IRQHandler` 固定 RXNE→`HMI_RxByte`（血氧屏）；`USART3_IRQHandler` 改为 RXNE→`on_uart_rx(USART3)`（血压屏）；**新增 `UART5_IRQHandler`**→`on_uart_rx(UART5)`（血压传感器） |
| `USER/main.c` | 去掉 `HMI_SCREEN_SPO2` 二选一，**同时**初始化血氧屏(USART2)+血压屏(USART3)+两传感器，主循环并行跑 `HMI_Poll/task_hmi_*/task_clock` 与 `app_loop()` |
| `USER/merge_cfg.h` | 取消 `HMI_SCREEN_SPO2/BP` 二选一宏，改为双屏并行说明 |
| `F:/VisualTFT/SPO2_Hospital/SPO2_Hospital.tftprj` | `DeviceEnableCRC` 由 `1` 改回 **`0`**（`dc_hmi` 组帧不带 CRC，血氧屏必须关闭 CRC） |

### 9.5 CRC 一致性（重要）
- 血氧屏用 `dc_hmi`：组帧**不带 CRC** → 屏工程 `DeviceEnableCRC` 必须 = **0**。
- 血压屏用 `hmi_dacai`：`HMI_USE_CRC=1` 每帧带 CRC-16/MODBUS → 屏工程 `DeviceEnableCRC` 必须 = **1**。
- 两端不一致：MCU 带 CRC / 屏不开 → 屏把 CRC 字节当文本（乱码）；屏开 CRC / MCU 不带 → 整屏不显。
- 修改 `.tftprj` 后须在 VisualTFT 中**重新编译并下载**对应屏，否则屏固件开关不变。
