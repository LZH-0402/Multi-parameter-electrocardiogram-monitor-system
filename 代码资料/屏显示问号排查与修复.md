# 大彩屏显示 `？？` 排查与修复记录（STM32F407_HOSPITAL / 血压屏）

> 适用工程：`STM32F407_HOSPITAL`，双屏双传感器并行架构（血氧屏 USART2@115200 + 血压屏 USART3@9600）。
> 血压屏走 `hmi_dacai` 驱动，USART3(PB10/PB11) @9600，`RX_USE_DMA_IDLE=0`（RXNE 逐字节中断）；`merge_cfg.h` 已无 `HMI_SCREEN_BP`/`HMI_SCREEN_SPO2` 二选一宏。
> 现象：测血压时，**袖带压力（数值类控件）** 与 **时间/已用时（中文文本类控件）** 后面**偶尔**出现 `？？`（“榜”为旁边静态标签被一起看到）。
>
> 注：本文早期章节（B/C/D）写于单屏时代，当时血压屏挂在 USART2@9600；后续双屏改造把血压屏挪到 USART3@9600，下文涉及串口编号处已按现行代码更正。

## 一、先排除的（已修复的）根因

| 轮次 | 现象 | 根因 | 修复 |
|------|------|------|------|
| B | 压力偶尔 `？？` | `BP_CMD_START` 帧未校验 `len`，异常/截断帧读到 `g_data[]` 旧字节产生伪数值（常达几千），写屏越界→`？？` | `app_bp.c` 加 `if (len < 2u) break;` + 量程保护 `p.pressure <= 600u`；`BP_CMD_RESULT` 加 `if (len < 5u) break;` |

## 二、本轮（D）根因：连续写文本帧“淹没”屏串口解析器 → 偶发黏帧

### 关键代码实证
- 屏发送路径 `uart_send_byte`（轮询 `USART_FLAG_TXE` 后 `USART_SendData`）→ `uart_send_buf` → `hmi_send_cb` → 血压屏串口（**USART3@9600**）。**全程轮询、阻塞、单线程**，一帧发完才发下一帧，字节绝不会自交错。
- `on_uart_rx` / `on_uart_rx_idle`（USART3/UART5 中断里）**只把收到的字节入环形缓冲，绝不写屏**。因此中断不会打断/抢占一次屏发送。
- ⇒ **屏收到的字节本身是正确的**，不是“软件把帧发错了”。

### 真正的触发点
`clock_broadcast()` 原本每秒把时钟 `B1 10` 写文本帧**广播到全部 0~9 页（10 帧背靠背）**；`status_set()` 在状态切换时也会向全部页写 4 个状态条控件。

大彩 M 系屏在**连续收到大量 `B1 10` 写文本帧**时，串口指令解析器偶发丢掉帧尾 `FF FC FF FF`，把相邻两帧黏成一帧解析成乱码 → 被屏渲染成 `？？`。这正好解释：
- 为什么**数值（压力）和中文（时间）两类内容都偶尔中招**——不是某种控件/内容的问题，而是**帧流被淹没后的随机黏帧**；
- 为什么是“偶尔”——只在大批量背靠背帧时小概率发生。

## 三、本轮（D）修复

核心思路：**屏同一时刻只显示一页，时钟只刷新“当前可见页”**，把每秒 10 帧降到约 1 帧；并周期回读屏当前页，保持“当前页”跟踪准确（含屏用“切页型”按钮自行跳页的情况）。

改动文件：
1. `HARDWARE/hmi_dacai.c`
   - 新增全局 `uint16_t g_hmi_cur_screen = 0;`
   - `hmi_change_page()` 内写入 `g_hmi_cur_screen = screen_id;`（MCU 主动切页时记录）
2. `HARDWARE/hmi_dacai.h`
   - 声明 `extern uint16_t g_hmi_cur_screen;`
3. `HARDWARE/app_bp.c`
   - `clock_broadcast()`：原来的 10 页 `for` 循环改为 `hmi_write_text(g_hmi_cur_screen, HMI_CTRL_CLOCK, b);`
   - `hmi_rx_frame()` 的 `B1 01`（查询当前页应答）分支：加 `g_hmi_cur_screen = scr;` 同步
   - `app_loop()`：每 3 秒调用一次 `hmi_get_screen()`，使 `g_hmi_cur_screen` 与屏实际显示页保持一致

> 说明：`status_set()` 仍向全部页写状态条（仅在状态切换时发生，频率低；且屏跨页保留控件值，切页后不丢字），未改为定点刷新以**避免切页后状态条变旧**的回归。如仍偶发，可一并改为定点刷新。
>
> 最新修复：本文件与屏工程均启用 CRC 后，上述黏帧/乱码已被协议层 CRC 兜底，基本可根除。

## 四、CRC 校验（MCU 与屏工程均已同步开启）

任务D 的"黏帧"修复（只刷可见页）已把偶发 `？？` 概率降到很低；若仍偶发，多半是 **9600 RS232 链路字节错**。协议层兜底 = 启用 CRC。

### 4.1 现象：只开 MCU 侧 CRC 时屏乱码

用户开启 MCU 侧 CRC 后，屏出现**新乱码**（例如时钟 `2026-01-01 00:04:53` 末尾多出一个 `&`）。根因：
- MCU 发出的写文本帧变成 `EE B1 10 ... <文本> <CRC:2> FF FC FF FF`；
- 屏工程 `DeviceEnableCRC="0"` 仍按**无 CRC** 解析，把帧尾前多出的 2 字节 CRC 当成**文本内容**塞进控件；
- 因此文本控件末尾会多出 1~2 个"随机字符"，正好对应 CRC 字节。

### 4.2 已修改的地方

| 位置 | 修改内容 |
|------|----------|
| `HARDWARE/hmi_dacai.h` | `HMI_USE_CRC` 宏从 `.c` 移到 `.h` 并固定为 `1`，整个工程可见。 |
| `HARDWARE/hmi_dacai.c` | 所有发屏帧自动附带 CRC-16/MODBUS（只对 body 计算，高字节在前，帧尾前）。 |
| `HARDWARE/app_bp.c` | `hmi_rx_frame` 在解析前剥离屏回传帧末尾的 2 字节 CRC，保持原 offset 不变。 |
| `F:/VisualTFT/BP_Hospital/BP_Hospital.tftprj` | `DeviceEnableCRC="0"` → `DeviceEnableCRC="1"`。 |
| `F:/VisualTFT/SPO2_Hospital/SPO2_Hospital.tftprj` | **保持 `DeviceEnableCRC="0"`**：血氧屏走 `dc_hmi`，组帧不带 CRC（见 `dc_hmi.h` 头注释），开 CRC 反而会导致血氧屏整屏不显。 |

### 4.3 注意事项

- **两端必须一致**：
  - 只开 MCU 不开屏 → 屏把 CRC 字节当文本渲染（如时钟末尾多 `&`）→ 整屏乱码；
  - 只开屏不开 MCU → 屏因帧格式不符整屏不显。
- 屏工程修改 `.tftprj` 后，**必须在大彩 VisualTFT 中重新编译并下载到屏**，否则屏固件里的 CRC 开关仍为 `0`。
- **检查硬件**：SP3232 供电/退耦、RS232 线缆与接地、屏与板子共地；确认**血压屏串口（USART3@9600）**波特率与屏一致。

## 六、切页后时钟跳变 / 各页时间不同步（本次新增修复）

### 6.1 现象
CRC 乱码修复后，用户反映：**每切换一个页面（或按一次按钮），时间都会自己“跳”一下**；并且**不同页面的时钟显示不一致**（各页时间没同步）。

### 6.2 根因
任务D 为避免黏帧，把 `clock_broadcast()` 从“广播 10 页”改成“只写当前可见页 `g_hmi_cur_screen`”，每秒 1 帧。但这带来副作用：

- 屏同一时刻只显示一页，**没被刷新的页面其时钟控件停在“上一次访问它时”的值**；
- 切到新页面时，新页要等**下一秒整点**或**3 秒周期轮询发现切页**后才被写入当前时间——
  - MCU 主动切页（`hmi_change_page`）：最多等 1 秒；
  - 屏自行切页（切页型按钮）：最多等 3 秒。
- 于是切页瞬间新页显示的是旧时间、随后跳到当前时间，看起来就是“时间自己跳、各页不同步”。
- 上一轮修复又给按钮按下额外加了 `hmi_get_screen()` 回读，等于每次按键都去重写一次时钟，更易被看到这个跳变。

### 6.3 修复（恢复“时钟广播到所有页”）
核心：**让每一页的时钟控件都每秒刷新当前时间**，这样无论切到哪一页都立即正确、不再跳；并去掉按键额外的回读。

1. `HARDWARE/app_bp.c`
   - `clock_broadcast()`：改回 `for (pg = 0; pg <= HMI_SCREEN_TIME; pg++) clock_write_to(pg);`，即每秒把当前时间写到 0~9 全部页的时钟控件(100)。
   - 把组帧逻辑拆出为 `clock_write_to(screen)`（单页写入），方便复用。
   - 移除按钮（0x11）按下时的 `hmi_get_screen()` 额外回读（不再需要，且会触发按键重写时钟的跳变观感）。
2. `HARDWARE/hmi_dacai.h` / `hmi_dacai.c`
   - 仍保留 `hmi_page_changed_cb_t` / `hmi_set_page_changed_cb()` / `hmi_fire_page_changed()` 与 `g_hmi_cur_screen`：
     `hmi_change_page()` 与 B1 01 应答仍会触发 `clock_on_screen_changed()` 把时钟立即补刷到新页（提供切页瞬间 0 等待的即时性，是广播之外的“双保险”，写入的是同一当前值，不会造成跳变）。

> 为什么恢复广播不会 reintroduce 黏帧/乱码：屏工程已设 `DeviceEnableCRC="1"`，MCU 发帧带 CRC-16/MODBUS。即使 10 帧背靠背发送，屏也能按 CRC 正确分拣帧、丢弃坏帧，而**不会**像任务D那样把相邻帧黏成一帧渲染成 `？？`。

### 6.4 效果
- 每一页的时钟控件都每秒更新当前时间，切到任意页都**立即正确，不再跳变**；
- 各页时间始终统一，不存在“各页不同步”；
- 保留页面变化回调作为即时补刷的双保险（写入同一当前值，无副作用）。

### 6.5 验证
1. 编译下载后，依次手动切所有页面（idle / measuring / result / history / settings / time 等）；
2. 观察切页后时钟是否**立即**显示当前正确时间（不再先旧值后跳变）；
3. 按任意按钮（包括不切页的按钮，如亮度±）后，时钟不应出现跳变；
4. 停留任意页面观察 1~2 分钟，时间应每秒 +1，且与其它页面一致。

### 6.6 风险与回退
- 广播 10 页≈每秒 10 帧写文本，串口占用较“只刷当前页”更高；在大彩 M 系屏 + CRC 下不会乱码，最坏情况只是偶发某页少刷新 1 秒（自纠正）。
- 若现场 RS232 链路质量极差、偶发丢帧导致个别页时钟偶尔慢 1 秒，可把广播频率降到每 2 秒一次，或改回“只刷当前页 + 页面变化回调”方案（但会有切页瞬间≤1秒的旧值窗口）。

## 七、测量（开始/停止）时时钟卡住后跳变（本次新增修复）

### 7.1 现象
CRC 与切页时钟都已正常后，用户反映：**点“开始测量”或“停止测量”时，屏上的时间不是每秒平滑 +1，而是卡住一会、突然跳到下一个（甚至后面几个）时间**。

### 7.2 根因：测量期高频气压写屏淹没 9600 串口，时钟帧被挤掉
- 屏发送全程是**轮询阻塞**（`uart_send_byte` 等 `TXE` 才发下一字节，`uart_send_buf` 串发整帧），一帧发完前主循环被卡住。9600 8N1 ≈ **960 字节/秒（≈1.04 ms/字节）**。
- 非测量时：`clock_broadcast()` 每秒向 0~9 页各写 1 帧时钟（每帧≈32 字节）→ ≈320 字节/秒 ≈ 33% 负载，时钟每秒平滑 +1，正常。
- 测量时（ST_MEASURING / ST_STOPPING）：传感器以 **约 10~50 Hz** 持续上报 `BP_CMD_START` 实时气压帧，原代码**每收到一帧就 `hmi_write_text` 写一次压力控件**（每帧≈15 字节）：
  - 10 Hz → +150 字节/秒；50 Hz → +750 字节/秒；
  - 叠加时钟广播 320 字节/秒，**合计 470~1070 字节/秒**，在高频段已**超过 960 字节/秒的物理上限**。
- 串口被气压帧占满时，屏 RX 缓冲溢出/解析器来不及处理，**时钟帧在屏端被排队甚至丢弃** → 可见的 measuring 页时钟在某几秒没刷新；当压力流速率变化（开始测量=流量起、停止测量=流量止）或链路稍松时，时钟帧才挤过去，于是表现为“卡住一会、突然跳到下一个时间”。正好对应“点开始/停止测量时出现”的时机。
- 注意：这不是又回到黏帧/乱码（帧内容本身正确），而是**时钟帧到达被延迟/丢弃导致的显示跳变**；CRC 只兜底坏帧，不解决“帧没到”。

### 7.3 修复：实时气压写屏节流（纯时间闸门）【重要修正】
思路：在不影响压力条观感的前提下，把气压写屏频率**恒定**压到串口安全范围内，给每秒的时钟帧“让路”。

改动文件：`HARDWARE/app_bp.c`
1. 新增节流状态（文件静态变量）：`static uint32_t s_press_send_tick = 0;  /* 上次写屏时刻 */`
2. `on_bp_frame()` 的 `BP_CMD_START` 分支：把“每帧必写”改为**纯时间闸门写**：
   - **仅按固定间隔刷新**：`now - s_press_send_tick >= 150u`（≥150 ms，≈6.7 Hz 上限）才写一次；
   - **不再使用“变化≥3mmHg 立即刷新”的闸门**（这是第一版仍跳的根因，见 7.3.1）；
   - 仍只在 `ST_MEASURING`（写 measuring 页 111）或 `ST_STOPPING`（写 stopping 页 111）时写，其它状态不写。
3. `bp_start_measure()`：开始测量时把 `s_press_send_tick = 0;` 复位，**首帧立即刷新**（不被 150 ms 闸门拦在上一轮残留值上）。

节流后最坏负载（恒定，与传感器报多快/压力变多大无关）：气压 ≈6.7×15≈100 字节/秒 + 时钟广播 320 字节/秒 ≈ **420 字节/秒 ≈ 44%**，远低于 960 上限，时钟帧每 1 秒都能准时到达，平滑 +1。

> 为什么不反过来“降时钟广播频率”：第六节的“广播到全部 10 页”正是为了解决切页跳变/各页不同步，已验证有效且不能回退。因此本次只压测量期新增的气压流量，保留时钟广播不动。

#### 7.3.1 第一版为何仍跳（已修正）
第一版用了“时间闸门(≥150ms) **或** 变化闸门(压力变化≥3mmHg 立即刷新)”。但开始测量（快速充气）、停止测量（快速泄气，压力骤降）时，相邻气压帧差常 ≥3 mmHg，于是**变化闸门几乎每帧都放行**，等效回到高频写屏 → 9600 串口再次被淹没 → 时钟仍卡住后跳（正对应“点开始/停止测量时跳”）。修正版去掉变化闸门、只留纯时间闸门，负载恒定封顶。

> 注：纯 150ms(6.7Hz) 刷新压力条肉眼仍平滑跟手；若现场感觉压力条稍钝，可把 `150u` 调小到 `100u`(≈10Hz)，仍安全。

### 7.4 效果
- 测量 / 停止过程中，屏上时间**每秒平滑 +1**，不再卡住后跳；
- 压力条仍跟手：150 ms 内随压力变化刷新，急变（变化≥3 mmHg）立即刷新，肉眼无差别；
- 切页同步、CRC 不乱码等既有修复不受影响。

### 7.5 验证
1. 重新编译 STM32 工程并下载；屏工程已使能 CRC，无需再改。
2. 进 measuring 页，点“开始测量”：观察时钟控件是否**每秒 +1**（而非卡几秒后跳）；同时压力条应平滑上升。
3. 测量中点“停止测量”：时钟仍应每秒 +1，直到回到 idle；不应出现停止瞬间时间“猛跳”。
4. 若现场仍偶发卡顿，可把时间闸门从 `150u` 调更小（如 `100u`，≈10 Hz）进一步降流量，或确认 RS232 线缆/共地（见 4.3）。

## 八、补记（2026-10-12）：时钟彻底退出文本链路

本文第 7 章的整套"时间闸门 / 分页节流"方案，是在**血压屏时钟为文本控件**的前提下做的流量优化。
2026-10-12 已把血压屏 `CLOCK`(id=100) 从 `type="text_display"` 改成 **`type="rtc"`**，
MCU 改用 **`EE 81`**（`hmi_set_rtc()`）设置屏内 RTC，屏自己走：

| | 文本控件时代（本文第 7 章） | 现在（RTC 控件） |
|---|---|---|
| 每秒帧数 / 字节 | 4~10 帧 / 147~340 B | **1 帧 15 B** |
| 9600 链路占用 | ~15% ~ 35% | **~1.6%** |
| 与"？？"的关系 | 写文本帧流是黏帧诱因之一 | **时钟完全不写文本控件，该诱因消失** |
| 各页一致性 | 靠广播/轮转保持 | 天然一致（同一屏内 RTC） |

- `clock_write_to()` / `clock_broadcast()` / `clock_pace_step()` / 页面变化补刷回调**均已删除**；
