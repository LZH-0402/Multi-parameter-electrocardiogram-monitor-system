## 续：error 65 access violation at 0x0000000C（仿真器取不到复位向量）

- 成因：Cortex-M 复位时内核固定从 **0x00000000** 取向量表，而本工程 Flash 在 0x08000000。CPU DLL `SARMCM3.DLL` 没加 `-REMAP` 时不会把 ROM 别名到 0，取不到复位向量 → PC 停在 0 → 反汇编窗口读 0x0000000C 时报 no 'read' permission（0x0C = 第 4 个向量，HardFault）。
- **根治**：`SARMCM3.DLL` 的 Parameter 填 **`-REMAP -MPU`**。依据：官方 `MCBSTM32F400\Blinky\Blinky.uvprojx`（STM32F407IG）就是 `<SimDllArguments>-REMAP -MPU</SimDllArguments>` + `SimDlgDll=DCM.DLL -pCM4`。本机 Keil_v514 的 SarmCM3.dll 二进制里确有 REMAP 字样。
- **不用改 uvprojx 的绕法**：在调试 ini 里手动设 SP/PC/VTOR（同官方 `Dbg_RAM.ini` 的 Setup() 写法）。
- 另：仿真器只映射程序段/数据段，**片上外设空间默认未映射**，访问 RCC(0x40023800)/GPIO(0x40020000)/USART2(0x40004400) 会继续报 error 65，需 `MAP 0x40000000,0x400FFFFF READ WRITE` 等。
- 本次 `COMDEBUG.ini` 改为：4 条 MAP（外设/位带/AHB2/PPB）+ Setup() 设 SP/PC/VTOR + 保留串口 VTREG 的注释说明。
- **仍未落盘**：uvprojx 的 `<SimDllArguments>` 还是空的（Keil 又开着了），需关掉 Keil 后补 `-REMAP -MPU`。

### 关键实测结论（后面改屏必看）
- **按钮跳转全部由屏内完成**：主界面 5 个导航键 + 各页"返回" + 暂停/清空的取消与确认，

- **两类按钮的上报语义不同，处理方式必须区分**（本次踩到并已修）：
  - `button_type=0` 瞬变：按下 state=1、松开 state=0 → 只处理 state=1；

### 功能实现要点
- 节拍（App_Tick，10ms 分频）：10ms 采样+波形 / 100ms 报警判定 / 400ms 刷当前页 / 1s 监护时长+RTC 同步 / 60s 趋势加点。
- **波形**：`s_win[300]` 滑动窗极值归一化 → 0~255，攒 10 点一帧 `GraphChannelDataAdd(0,19,0,...)`；
  100Hz 采样 → 10 帧/s ≈ 240B/s，115200 下余量充足。
- **报警**：SpO2 < 下限 或 PR > 上限，持续 3s（30×100ms 计数）才记一条；滞回 SpO2≥下限+2 / PR≤上限-5 解除并把该行改"已解除"。
  记录 4 行环形，最新插第 1 行；越限则 `SetBuzzer(200)`（受设置页声音开关控制）。
- **暂停闭环**：主界面"暂停"→屏跳暂停页→"确认"再按一次 toggle 监护状态（设计里没有"恢复"按钮，
  所以把确认键做成 暂停/恢复 切换，上下文文案由 MCU 改写）。
- **RTC**：每秒 `ReadRTC()`，回包 `NotifyReadRTC` 把 BCD 转十进制缓存，用于报警时间戳、状态更新时间、
  最近有效时间、趋势时间刻度。
- **抗启动时序**：上电 300ms 后推一遍初值；若一直没收到屏的任何回包（RTC/画面/按钮），每秒补发一遍初值，最多 5 次。
