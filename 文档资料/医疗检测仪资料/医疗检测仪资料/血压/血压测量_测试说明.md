## 步骤1b：屏链路诊断（分辨 RS232 链路 + 写文本 opcode）

> ✅ **已定位并修复（用户反馈屏=9600）**：屏工程实际波特率=9600，而我们代码原写死 115200，导致屏静默丢帧、完全不跳页（现象 C）。已把 `uart_periph_init()` 中 **USART3 改为 9600** 重新编译下载；USART1(调试)/UART5(传感器) 仍为 115200。请重新编译下载，按下方验收标准观察。

> 背景：步骤1 时屏停在 P00 默认文本，没显示我发的 `LINK OK`。原因有两种可能——  
> (A) RS232 链路本身没通（线/电平/波特）；(B) 链路通了，但写文本 opcode 不是 0xB1（旧固件用 0xB0）。  
> 本步用“跳页 + 双写”一次性区分。

### 上电后会做什么（新行为）

- 调试口(USART1)每秒仍打印 `[Ns] alive`。
- 上电立即在 **P00** 写两个测试串：`110="TRY-B1"`（用 opcode 0xB1）、`111="TRY-B0"`（用 opcode 0xB0）。
- 之后**每 2 秒**在 **P00 ↔ P01** 之间切换：
  - 切到 P01 时调试口打印 `-> P01`；
  - 切回 P00 时重写上面两个测试串，并打印 `P00 + wrote 110=TRY-B1(0xB1), 111=TRY-B0(0xB0)`。
- 屏口(USART3)实际发出的字节（每 2s 周期）：
  - `EE A5 01 FF FC FF FF`（切 P01）
  - `EE A5 00 FF FC FF FF`（切 P00）
  - `EE B1 00 6E 54 52 59 2D 42 31 FF FC FF FF`（P00/110 写 "TRY-B1"）
  - `EE B0 00 6F 54 52 59 2D 42 30 FF FC FF FF`（P00/111 写 "TRY-B0"）

### 屏工程前置要求（重要！否则测试看不出东西）

- **P00 必须有两个文本控件，ID 分别设为 110 和 111**（VisualTFT 里选中控件→属性→ID）。
  - 没有 110/111，写文本就“写到了不存在的控件”上，屏上自然没变化。
- **必须有一个 P01 页面**（内容随意，甚至空白页也行），这样“跳页”才看得见。
- 屏上电默认页应为 P00（VisualTFT 工程设置）。

### 验收标准（请逐项看屏 + PC 串口助手确认）

- [ ] 屏**每 2 秒在 P00 和 P01 之间来回跳**（肉眼可见页面变化）。  
  → 若会跳：说明 RS232 链路 + 切页 opcode(0xA5) 都正常，排除原因 (A)。  
  → 若完全不跳、一直停在 P00：说明链路/电平/波特有问题（见下“排错”）。
- [ ] P00 上**控件 110 出现 `TRY-B1`**：说明该屏认 **0xB1** 为写文本指令。
- [ ] P00 上**控件 111 出现 `TRY-B0`**：说明该屏认 **0xB0** 为写文本指令。
- [ ] PC 串口助手(USART1)看到 `-> P01` / `P00 + wrote ...` 周期性打印，证明 MCU 端发送逻辑在跑。

3. **屏根本不跳页** → 链路层面有问题，按下面排错，把结论告诉我我们一起修。

### 排错（仅当“屏不跳页”时出现）

- 确认屏的 RS232（DB9）确实接在板载 SP3232 出来的那一路（不是接错到别的地方）。
- 确认屏工程里“上电默认页”设置、以及波特率确实是 115200（VisualTFT 工程属性）。
- 用逻辑仪在 **PB10（USART3_TX）** 抓：每 2s 应能看到 `EE A5 ...` 字节；若抓不到，是 MCU/电平问题；若抓得到但屏不跳，是屏工程/屏侧问题。
- 串口助手看 USART1 的 `-> P01`/`P00 + wrote` 是否在打印——在打印说明 MCU 在发。

## 步骤2：传感器帧解析 + 实物链路诊断（已通过）

> 本步代码已落地：CKSUM 接收端 BUG 已修（旧代码把 CKSUM 字节自身累加进校验和，导致所有合法帧被丢弃；  
> 现改为只记录 `g_cksum_recv`）；`bp_sensor_feed()` 接入接收路径；上电 6s 自动发一次  
> `WAKE(0xAA)+START(0xA0)`；`app_loop()` 里有 `U3LOOP` 回环自测（每 3s 发 WAKE 并统计 UART5 收到的字节）。
>
> **接收架构（2026-10-09 加固）**：USART3/UART5 中断里**只把字节入队**（256 字节环形缓冲），  
> 打印 `RX2:XX`/`RX3:XX` 与 `bp_sensor_feed()` 解析全部放到 `app_loop()` 里做。  
> 原因：在中断里每收 1 字节就打 ~7 个调试字符（≈600µs@115200），而传感器在 115200 下每字节仅 87µs，  
> 真实传感器连发整帧时会在打印期间来不及读 RDR → ORE 溢出丢字节 → 多字节帧被打散、校验失败。

### 手册权威事实（HKB-08B+ V2.2，务必以此为准）

- **通信波特率 115200 bps，8N1（1 起始/8 数据/1 停止/无校验），全双工。**
- 帧格式：`0xFF 0xC0 | LEN | CKSUM | CMD | DATA...`；`LEN = 3 + N(DATA)`；`CKSUM = (LEN + CMD + ΣDATA) & 0xFF`。
- **★ 唤醒(0xAA) 有应答**：上位机发 `FF C0 03 AD AA`，传感器**回** `FF C0 03 AD AA`。  
  → **这是一个"活探测"**：只要传感器上电、接在 TTL、通路正确，U3LOOP 每 3s 发的唤醒就**必然**收到 `FF C0 03 AD AA` 回声。收到 0 → 传感器根本没在说话。
- 启动测量(0xA0) 应答 `FF C0 05 CKSUM A0 QYH QYL`（~10Hz）；结果 `FF C0 08 CKSUM AC SSYH SSYL SZYH SZYL XL`；错误 `FF C0 04 CKSUM AD X`。
- 数字接口三选一：**USB / RS232 / UART(TTL)** —— 必须用标 `RX/TX` 的 **TTL（UART）** 那组。

### 实测记录

> ★ **接线变更提示（2026-10）**：下方"实测记录 / 决策树"最初按**旧接线**记录——当时传感器接在 **USART3 / PB10·PB11**、屏接在 **USART2**。现已改为 **传感器 = UART5 / PC12·PD2（TTL 直连，不经 P5）**、**屏 = USART3 / PB10·PB11（经 SP3232 第二通道 → COM_G）**。日志里的 `RX2`/`RX3`/`U3LOOP` 是代码里**固定的队列索引标签**（`RX2`=屏、`RX3`=传感器），与具体物理串口无关，至今仍有效；但**回环短接、万用表探针等"动手"步骤的引脚要换成新值**：传感器回环/探针用 **PC12·PD2**，屏用 **PB10·PB11**。

- **2026-10-09（UART5 回环自测）**：短接 PB10↔PB11 后调试口出现

### 实物接线（方案 A，已与用户核对）

> ★ **串口改动（2026-10）**：传感器已改到 **UART5（PC12=TX、PD2=RX，115200）直连，不经 P5**；串口屏改到 **USART3（PB10=TX、PB11=RX，9600，经 SP3232 第二通道 → COM_G）**，**P5 排针现在载的是 USART3 的 TTL（接屏 TTL 时用，需拔蓝牙/无线）**。新接线拓扑以 `血压模块项目书.md` 2.2 节为准。

- 传感器 **GND → 板 GND**（共地，必须）
- 传感器 **5V → 板 5V**（注意：模块工作电流 350~500mA，见下方"供电坑"）
- 传感器 **RX（TTL 组）→ PC12（UART5_TX）**
- 传感器 **TX（TTL 组）→ PD2（UART5_RX）**
- **传感器直连 PC12/PD2，不碰 P5**：UART5 是 MCU 上独立的串口外设（PC12=发、PD2=收），与 P5 跳线排针无关；传感器线直接连到 PC12、PD2 这两个 GPIO 即可，**不要**接到 P5 上的任何脚（P5 现在是 USART3 屏的出口，接错会把屏和传感器并联抢线）。
- ⚠ 交叉接法：传感器 TX 接 MCU RX(PD2)，传感器 RX 接 MCU TX(PC12)。**别接反**。
- ⚠ **RS232（COM2）那一组不要接**——HKB 走 TTL，接 RS232 的 ±12V 电平读不到且可能打坏 IO。
- **传感器连接器上的 `3V`(3.3V) 脚不用接（悬空即可）**：它是模块内部把 5V 稳压出来的 **3.3V 输出**，本意是方便你给外部 3.3V 电路（如电平转换）取电，**不是 TTL 工作的必要输入**。HKB 的 TTL 串口逻辑电平就是 3.3V（正好和 STM32F407 的 3.3V IO 匹配，可直接连，不必串电阻/分压）。判断方法：模块上电后万用表量 `3V` 脚对 GND，若稳定 ~3.3V=输出（确认，悬空就行）；若 0V/悬空则可能是输入（需外供 3.3V，但此模块极少见）。
- **串口屏（USART3）接线**：
  - 方案A（RS232，推荐）→ **COM_G（J4，第二 DB9）**：`屏 DIN → COM_G Pin3(TXD，板→屏)`、`屏 DOUT → COM_G Pin2(RXD，屏→板)`、`屏 GND → Pin5/GND`。⚠ COM_G 为标准 DTE（Pin3=TX、Pin2=RX），与 COM_M 相反。
  - 方案B（TTL）→ 从 **P5 排针**（P5.pin3=USART3_TX/PB10、P5.pin4=USART3_RX/PB11）取电平；此时需拔掉 P5 上占着 USART3 的蓝牙/无线跳线帽，避免屏被抢线/悬空。

### 供电方式（二选一，电流都要够）

- **方式A（板供）**：传感器 5V → 板 5V，GND 共地。注意板 USB 5V 可能带不动 350~500mA（打气瞬间欠压不回声），建议板子用≥1A 5V 供电。
- **方式B（USB 自供，推荐）**：传感器自带 USB 口插**充电头/充电宝（≥1A，不插电脑）**&#x53D6; 5V 电；TTL 的 `GND/RX/TX` 照接，**5V 脚悬空**。
  - ⚠ USB 口同时是模块的第三个数字接口(USB-CDC)：插电脑会被枚举→模块可能切 USB 模式、**不再响应 TTL 命令**；故 USB 只取电、数据仍走 TTL。
  - ⚠ **必须共地**：USB 若接独立充电头（隔离输出），要把传感器 TTL `GND` 显式连到板 GND；若与板 CH340 接同一台电脑则地已共。
  - ⚠ 不要同时接传感器 5V 脚和 USB（两 5V 源并联会互灌）；USB 供电时 5V 脚悬空。
- 无论哪种：通电瞬间听/摸气泵"哒"一声或轻微震动、模块指示灯亮，才算真正上电。

## 步骤5：DMA+空闲中断 接收 + 实时气压写屏（代码已落地，待实测）

> **本步按用户选定范围实现**：① USART3(屏) + UART5(传感器) **接收改 DMA + 空闲中断(IDLE)**；② 测量中把 0xA0 实时气压写**测量页**。
> 中文状态（GBK）本步**未做**，留待下次（需实机屏文本控件挂 GBK/GB2312 字库）。

### 为什么要改（痛点回顾）
原来 USART3/UART5 用**单字节 RXNE 中断**：每来 1 字节进一次中断。虽然已用"中断只入队 + 主循环出队打印"躲开了 ORE 丢字节，但高速连发时中断频率仍高（115200 下每 87µs 一次）。
改成 **DMA + 空闲中断**后：DMA 硬件把字节直接搬进内存暂存区，**只有一帧收完（线路空闲 ≥1 帧时间）才进一次中断**，中断频率降为"每帧一次"。

### 代码改动（3 个文件）
- `HARDWARE/app_bp.h`
  - 新增开关宏 **`RX_USE_DMA_IDLE`（默认 1）**：=1 走 DMA+IDLE；=0 一键回退步骤4 的 RXNE 旧行为。
  - 新增声明 `void on_uart_rx_idle(USART_TypeDef *u);`
- `HARDWARE/app_bp.c`（步骤5 核心）
  - 新增 DMA 暂存区 `s_dma_screen_buf`/`s_dma_sensor_buf`（各 64B）与 `dma_rx_init()`：
    **USART3_RX→DMA1 Stream1 通道4、UART5_RX→DMA1 Stream0 通道4**（F407 固定映射），Normal 模式、字节宽度、内存自增。
  - `uart_periph_init()`：USART3/UART5 由"开 RXNE 中断"改为**只开 IDLE 中断**（USART1 调试口仍用 RXNE 回显）。
  - `app_init()`：在 `uart_periph_init()` **之前**调用 `dma_rx_init()`（先武装 DMA，再开 USART+IDLE，避免空窗误搬垃圾）。
  - 新增 `on_uart_rx_idle(u)`：读 DMA 剩余计数 → 把本帧字节按原逻辑 `on_uart_rx()` 入环形缓冲（计数器照旧）→ 重启 DMA。
  - 新增页面/控件宏：`HMI_PAGE_MAIN=0`、`HMI_PAGE_MEAS=1`、`HMI_CTRL_MAIN_A=110`、`HMI_CTRL_MAIN_B=111`、**`HMI_CTRL_PRESS=111`**。
  - `on_bp_frame()` 的 `0xA0` 分支：解析出气压后 `hmi_write_text(HMI_PAGE_MEAS, HMI_CTRL_PRESS, 数字串)` 实时刷到**测量页**（原来只打印调试口）。
- `USER/stm32f4xx_it.c`
  - `USART3_IRQHandler` / `UART5_IRQHandler`：`#if RX_USE_DMA_IDLE` 分支改为**判 IDLE 标志 → 读 SR 再读 DR 清标志 → 调 `on_uart_rx_idle()`**；`#else` 保留原 RXNE 分支。

> ★ 主循环 `app_loop()` 完全不变：`RX3:XX`/`RX2:XX` 逐字节打印 + `bp_sensor_feed()`/`hmi_rx_feed()` 解析照旧。所以调试口现象与步骤4 一致，只是底层收字节方式变了。

### 若"调试口有 PRESSURE 但屏上气压不动"——多半是控件 ID 不对
`HMI_CTRL_PRESS` 默认按 **测量页 + 控件 111** 猜（参考你的设计包 P02 的 PRESSURE 控件号）。**请在 VisualTFT 里看你实机测量页上气压控件的真实 ID**，若不是 111，改 `HARDWARE/app_bp.c` 顶部两行宏：
```c
#define HMI_PAGE_MEAS   1u    /* 你的测量页号（当前实测按钮跳到 1） */
#define HMI_CTRL_PRESS  111u  /* 你的测量页气压控件 ID */
```
改完 `Rebuild` 即可，无需动其它代码。
