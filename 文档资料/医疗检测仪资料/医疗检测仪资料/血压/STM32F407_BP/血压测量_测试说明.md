## ⚠ 修正记录（重要，先看）

### 【2026-10-09】★★ 帧格式纠错：屏不动的真因，跟 CRC 无关 ★★

- **旧代码把"切页"写成 `EE B1 <页号> FF FC FF FF` —— 这是错的。**  
  大彩协议里 **`B1 01` 是"查询当前画面"，`B1 00` 才是"切换画面"**。  
  所以以前发的 `EE B1 01 FF FC FF FF` 屏只会当成一次"查询"，页面根本不动。
- 正确帧（官方《大彩指令集》与本机 SPO2 工程 `mcu/hmi_tool.py` 完全一致，两处互证）：
  | 功能    | 帧（16 位参数"高字节在前"）                                              |
  | ----- | ------------------------------------------------------------- |
  | 切换画面  | `EE B1 00 <画面号:16> FF FC FF FF`                               |
  | 写文本   | `EE B1 10 <画面:16> <控件:16> <ASCII/GBK> FF FC FF FF`            |
  | 读控件值  | `EE B1 11 <画面:16> <控件:16> FF FC FF FF`                        |
  | 查询画面  | `EE B1 01 FF FC FF FF`（屏应答 `EE B1 01 <画面:16> FF FC FF FF`）    |
  | 曲线灌数据 | `EE B1 32 <画面:16> <控件:16> <通道:8> <点数:16> <数据...> FF FC FF FF` |
- **已改**：`hmi_dacai.c/.h` 全部按上表重写（API 增加 `screen_id` 参数），`app_bp.c` 改为调用封装，  
  不再手拼帧；并新增每轮一次的"查询画面"自测。

### 【2026-10-09】关于 CRC（结论：不用改 CRC，别在指令助手勾它）

- 官方明确 **CRC 是可选**的，帧为 `EE <命令+参数> CRC16 FF FC FF FF`；**CRC 不含帧头帧尾**。
- 本工程屏 `DeviceEnableCRC="0"` → **屏不校验 CRC**，帧内不能带 CRC。  
  兄弟工程 SPO2 同样是 `DeviceEnableCRC="0"`，其 `dc_hmi.h` 注释也写明"不启用 CRC"。
- **所以：指令助手的 `CRC16校验` 勾选框不要去勾**（勾了会多 2 字节，屏解析失败）。  
  MCU 侧 `hmi_dacai.c` 已留 `HMI_USE_CRC` 宏（默认 0），需要时再统一开启。
- CRC 算法（备查，与指令助手输出反推一致）：**CRC-16/MODBUS**，只对"命令+参数"计算，  
  **高字节在前**，插在帧尾前。例：`B1 01` → `20 B4`，即 `EE B1 01 20 B4 FF FC FF FF`。

### 【2026-10-08】其余修正

- 波特率索引核实：本机 SPO2 工程 `dc_hmi.h` 注释写明 `DeviceBaudRate="7" => 115200`，

### 上电后会做什么（当前代码行为）

### ★★★【2026-10-09 原理图证实】真凶很可能是 **P3 跳线选了 RS485**——把 USART2 从屏上切走了 ★★★

依据：板载原理图 `F:\嵌入式\课件资料\1_开发资料\STM32F407_原理图.pdf`（神舟号 V2.0，第 5 页）。

**P3 = "RS232/RS485" 选择跳线（6 pin，2 列×3 行），管的是 USART2(PA2/PA3)：**

| 排   | 左列                   | 右列                   | 归属                                                  |
| --- | -------------------- | -------------------- | --------------------------------------------------- |
| 第1排 | `485_TX`             | `485_RX`             | **RS485**（U4 SP3485）                                |
| 第2排 | `PA3_RX`(=USART2_RX) | `PA2_TX`(=USART2_TX) | **MCU USART2**                                      |
| 第3排 | `COM1_T`(=R1OUT)     | `COM1_R`(=T1IN)      | **RS232**（U8 SP3232 通道1 →`232TX/232RX`→**RS2 口→屏**） |

> ⚠ **关键**：SP3232 的 `T1IN/R1OUT` 是**接在 P3 上**的，**不是**硬连到 PA2/PA3。  
> **P3 跳到哪一排，USART2 才连到哪里。**

**现状（你的实测）**：两个跳线帽在 **第1排(485)**：`485_TX→PA3_RX`、`485_RX→PA2_TX`  
→ **USART2 被切去 RS485，SP3232 的输入/输出全部悬空 → 屏收不到、MCU 也收不到屏的应答 → `RX2` 恒为 0。**  
✅ 这正好解释"电平模式/接线方向/波特率/协议全都对，却五个档位都是 0 应答"——**这才是真凶，不是 SP3232 坏。**

**修法（一步，先做这个！）**：把 P3 的**两个跳线帽整体下移一排**（由 第1排↔第2排，改插成 第2排↔第3排），  
即变成 `PA3_RX↔COM1_T`、`PA2_TX↔COM1_R` → 通路为 **USART2 ↔ SP3232 ↔ RS232(RS2) ↔ 屏**。  
改完重新上电，看调试口是否出现 `[SWEEP] baud = 9600 -> RX2 bytes = N   <<< SCREEN ANSWERED!`。

## 步骤2：传感器帧解析（bp_sensor_feed + 调试口打印）

> 目标：UART5 收到 HKB-08B+ 的字节逐字节喂 `bp_sensor_feed()`，解出帧后通过调试口(USART1)打印命令字 + 解析结果，  
> **不依赖屏就能验证传感器链路**（屏链路由步骤1b 已确认）。

### ⚠ 接线前必做：传感器用 UART5 直连，P5 不再管传感器

- **传感器接 UART5（PC12/PD2），TTL 直连，不经任何跳线**：UART5 是 MCU 上独立外设（PC12=TX、PD2=RX），与 P3/P5 排针无关，直接接这两个 GPIO 即可。
- **P5 排针现在载的是 USART3 的 TTL（屏用）**：若屏走 TTL，从 P5.pin3=USART3_TX/PB10、P5.pin4=USART3_RX/PB11 取；此时需拆掉 P5 上占着 USART3 的 WB 无线跳线帽（否则无线模块与屏并联抢线）。**传感器不接 P5**。

### 接线（HKB-08B+ 是 TTL 3.3V，不是 RS232）

- 传感器直接接 UART5（**不要经过 SP3232**，那是给屏 RS232 用的）：
  | HKB-08B+ | 方向 | 板（神舟号）                             |
  | -------- | -- | ---------------------------------- |
  | TX       | →  | **PD2**（UART5_RX）                 |
  | RX       | ←  | **PC12**（UART5_TX）                |
  | GND      | —— | **板 GND**（共地！）                     |
  | VCC      | 供电 | 传感器自带 5V 供电（或板 5V，确认电流够；别从 PA 口取电） |
- ⚠ 注意交叉：**传感器 TX → MCU RX(PD2)，传感器 RX → MCU TX(PC12)**（和屏 RS232 一样是 DTE↔DTE 交叉）。
- 传感器波特率固定 **115200 / 8N1**（已核对手册 V2.2；UART5 已在 `uart_periph_init()` 配 115200）。


### 上电后会做什么（步骤2 代码行为）

- `app_init()` 新增：`bp_sensor_init(on_bp_frame)` —— 注册帧解析回调。
- `on_uart_rx()` 的 UART5 分支：除保留 `RX3:XX` 十六进制打印（便于看原始字节）外，新增 `bp_sensor_feed(b)` 喂解析器。
- `on_bp_frame()` 回调：每解出一帧（已通过校验和）打印一行 `>>> BP FRAME cmd=XX len=N ...`：
  - `0xAC 结果`：`RESULT SYS=收缩压 DIA=舒张压 HR=心率 IRR=不齐位(0/1)`
  - `0xA0 气压`（测量中约 10Hz）：`PRESSURE=当前气压mmHg beat=心跳位(0/1)`
  - `0xAD 错误`：`ERROR code=错误码`（`0=无脉搏 1=11s打不上50mmHg 2=数值有误 3=超压 4=干预过多`）
  - 其它命令字：原样打印 DATA 十六进制。
- `app_loop()` **上电 6s 后自动发一次 `唤醒(0xAA)+启动测量(0xA0)`**（`bp_send_cmd`），让传感器开始输出气压帧 + 结果帧，便于一次刷机就验证解析。  
  **仅触发一次**（避免气泵反复打气）；正式流程在步骤4 改为由屏按钮触发。

### ★ 修复的 BUG（步骤2 关键，已改 `bp_sensor.c`）

- 原 `bp_sensor_feed()` 在 `S_CKSUM` 状态把 **CKSUM 字节本身也累加进校验和**（`g_sum += b`），  
  导致所有合法帧 `g_sum != g_cksum_recv` 被丢弃 —— 表现就是"传感器明明有数据，MCU 却永远解析不出帧"。
- 按手册 CKSUM0 公式 `CKSUM = (LEN + CMD + sum(DATA)) & 0xFF`（**不含 CKSUM 自身**）修正：  
  `S_CKSUM` 只记录 `g_cksum_recv = b`，不再 `g_sum += b`。发送端 `bp_make_cmd()` 本来就是正确的，收发现在一致。
- 已用纯 C 状态机 + 合成帧做算法验证：修复后正确解出 `RESULT(SYS=190/DIA=120/HR=72)`、`PRESSURE(100)`、`ERROR(1)`；  
  旧 BUG 版对这三帧全部丢弃（印证 BUG 真实存在）。

### 排错（步骤2）

- **完全收不到 RX3**（连 FF C0 都没有）：查 TTL 交叉（传感器 TX→**PD2**、传感器 RX→**PC12**、共 GND）；  
  查传感器供电（VCC/GND 到位、LED 亮）；查 UART5 波特率 115200；确认传感器是接在 **UART5/PC12·PD2** 而非 P5（P5 现在是屏的）。
- **有 RX3 但从不出现 `>>> BP FRAME`**：多半帧头/校验问题。本步已修 CKSUM BUG，若仍不行，用逻辑仪抓一帧原始字节发我核对 LEN/CKSUM。  
  注意：HKB 复位帧是 `FF 00` 两字节（无帧头 0xC0），解析器会忽略它（S_WAIT_C0 收到 0x00 回到 S_WAIT_FF），不影响。
- **只有 PRESSURE 没有 RESULT**：气袋没绑紧/没接气泵 → 11s 后回 `0xAD code=1`；或测量被打断 → `0xAD code=4`。绑好气袋再测。

### 6.4d ★ 亮度调节（**本次新增**）

屏工程 settings 页本来就有 `btn_brightness_minus(10)` / `btn_brightness_plus(11)` 两个**瞬变型**按钮，但 MCU 侧此前未接。

- **MCU 侧实现**：
  - `s_bright_percent`（0~100，人眼语义）→ 宏 `HMI_BACKLIGHT_MAP(p) = 255 - p*255/100` 转成屏的"暗度"值。
  - 范围限制 **20%~100%**（`BRIGHT_MIN_PERCENT`/`MAX`），步进 **20%**（`BRIGHT_STEP`），**防止调到 0 黑屏**。
  - `bright_step(dir)`：改百分比 → `bright_apply()` 发 `0x60` 指令 → `bright_show()` 刷新 settings 页 `BRIGHTNESS(110)` 显示（如 `80%`）。
  - 上电 `app_init()` 调 `bright_apply()` 应用默认 100%；进 settings 页时 `bright_show()` 刷新显示。
  - 调试口打印 `>>> BRIGHT 80%`。

### 6.4f ★★ 修复：点"停止测量"后卡死在 stopping 页（**实机 BUG，已修**）

**现象**（用户实机照片，2026-10-09）：点停止后屏停在 stopping 页，显示"已停止 / 本次测量已取消 / 停止请求已提交 / 暂不可开始新测量"，**无法重新测量**。

**根因（两处叠加）**：

1. **`stopping` 页唯一的按钮 `btn_stop(10)` 是「瞬变型」`button_type=1`** —— 屏**不会自己跳页**，必须由 MCU 主动 `hmi_change_page()` 把它送走。而原代码 `BP_CMD_STOP` 分支里**根本没有 `hmi_change_page()`**（当初的设计选择是"留在 stopping 页"，但对瞬变型按钮来说，等于永久卡住）。
2. **实际入口判断错了**：`measuring` 页的 `btn_stop` 是**切页型**（`switch=stopping`），屏会**先自己跳到 stopping** 再上报事件，所以上报的画面号是 **stopping(7)** 而不是 measuring(1)。原代码在 `HMI_SCREEN_STOPPING` 分支里要求 `s_state == ST_MEASURING` 才动作 —— 这个条件本身是对的，但配合第 1 点就形成了死锁闭环。

**修复方案（不等传感器应答，立即脱困）**：

- **`stop_measure()` 改为：发 `0xA1` → 写 stopping 页"正在停止" → `status_refresh()` → 立即 `hmi_change_page(HMI_SCREEN_NOTICE)`**。
  - **不再等 `0xA1` 应答**。理由：气阀放气需要时间，且传感器掉电/断线时 `0xA1` 应答**永远不会来**，"等应答"必然卡死。
  - 切到 **notice 页**（而不是 idle）：notice 页有 **`btn_retry(10)`＝重新测量** 和 **`btn_back(11)`＝返回** 两个切页型按钮，是天然的"可重测"落点。
- **`notice_show(255)` 在切页前先写好**："本次测量已取消，可重新测量"，避免用户先看到旧文案。
- **新增超时兜底**：`app_loop()` 里若 `s_state==ST_STOPPING && !s_stop_acked` 超过 **1500ms**，强制 `s_state=ST_IDLE` + 记一条"已取消"历史 + 刷新状态文案 + 调试口打印 `[BP] STOP timeout (no 0xA1 ack) -> force IDLE`。
- **`BP_CMD_STOP` 应答分支**：改为只做"补正"（写 stopping 页最终文案 + 记历史 + 归位状态 + 刷新 notice 提示），**不再强制跳页** —— 以免用户已经自己走到别的页面时又被拽回来。加 `s_stop_acked` 标志防重复记录。
- **新增变量**：`s_stop_tick`（发 `0xA1` 时刻）、`s_stop_acked`（是否已确认）。`bp_start_measure()` 里清 `s_stop_acked`。
- `HMI_SCREEN_STOPPING` 分支放宽为 `s_state==ST_MEASURING || s_state==ST_STOPPING` 都允许再次触发（幂等，重发 `0xA1` 并重新计时）。

**修复后的操作流**：

```
measuring 点"停止" → 屏自跳 stopping → 上报事件(scr=7,ctrl=10)
  → stop_measure()：发 0xA1 + 写"正在停止" + 【立即切到 notice】
  → notice 页显示"本次测量已取消，可重新测量"
      ├─ 点"重新测量" → 屏自跳 measuring → MCU 发 WAKE+START ✅ 可继续
      └─ 点"返回"     → 屏自跳 idle ✅
  → 若传感器 1.5s 内回了 0xA1：补正 stopping 页文案 + 记历史（用户看不到，因为在 notice 页）
```

**验收**：
1. measuring 页点"停止" → 屏**立刻**跳到 notice（不再停在 stopping 页）。
2. notice 页点"重新测量" → 正常进入 measuring，气压/已用时正常刷新。
3. 拔掉传感器再点"停止" → 也应立刻跳 notice（1.5s 兜底不会永久卡住）。
4. 调试口：`[BP] STOP requested (0xA1) -> notice page`；若传感器不回，1.5s 后出 `[BP] STOP timeout (no 0xA1 ack) -> force IDLE`。

### 6.5 已知限制 / 回退

- **时间不掉电保持**：纯 MCU 软件 RTC，每次上电从 `2026-01-01` 重新走（**已可用 time 页手动校准**）。  
  掉电保持需外加 RTC 电池或把基准存 EEPROM（本步未做）。
- **历史不掉电保持**：`s_hist[100]` 在 RAM，复位即清空；容量 100 条，满后循环覆盖。
- **中文串用 GBK `\xNN` 转义**写死在 `app_bp.c`（AC5 无法吃 UTF-8 中文），源文件保持纯 ASCII。前提是屏控件挂了 GBK 字库（本工程 font 5/6/7/9 均为中文库，已确认）。
- 回退：保留本文件上一版 hex；如需回到步骤5 行为，注释掉 `app_loop()` 里的 1s 节拍块即可（时间/已用时/历史刷新全部停）。

> 合规提醒：该屏不得用于医疗/救生唯一控制设备；本系统仅作学习/原型。

### 6.6 步骤7：血压正常范围判定（新增）

**需求背景**：用户在结果页希望能直接看到本次血压是否"正常"，而非只显示三个原始数值。

**实现位置**：`HARDWARE/app_bp.c`
- 新增范围常量（步骤7 块，位于 `result_show()` 之前）：
  `BP_SYS_LO=90 / BP_SYS_HI=139 / BP_SYS_H1=140 / BP_SYS_H2=160`、`BP_DIA_LO=60 / BP_DIA_HI=89 / BP_DIA_H1=90 / BP_DIA_H2=100`、`BP_PR_LO=60 / BP_PR_HI=100`（单位 mmHg / bpm）。
- 新增两个函数：
  - `bp_classify(sys, dia)` → 返回**血压分级标题**（GBK 转义串）。诊断取收缩压/舒张压中**较高**分级：
    | 分级 | 条件 | 屏上标题 |
    |------|------|---------|
    | 正常 | SYS 90~139 且 DIA 60~89 | `血压正常` |
    | 偏低 | SYS<90 或 DIA<60 | `血压偏低，请关注` |
    | 偏高（1级） | SYS 140~159 或 DIA 90~99 | `血压偏高，请注意` |
    | 高血压（2级） | SYS≥160 或 DIA≥100 | `血压过高，建议就医` |
  - `bp_pr_note(pr)` → 返回**脉率提示**：`pr>100` 写 `心率偏快，请注意`；`pr<60` 写 `心率偏慢，请关注`；正常返回空串。
- 改造 `result_show()`：
  - `TIP_TITLE(103)` 写 `bp_classify()` 的分级标题（取代原固定的"测量完成"）。
  - `TIP_DETAIL(104)` 写**合并提示** = 脉率提示 +（若 `irregular`）`心率不齐，请由专业医护人员评估`，两项之间用 `； ` 分隔；均无则写空。
  - 原结果分支里对 TIP_TITLE/TIP_DETAIL 的重复写入已删除（统一由 `result_show()` 处理）。

**判定依据**：成人静息态临床参考范围（中国高血压防治指南 / AHA 常用分界）。**注意**：这只是"参考提示"，不构成诊断；异常时应以专业医护人员判断为准（屏上"建议就医"提示已体现）。

**GBK 注意**：所有新增中文提示均为 GBK `\xNN` 转义（AC5 不吃 UTF-8）。

**编译**：`UV4.exe -b` 命令行 → **0 Error / 0 Warning**，`Code=12392`（较步骤6 增 276 B），产物 `OBJ/STM32F407_Template.hex`。

**验收**：
1. 测出正常血压（如 120/80，PR 72）→ 结果页标题显示 `血压正常`，详情为空。
2. 偏高（如 150/95，PR 72）→ 标题 `血压偏高，请注意`。
3. 高血压（如 170/105）→ 标题 `血压过高，建议就医`。
4. 偏低（如 85/55）→ 标题 `血压偏低，请关注`。
5. PR 异常（如 55 或 110）→ 详情显示 `心率偏慢…` 或 `心率偏快…`；若有心率不齐，详情追加 `；心率不齐，请由专业医护人员评估`。
