# 基于 STM32F407 的无创血压（NIBP）测量模块项目书

## 摘要

本项目为"多参数心电监护仪系统"中的**无创血压（NIBP, Non-Invasive Blood Pressure）子系统**，目标是完成从传感采集、信号解析、状态管理到人机交互的完整闭环。系统以 STM32F407ZGT6 为主控，通过 UART 驱动 HKB-08B+ 示波法血压测量模块完成充放气与血压解算，并以大彩（Dacai）组态串口屏作为本地人机界面，实现测量启动/停止、实时气压与时序显示、结果展示、历史记录翻页、时间校准与亮度调节等功能。

项目采用标准外设库（SPL）开发，工程规模约 3200 行 C 代码，最终固件 `Code=12116 B / RO-data=472 B / RW-data=128 B / ZI-data=3344 B`，Keil AC5 编译零错误零警告，已在实机上完成多轮联调与验收。

## 1 项目概述

### 1.1 项目背景与需求

血压是心电监护仪的核心生命体征参数之一。在"多参数心电监护仪系统"的整体架构中，血压模块承担独立的测量与展示职责，需要满足以下需求：

1. **能够独立完成一次完整测量**：从用户触发开始，经充气、放气、脉搏波检测，到得出收缩压（SYS）、舒张压（DIA）、脉率（PR）三个结果。
2. **具备明确的测量状态反馈**：用户必须能在屏上区分"空闲""测量中""停止中"三种状态，避免出现"按了没反应"或"卡在某个页面出不来"的体验缺陷。
3. **异常可控**：气袋未绑好、测不到脉搏、超压、干扰过多等异常情况须有明确提示，并允许用户重新测量。
4. **测量过程可中断**：用户应能随时停止正在进行的测量，且停止后系统必须回到可再次测量的状态。
5. **结果可追溯**：保留本次会话内的测量记录，支持翻页查看。
6. **设备基本设置**：支持时间校准与屏幕亮度调节。

### 1.2 功能设计

系统按"页"组织功能，共设计 10 个界面，覆盖完整操作链路：

| 页面 | 页面号 | 核心功能 |
|------|-------|---------|
| 主页面 idle | 0 | 显示上次测量结果、当前时间、状态提示；提供"开始测量/历史/设置"入口 |
| 测量页 measuring | 1 | 实时显示当前气压（mmHg）、已用时长（mm:ss）、测量状态 |
| 结果页 result | 2 | 展示本次 SYS / DIA / PR；提供"再次测量/历史/换患者" |
| 异常页 notice | 3 | 展示错误码与处理建议；提供"重新测量/返回" |
| 历史页 history | 4 | 4 行 × 6 列记录表格，支持上一页/下一页翻页 |
| 设置页 settings | 5 | 亮度加减、进入时间校准、进入维护页 |
| 维护页 maintenance | 6 | 授权状态说明（当前仅展示，不开放写操作） |
| 停止页 stopping | 7 | 停止过渡态显示 |
| 确认页 confirm | 8 | 换患者二次确认，清空上次结果 |
| 时间页 time | 9 | 年/月/日/时/分 五字段编辑与保存 |

**测量状态机**设计为三态：

```
  ┌──────────┐  按下"开始测量"   ┌─────────────┐
  │  ST_IDLE │ ───────────────→ │ST_MEASURING │
  │  （空闲） │                  │  （测量中）  │
  └──────────┘ ←─────────────── └─────────────┘
        ↑         收到结果/错误/超时     │ 按下"停止"
        │                              ↓
        │                        ┌─────────────┐
        └────────────────────────│ST_STOPPING  │
              收到停止应答 / 1.5s 超时  │ （停止中） │
                                  └─────────────┘
```

### 1.3 技术方案

| 层次 | 方案选择 | 选型理由 |
|------|---------|---------|
| 主控 | STM32F407ZGT6（168 MHz） | 性能充裕，外设丰富，双板（血压/血氧）可复用同一套底层 |
| 血压采集 | HKB-08B+ 示波法模块 | 模块自带气泵、气阀与解算算法，串口输出结果，无需自研气路控制 |
| 人机界面 | 大彩 DC80480DN050 组态串口屏 | 组态化开发，界面与业务解耦；MCU 仅通过串口读写下发指令 |
| 驱动库 | ST 标准外设库（SPL） | 与课程教学环境一致，寄存器级可控，便于调试 |
| 工具链 | Keil MDK AC5 | 与既有工程链一致，支持命令行批量编译 |
| 通信 | 3 路独立 UART | 调试、屏、传感器物理分离，互不干扰 |

## 2 硬件设计

### 2.1 硬件选型

**（1）主控板：STM32F407ZGT6 神舟号 V2.0（郑州精畅科技）**

- 内核 Cortex-M4F，主频 168 MHz（8 MHz HSE 经 PLL 倍频）
- 1 MB Flash / 192 KB SRAM，满足固件与 100 条历史记录缓存需求
- 板载资源：SP3232（RS232 电平转换）、SP3485（RS485）、TJA1050（CAN）、CH340（USB 转串口）、LAN8720A（以太网）、24C02（I2C EEPROM）

**（2）血压传感器：HKB-08B+ 示波法血压测量模块**

- 测量原理：示波法（Oscillometric），通过气袋压力振荡幅值包络推算平均压，再以经验系数导出收缩压/舒张压
- 内置气泵与放气阀，测量过程自动完成充放气
- 对外提供三种数字接口：USB / RS232 / UART（TTL），三选一
- 供电：5 V DC，工作电流 350 ~ 500 mA（气泵、气阀为耗电主体）
- 通信参数：**115200 bps，8N1**，全双工

**（3）显示设备：大彩 DC80480DN050_1111_0C 组态串口屏**

- 5 英寸 800 × 480 分辨率，电容触摸
- 型号末段编码含义：`0` = RS232 接口，`C` = 电容触摸
- 出厂默认 RS232 模式，与板载 SP3232 匹配
- 通信参数：**9600 bps，8N1**
- 帧格式：`EE` 帧头 + 命令体 + `FF FC FF FF` 帧尾，**不启用 CRC**

### 2.2 接口设计与引脚分配

三路 UART 分工明确，物理层完全隔离：

| 串口 | 引脚 | 波特率 | 对接设备 | 电平 | 用途 |
|------|------|--------|---------|------|------|
| USART1 | PA9 (TX) / PA10 (RX) | 115200 | PC（CH340） | TTL via USB | 调试日志输出 |
| USART2 | PA2 (TX) / PA3 (RX) | 9600 | 大彩串口屏 | RS232（经 SP3232） | 屏指令收发 |
| USART3 | PB10 (TX) / PB11 (RX) | 115200 | HKB-08B+ 模块 | TTL 3.3 V | 传感器协议收发 |

引脚复用均配置为 AF7（USART 功能）。

**关键跳线（易错点，务必按引脚号接线）**

板载 P3、P5 两组 2×3 排针通过跳线帽决定 USART 的物理去向：

- **P3 = "RS232 / RS485" 选择，管 USART2**
  - pin1 = `T1IN`、pin2 = `R1OUT`（SP3232 通道1 → RS232 → 屏）
  - pin3 = `USART2_TX`(PA2)、pin4 = `USART2_RX`(PA3)
  - pin5 = `RS485_RX`、pin6 = `RS485_TX`（SP3485）
  - **接屏：跳线帽插 pin3/4 ↔ pin1/2**；若误插 pin3/4 ↔ pin5/6，USART2 会被切到 RS485，屏收不到任何数据。

- **P5 = "RS232 / BLE / WIFI" 选择，管 USART3**
  - pin1 = `T2IN`、pin2 = `R2OUT`（SP3232 通道2）
  - pin3 = `USART3_TX`(PB10)、pin4 = `USART3_RX`(PB11)
  - pin5 = `GBC_RX`、pin6 = `GBC_TX`（无线模块座）
  - **接传感器方案 A**：拆掉跳线帽，传感器 RX/TX 直接接 P5.pin3/pin4 + GND
  - **接传感器方案 B**：保留跳线帽，拔掉无线模块，把传感器插到无线座
  - ⚠ 常见错误：**拆了跳线帽却把传感器插在无线座上**，会导致 USART3 完全悬空，一路收不到任何字节。

**接线示意**

```
STM32F407                         HKB-08B+
  PB10 (USART3_TX) ──────────────→ RX
  PB11 (USART3_RX) ←────────────── TX
  GND              ─────────────── GND
  （5V 由独立电源供给，≥1A）

STM32F407                        大彩串口屏
  PA2 (USART2_TX) → SP3232 → RS232 TX ─→ DIN
  PA3 (USART2_RX) ← SP3232 ← RS232 RX ←─ DOUT
  （屏与板均为 DTE，需 TX↔RX 交叉）
```

### 2.3 使用方法

1. **上电**：板卡与屏分别供电，屏进入主页面（idle），右上角开始显示走时。
2. **自检**：MCU 上电后向屏发送"查询当前画面"指令，屏应答即证明**接线、波特率、帧格式三项均正确**——这是最可靠的链路自检手段。
3. **测量准备**：将气袋绑于上臂，松紧以能插入一指为宜，气管插紧无漏气。
4. **开始测量**：在主页点"开始测量"，屏切换至测量页，观察气压上升与用时递增。
5. **读取结果**：测量完成后系统自动跳转结果页，显示 SYS / DIA / PR 三个数值。
6. **查阅历史**：点"历史"进入记录页，使用上一页/下一页翻页。
7. **异常处理**：若出现异常页，按提示检查气袋/管路后点"重新测量"。
8. **中断测量**：测量过程中点"停止测量"，系统立即响应并回到可重测状态。

## 3 软件设计

### 3.1 软件架构

固件采用分层结构，硬件相关与协议相关代码严格分离，`bp_sensor.c` 与 `hmi_dacai.c` 均为**纯 C、不依赖任何 MCU SDK**，可移植到其他平台。

```
USER/main.c
    └── app_init() / app_loop()            应用层（app_bp.c，约 1380 行）
         ├── HARDWARE/bp_sensor.c          传感器协议层（145 行，纯 C）
         │    组帧 / 逐字节流式解析 / 结果解包
         ├── HARDWARE/hmi_dacai.c          屏协议层（159 行，纯 C）
         │    帧封装 / 切页 / 写文本 / 背光 / 蜂鸣
         └── STM32 SPL                     底层驱动（GPIO/AF、UART、DMA、NVIC）
```

各层通过**回调**解耦：传感器层解析出一帧后回调 `on_bp_frame()`，屏层接收字节后由 `hmi_rx_feed()` 组装成帧再回调 `hmi_rx_frame()`，应用层只在回调中处理业务逻辑。

### 3.2 通信协议设计

#### 3.2.1 HKB-08B+ 传感器协议

**帧格式**

```
┌──────┬──────┬───────┬───────┬───────┬──────────────┐
│ 0xFF │ 0xC0 │  LEN  │ CKSUM │  CMD  │     DATA     │
└──────┴──────┴───────┴───────┴───────┴──────────────┘
   帧头（2B）        长度   校验和   命令字    数据（N 字节）
```

- `LEN = 3 + N`，其中 3 包含 LEN 自身、CKSUM、CMD 三个字节
- `CKSUM = (LEN + CMD + ΣDATA) & 0xFF`，取低 8 位
- 特例：复位指令为 `FF 00` 两字节，无帧头

**命令字定义**

| 命令字 | 名称 | 方向 | 说明 |
|-------|------|------|------|
| 0xAA | WAKE | 下发 | 唤醒传感器，**有应答**，可用于存活探测 |
| 0xA8 | SLEEP | 下发 | 休眠 |
| 0xA0 | START | 下发 | 启动测量；应答帧约 10 Hz 上报实时气压 |
| 0xA1 | STOP | 下发 | 停止测量（气阀放气） |
| 0xD0 / 0xD1 | START_WAVE / STOP_WAVE | 下发 | 静压测波形开关 |
| 0xD2 | SET_GAIN | 下发 | 设置放大倍数（1 ~ 7） |
| 0xD3 | WAVE | 上报 | 波形数据点（200 Hz） |
| 0xAC | RESULT | 上报 | 测量结果 |
| 0xAD | ERROR | 上报 | 错误报告 |

**数据字段解析**

`0xAC` 结果帧 DATA 布局：`SSYH SSYL SZYH SZYL XL`

- `SSYH << 8 | SSYL` → 收缩压 SYS（mmHg）
- `SZYH << 8 | SZYL` → 舒张压 DIA（mmHg）
- `XL` → 脉率 PR（bpm）
- `SSYH` 的第 7 位（bit7）为**心率不齐标志**（irregular）

`0xA0` 气压帧 DATA 布局：`QYH QYL`

- `QYH << 8 | QYL` → 当前气压（mmHg）
- `QYH` 的第 4 位（bit4）为**心跳检测标志**（has_beat）

**错误码定义**

| 错误码 | 含义 | 处理建议 |
|-------|------|---------|
| 0 | 测不到有效脉搏 | 检查气袋佩戴位置后重试 |
| 1 | 11 秒内打气未达 50 mmHg | 检查气袋绑扎与气管连接 |
| 2 | 本次结果数值无效 | 重新测量 |
| 3 | 气袋压力超过 295 mmHg | 超压保护，停止使用并检查设备 |
| 4 | 干预过多（测量中移动/说话） | 保持静止后重试 |

#### 3.2.2 大彩组态屏协议

**帧格式**

```
┌──────┬───────────────┬──────────────┐
│ 0xEE │  命令 + 参数   │ FF FC FF FF  │
└──────┴───────────────┴──────────────┘
 帧头                  固定帧尾（4B）
```

16 位与 32 位参数一律**高字节在前**（大端）。

**核心指令**

| 功能 | 帧结构 |
|------|--------|
| 切换画面 | `EE B1 00 <画面号:16> FF FC FF FF` |
| 写文本 | `EE B1 10 <画面:16> <控件:16> <ASCII/GBK> FF FC FF FF` |
| 读控件 | `EE B1 11 <画面:16> <控件:16> FF FC FF FF` |
| 查询当前画面 | `EE B1 01 FF FC FF FF` |
| 曲线灌数据 | `EE B1 32 <画面:16> <控件:16> <通道:8> <点数:16> <数据...> FF FC FF FF` |
| 背光调节 | `EE 60 <亮度值:8> FF FC FF FF` |
| 蜂鸣器 | `EE 61 <时长:8> FF FC FF FF`（单位 10 ms） |

**背光参数方向（易错）**：亮度值 `0x00` = 背光最亮，`0xFF` = 背光关闭，**数值越大越暗**，与直觉相反。本工程在 MCU 侧定义人眼语义的 0 ~ 100% 亮度，再经映射 `level = 255 - percent × 255 / 100` 转换为屏参数，并限制在 20% ~ 100% 之间，防止误调至全黑无法恢复。

**按钮事件上报**

屏上按钮分为两类，行为差异显著：

- **切页型**（`button_type = 0`）：按下后**屏自己先跳页**，再上报事件。因此 MCU 收到的事件中，画面号是**目标页**而非源页。
- **瞬变型**（`button_type = 1`）：**屏不跳页**，只上报事件，必须由 MCU 主动下发切页指令将其送走。

事件帧格式：

```
EE B1 11 <画面:16> <控件:16> 10 <子类型> <状态> FF FC FF FF
                              ↑ 10 = 按钮控件
                                       ↑ 00=弹起 / 01=按下
```

这一机制是本项目**出现严重死锁问题的直接原因**，详见第 4 章。

### 3.3 接收架构设计

固件采用 **DMA + IDLE 空闲中断 + 环形缓冲** 的三级接收架构，解决高速收发下的丢字节问题。

**为什么不能直接在中断里处理**

传感器以 115200 bps 上报，每字节间隔仅约 87 μs。若在接收中断中打印调试信息（每字节约 7 个字符，9600 bps 下耗时约 600 μs），期间后续字节来不及被读取，将触发 ORE（溢出）错误，导致整帧被打散、校验失败。

**实际架构**

```
UART 硬件接收
    ↓
DMA1 搬运（USART2 → Stream5，USART3 → Stream1，通道 4）
    ↓ 缓冲区 64 字节
IDLE 空闲中断触发（线路空闲即认为一帧结束）
    ↓
on_uart_rx_idle()：读取 DMA 剩余计数 → 逐字节调用 on_uart_rx()
    ↓
on_uart_rx()：【仅入队，不做任何打印】
    环形缓冲 s_q2[] / s_q3[]（各 256 字节，读写指针 + 满则丢弃）
    ↓
app_loop() 主循环出队：【在此打印 RX2:/RX3:】+ 送入协议解析器
```

关键点：**中断只负责入队，一切耗时操作（打印、解析）都推迟到主循环**。中断处理时间被压缩到微秒级，从根本上避免了溢出丢字节。

### 3.4 关键算法与数据管理

**（1）软件 RTC 走时**

未使用 STM32 内置 RTC（需外部 32.768 kHz 晶振与备份电池），改用 **SysTick 毫秒计数器 + 基准点**的软件方案：

- 记录基准时刻 `s_rtc_base_tick` 与对应的"当日秒内偏移" `s_rtc_base_sec`
- 每次走时按 `elapsed = (g_tick - base_tick) / 1000` 计算绝对增量，而非逐秒自增
- 这样即使主循环某次被长时间阻塞，走时也不会累积丢失
- 跨天时用**闰年判别 + 月天数表**正确进位（闰年规则：能被 4 整除且不能被 100 整除，或能被 400 整除）
- 时间校准（time 页保存）通过重置基准点实现，校准后立即广播到所有页面

**（2）历史记录环形缓存**

- 定长结构数组 `s_hist[100]`，容量 100 条，满后循环覆盖
- 采用环形写指针 `s_hist_head`，最新记录位于 `head - 1`
- 显示时按 `(head - 1 - idx + CAP) % CAP` 反查实际下标，天然实现"最新在前"的倒序展示
- 每条记录包含：有效性、SYS、DIA、PR、时间戳（年/月/日/时/分）、状态码（1=测量成功 / 2=用户取消 / 3=异常）
- 分页显示：4 行 × 6 列 = 每页 24 个字段，页码按 `ceil(count / 4)` 计算

**（3）状态文案广播机制**

10 个页面中的大多数共用一套"公共状态控件"（同 ID、同坐标）：

| 控件 | ID | 位置 | 含义 |
|------|----|------|------|
| CLOCK | 100 | (548, 17) | 右上角实时时间 |
| CONTEXT | 101 | (24, 65) | 当前上下文/主体状态 |
| FOOTER | 102 | (24, 436) | 底部状态条 |
| TIP_TITLE | 103 | (40, 342) | 提示标题 |
| TIP_DETAIL | 104 | (40, 372) | 提示补充说明 |

由于 ID 与坐标一致，**一次广播写即可同步所有页面**，无需逐页维护。系统在状态切换时按当前状态选择文案组：

| 状态 | CONTEXT | FOOTER | TIP_TITLE |
|------|---------|--------|-----------|
| 空闲（无历史结果） | 未关联患者 | 等待设备状态 | 等待设备状态 |
| 空闲（有历史结果） | 测量完成 | 设备已就绪 | 设备就绪，可开始测量 |
| 测量中 | 正在测量 | 气压测量中 | 正在测量，请保持安静 |
| 停止中 | 正在停止 | 正在停止操作 | 正在停止，请稍等 |

设置页、维护页、确认页无这组公共控件，广播时自动跳过；结果页的提示控件被结果展示单独占用，也单独处理。

### 3.5 关于 IIC 与器件地址

本项目血压测量链路**未使用 IIC / I²C 总线**：血压传感器走 UART，显示屏走 UART。因此不存在器件地址配置。

板载虽有一颗 24C02 EEPROM（挂载于 I2C1，PB6/PB7），但其用途为板级参数存储，与本模块数据通路无关，且其 I2C 引脚与 USART3 使用的 PB10/PB11 **无冲突**，不影响血压模块运行。当前版本的历史记录与时间基准均存于 RAM，掉电不保留（见 4.4 节限制说明）。

### 4.2 遇到的典型问题

**问题一：传感器帧全部校验失败被丢弃**

- **现象**：传感器有数据回传，但所有帧都被解析器判定为校验错误而丢弃，无法得到任何结果。
- **排查**：逐字节跟踪解析状态机，发现校验和在接收端**把 CKSUM 字节自己也累加进去了**。
- **根因**：发送端按手册计算 `CKSUM = (LEN + CMD + ΣDATA)`，**不含 CKSUM 自身**；接收端却多累加了这一字节，导致对比永远不相等。
- **修复**：接收端严格按 `(LEN + CMD + ΣDATA) & 0xFF` 累加，仅在收到 DATA 全部结束后与本帧 CKSUM 比对。已用纯 C 合成帧做单元验证，通过后将整帧交给上层。

**问题二：下发切页指令，屏毫无反应**

- **现象**：MCU 持续发送切页指令，屏画面一动不动，但串口物理链路正常。
- **排查**：比对官方《大彩指令集》与同机另一工程（SPO2）的屏驱动脚本，发现帧格式一直写错。
- **根因**：原代码将"切换画面"写成 `EE B1 <页号>`。而大彩协议中 `B1 01` 实际是"**查询当前画面**"、`B1 00` 才是"**切换画面**"。屏收到 `B1 01` 后只把它当成查询请求，自然不会跳页。
- **修复**：切页改为 `EE B1 00 <画面:16>`，并顺手核对全部指令（写文本 `B1 10`、读控件 `B1 11`、曲线 `B1 32`）。同时**引入"查询当前画面"作为链路自检**：屏能应答 `EE B1 01 <画面号> FF FC FF FF` 即证明接线、波特率、帧格式三项全部正确。

**问题三：传感器一路收不到任何字节**

- **现象**：刷入新固件后调试口完全没有 USART3 的接收记录（`RX3:` 一条都没有）。
- **排查**：为定位问题在软件中加入 **USART3 回环自测**——短接 PB10 与 PB11，定时发送唤醒帧并统计收到的字节数。回环测试立即通过（收到自身帧回声），**证明 MCU 侧外设、时钟、GPIO 复用、中断、链路全部正常，问题 100% 在传感器侧**。
- **根因**：板载跳线帽的选择问题。P5 组的跳线帽决定 USART3 的去向，实际存在"拆了跳线帽却把传感器插在无线模块座"的状态，导致 USART3 物理悬空。
- **修复**：按接线方案 A（拆帽后直接接 P5.pin3 / pin4）或方案 B（保留跳线帽 + 拔无线模块换插传感器）正确接线。
- **经验**：**先做回环自测隔离软硬件**，这是排查串口问题的最高效手段。

**问题四：点"停止测量"后卡死在停止页，无法重新测量**

- **现象**：按下停止后，屏停在停止页，所有提示文案都已正确更新（"已停止""本次测量已取消"），但页面出不去，用户无法重新测量。
- **排查**：检查屏工程发现，停止页**唯一的按钮是瞬变型**（`button_type = 1`），屏不会自己跳页；而 MCU 的停止应答处理分支里**从头到尾没有下发切页指令**——文案写对了，但页面没被送走。
- **附带发现**：测量页的停止按钮是**切页型**（`switch = stopping`），屏会先自己跳到停止页再上报事件，所以事件里的画面号是**停止页**而非测量页。这解释了为什么原本针对"测量页"分支写的处理逻辑形同虚设。
- **修复**（三重保险）：
  1. **立即脱困**：`stop_measure()` 在发送停止指令后**不等应答**，直接写文案并切到异常页。理由：气阀放气需要时间，且传感器掉电或断线时应答永远不会到达，"等应答"必然存在卡死风险。
  2. **超时兜底**：主循环中增加 1.5 秒超时检测，若仍处于停止中且未收到应答，强制回归空闲状态，保证任何异常情况下都不会卡住。
  3. **落点选择**：异常页本身具备"重新测量"与"返回"两个切页型按钮，是天然的"可重测"落点，因此选择切到该页而非主页。
  4. **应答分支改为只补正不跳页**：避免用户已经自行切换到其他页面时又被强行拽回。

**问题五：高速接收时整帧被溢出打散**

- **现象**：传感器接连发送完整数据帧时，解析随机失败，出现校验错误。
- **根因**：最初在接收中断里直接打印调试信息。115200 bps 下每字节间隔仅 87 μs，而打印 7 个字符在 9600 bps 下需要约 600 μs，远超字节间隔，导致后续字节未及时读取而触发溢出。
- **修复**：改为 DMA + IDLE 中断 + 环形缓冲架构，中断内**只入队不打印**，所有打印与解析推迟到主循环。详见 3.3 节。

**问题六：源码中的中文无法编译**

- **现象**：包含 UTF-8 中文字符串的源文件在 Keil AC5 下产生大量 `unrecognized token` 与 `missing closing quote` 错误。
- **根因**：AC5 编译器对 UTF-8 编码的窄字符串字面量支持不完善。
- **修复**：所有面向屏显示的中文字符串一律改为 **GBK 编码的 `\xNN` 十六进制转义**，源文件保持纯 ASCII。前提是屏端控件挂载了 GBK 字库（本工程所用字库均为中文库）。

### 4.3 项目难点分析

1. **双协议栈的精确实现**：需同时准确实现传感器私有协议与大彩组态屏协议，两者帧格式、校验方式、字节序规则各不相同，任一处出错都会导致"静默失败"（无报错、无反应），排查成本高。

2. **嵌入式状态机的健壮性设计**：真实硬件存在掉电、断线、不应答等各种异常。状态机必须为**每一个状态转移都设计超时兜底**，否则极易出现用户视角的"卡死"。本项目在停止流程上就因此付出了一次实机返工的代价。

3. **组态屏交互模型的隐式约定**：切页型与瞬变型按钮的行为差异，以及"切页型按钮的事件画面号是目标页"这一细节，均未在显式接口中体现，属于必须通过阅读工程文件与实测才能掌握的隐式知识。

4. **高速串口接收的架构设计**：在中断上下文与主循环之间合理划分职责，是嵌入式实时系统的基础课题。本项目通过 DMA + IDLE + 环形缓冲的组合解决了这个问题，该架构具备通用推广价值。

5. **软硬件的联合定位**：面对"没有数据"这类现象，需要通过回环自测、链路自检等软件手段主动构造判据，把"软硬件混合问题"拆解为可分别验证的子问题。

### 4.4 已知限制与后续改进方向

**当前限制**

| 项目 | 现状 | 影响 |
|------|------|------|
| 时间保持 | 软件 RTC，掉电后从默认时刻重启 | 需每次上电手动校准 |
| 历史记录 | 存于 RAM，复位即清空，容量 100 条 | 无法跨会话追溯 |
| 患者管理 | 仅"换患者"确认清空，无患者信息录入 | 未与监护仪主系统联动 |
| 维护页 | 仅展示授权说明，未开放写操作 | 功能预留 |
| 波形显示 | 传感器提供 200 Hz 静压波形，屏协议支持曲线控件 | 当前未接入 |

**改进方向**

1. 启用 STM32 内置 RTC（外接 32.768 kHz 晶振 + 备份电池），实现掉电走时。
2. 将历史记录迁移至板载 24C02 EEPROM 或外扩 Flash，实现持久化存储。
3. 接入波形曲线控件，实时绘制静压脉搏波，提升可视化程度。
4. 与监护仪主系统打通，支持患者 ID 绑定与测量结果上传。
5. 引入版本管理（Git），并对协议层补充单元测试。

## 5 总结

本项目以 STM32F407 为核心，完成了血压测量模块从传感器接入、协议解析、状态管理到人机交互的完整实现。工程通过 Keil AC5 编译零错误零警告，固件规模约 12 KB，具备以下特点：

- **协议层高度可移植**：传感器与屏驱动均为纯 C 实现，不依赖 MCU SDK，可跨平台复用；
- **接收架构健壮**：DMA + IDLE 中断 + 环形缓冲的组合保证了高速收发下的数据完整性；
- **状态反馈清晰**：三态状态机配合公共状态控件广播，用户始终能明确感知当前所处状态；
- **异常处理完备**：关键流程均设置超时兜底，避免任何情况下的界面卡死。

项目过程中积累的经验——**以回环自测隔离软硬件问题**、**为每个状态转移设计超时兜底**、**警惕组态屏按钮的隐式行为约定**——对后续同类嵌入式开发具有直接的参考价值。
