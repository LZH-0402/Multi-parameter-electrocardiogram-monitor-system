# 血压测量代码 · 编程思路与执行流程

> 适用工程：`STM32F407_BP`（STM32F407ZGT6 + 标准外设库 SPL + Keil AC5）
> 配套文档：项目书、测试说明、正常范围速查。本文用于**理清代码是怎么一步步跑起来的**，方便后续维护与二次开发。

---

## 0. 一句话总览

整个程序是一个**「中断收字节 → 环形缓冲 → 主循环解析 → 业务函数 → 串口屏刷新」**的事件驱动状态机。
上电后 `main()` 只做两件事：`app_init()` 初始化一切，`while(1) app_loop()` 循环处理。所有"实时收数"都在中断里**只入队、不解析**，解析和屏刷新全部放到主循环，避免中断里卡太久丢字节。

```
上电
 └─ main()
     ├─ app_init()          // 一次性初始化（GPIO/NVIC/DMA/UART/屏/传感器/软RTC）
     └─ while(1) app_loop() // 三大任务：收屏帧 / 收传感器帧 / 1s 软RTC
```

---

## 1. 三路串口分工（先记住这个，整个代码就通了）

| 串口 | 引脚 | 波特率 | 连谁 | 角色 |
|------|------|--------|------|------|
| USART1 | PA9/PA10 | 115200 | PC（CH340 调试口） | **只看不控**：打印 RX 字节、状态、alive，用于排错 |
| USART3 | PB10/PB11 | 9600 | 大彩串口屏（RS232 经 SP3232 第二通道→COM_G） | 发指令 / 收按钮事件 |
| UART5 | PC12/PD2 | 115200 | HKB-08B+ 血压模块（TTL） | 组帧发命令 / 解帧收结果 |

- 调试口 USART1 收到的字节**直接回显**到 PC（见 `on_uart_rx` 的 else 分支）。
- 屏 USART3 与传感器 UART5 收到的字节**先入环形缓冲**（`s_q2` / `s_q3`，各 256 字节），再由主循环取出解析。

---

## 2. 两个"环形缓冲"是核心枢纽

文件顶部定义了两个 256 字节环形缓冲：

```c
#define RXQ_SIZE 256
static volatile uint8_t s_q3[RXQ_SIZE];   // 传感器(UART5) 接收缓冲
static volatile uint8_t s_q2[RXQ_SIZE];   // 屏(USART3) 接收缓冲
static volatile uint16_t s_q3_head, s_q3_tail;
static volatile uint16_t s_q2_head, s_q2_tail;
```

- 中断里**只做 `head` 推进 + 入队**（满则丢弃，不阻塞）。
- 主循环里**只做 `tail` 推进 + 出队 + 解析**。
- 头尾用 `volatile` + 单生产/单消费，主循环与中断不会同时改同一个变量，所以无需关中断保护。

---

## 3. 入口：`main.c` → `app_init()`

`main.c` 极简：

```c
int main(void) {
    app_init();
    while (1) { app_loop(); }
}
```

`app_init()`（HARDWARE/app_bp.c）按顺序初始化，任何一步失败都会卡死（设计如此，便于上电自检发现问题）：

```
app_init()
 ├─ uart_gpio_init()      // PA/PB/PC/PD 引脚复用（USART1/2/3 用 AF7，UART5 用 AF8）
 ├─ nvic_init()           // 中断优先级：USART1(1,1) < USART3(屏,1,2) < UART5(传感器,1,3)
 ├─ SysTick_Config()      // 1ms 一跳，g_tick++（见 stm32f4xx_it.c 的 SysTick_Handler）
 ├─ dma_rx_init()         // 仅 RX_USE_DMA_IDLE：USART3(屏)→DMA1_Stream1, UART5(传感器)→DMA1_Stream0
 ├─ uart_periph_init()    // 波特率/字长/停止位/校验；开 RXNE(USART1) 或 IDLE(2/3)
 ├─ hmi_init(hmi_send_cb)// 注册"屏发送回调"（最终走 USART3(屏) 发出）
 ├─ bp_sensor_init(on_bp_frame) // 注册"传感器整帧回调"
 ├─ s_rtc_base_* = 0      // 软RTC基准（无外部RTC，用 SysTick 推算日期时间）
 ├─ bright_apply()        // 上电恢复上次亮度
 └─ screen_diag_on_idle() // 切idle页 + 刷新"上次结果" + 发"查询当前页"让屏应答（自检三项）
```

> 为什么用"软 RTC"？板子没接外部 RTC 芯片，日期时间完全由 `g_tick`（SysTick 毫秒计数）推算，掉电即丢，需要时在 settings 页手动校时。

## 4. 中断层：字节是怎么进缓冲的

`stm32f4xx_it.c` 里三个 USART 中断：

```
USART1_IRQHandler → on_uart_rx(USART1, b)        // 仅回显到PC
USART3_IRQHandler → （IDLE 中断）on_uart_rx_idle(USART3)   // 屏
UART5_IRQHandler → （IDLE 中断）on_uart_rx_idle(UART5)     // 传感器
```

### 4.1 DMA + 空闲中断模式（默认 `RX_USE_DMA_IDLE=1`）

USART3(屏)/UART5(传感器) 不开每字节 RXNE 中断，而是开 **IDLE（线路空闲）中断**——收到一帧、总线静默后**才进一次中断**，效率远高于逐字节中断。

`on_uart_rx_idle(u)` 做的事（`app_bp.c`）：

```
on_uart_rx_idle(u)
 ├─ 根据 u 选 DMA 流与缓冲（屏=DMA1_Stream1/s_dma_screen_buf，传感器=DMA1_Stream0/s_dma_sensor_buf）
 ├─ 读 DMA 剩余计数 → 算出本帧已收字节数 got
 ├─ for i in got: on_uart_rx(u, buf[i])   // 逐字节塞进对应环形缓冲
 └─ 重启 DMA：关流→清5个标志→重置计数→开流（Normal 模式必须手动重启）
```

### 4.2 回退模式（`RX_USE_DMA_IDLE=0`）

直接用 RXNE 中断，每字节进 `on_uart_rx(u, b)` 入队。逻辑相同，只是中断更频繁。

### 4.3 `on_uart_rx()` —— 真正的"入队函数"

```c
void on_uart_rx(USART_TypeDef *u, uint8_t b) {
    if (u == SCREEN_UART)      { 入 s_q2; }   // 屏
    else if (u == SENSOR_UART) { 入 s_q3; }   // 传感器
    else { 回显到 USART1(PC); }
}
```

**关键设计**：中断里到此为止，**绝不做协议解析**。解析昂贵且可能阻塞，留给主循环。

## 5. 主循环：`app_loop()` 的三大任务

```c
void app_loop(void) {
    // 任务1：传感器缓冲排空 → bp_sensor_feed 解帧
    while (s_q3_tail != s_q3_head) { b=出队; bp_sensor_feed(b); }
    // 任务2：屏缓冲排空 → hmi_rx_feed 组帧
    while (s_q2_tail != s_q2_head) { b=出队; hmi_rx_feed(b); }
    // 任务3：每 1s 软RTC推进 + 屏时钟/测量计时刷新
    if (每1s) { clock_tick_1s(); clock_broadcast(); 测量计时刷新; }
    // 附带：ST_STOPPING 超时(1.5s无0xA1应答) → 强制回 IDLE
}
```

注意：这里把字节喂给 **`bp_sensor_feed()` / `hmi_rx_feed()`**，它们内部做"逐字节状态机解析"，解出完整一帧后**回调**业务函数（`on_bp_frame` / `hmi_rx_frame`）。这是典型的"中断收、循环解、回调业务"三段式。

## 6. 屏侧数据流：字节 → 组帧 → 按钮分发 → 业务

### 6.1 `hmi_rx_feed()` —— 屏字节组帧器

逐字节喂入，识别大彩帧：`0xEE` 开头，`FF FC FF FF` 结尾即收完一帧，交给 `hmi_rx_frame()`。缓冲满/超长则丢弃重来。

### 6.2 `hmi_rx_frame()` —— 帧解析 + 按钮分发

只处理 `B1` 子指令：

| 子指令 | 含义 | 处理 |
|--------|------|------|
| `B1 01` | 查询当前页应答 | 仅打印（用于上电自检验证三项） |
| `B1 11` | 按钮返回帧 | **只有"按下"(status=1)才处理**，按 `页面号 + 控件ID` 分发 |

按钮分发逻辑（核心 switch）：

```
hmi_rx_frame()
 └─ switch(scr 页面号)
     ├─ IDLE(0)     : 开始测量(10) / 历史(11) / 设置(12)
     ├─ MEASURING(1): 停止(10)
     ├─ STOPPING(7) : 停止确认(10)  ← 仅在测量/停止中才真正停
     ├─ RESULT(2)   : 再测(10) / 历史(11)
     ├─ NOTICE(3)   : 重试(10)
     ├─ HISTORY(4)  : 上一页(10) / 下一页(11)
     ├─ CONFIRM(8)  : 确认(11) → 清空"上次结果"
     ├─ SETTINGS(5) : 进时间(12) / 亮度-(10) / 亮度+(11)
     └─ TIME(9)     : 选字段(10~14) / +/- (15,16) / 保存(18)
```

> **两类屏按钮**（理解屏交互的关键）：
> - **切页型**（button_type=0）：屏自己先跳页再上报，MCU 收到的是"目标页"事件，只做业务（如刷新该页数据）。
> - **瞬变型**（button_type=1）：屏不跳页，需要 **MCU 主动 `hmi_change_page()`** 切页（如时间编辑、确认弹窗）。

## 7. 传感器侧数据流：字节 → 解帧 → `on_bp_frame()` → 业务

### 7.1 协议与解帧（`bp_sensor.c`，纯 C 无 SDK 依赖）

帧格式：`FF C0 | LEN | CKSUM | CMD | DATA...`
- `LEN` = 3 + N(DATA)
- `CKSUM` = (LEN + CMD + ΣDATA) & 0xFF，**不含 CKSUM 自身**（这是个被修过的坑）
- 复位指令特例：`FF 00`

`bp_sensor_feed()` 是逐字节状态机（WAIT_FF→WAIT_C0→LEN→CKSUM→CMD→DATA），解出整帧后调用在 `app_init` 注册的回调 `on_bp_frame()`。

### 7.2 `on_bp_frame()` —— 传感器整帧回调（真正的业务中枢）

```
on_bp_frame(cmd, data, len)
 ├─ 0xAC 结果帧
 │    ├─ bp_parse_result() → 填 s_last（SYS/DIA/PR/心率不齐）
 │    ├─ result_show()      → 写结果页 110/111/112 + 刷新 idle 页"上次结果"
 │    ├─ hist_add(有效)     → 记一条历史
 │    ├─ hmi_change_page(RESULT) → 切结果页
 │    └─ s_state = ST_IDLE; status_refresh()
 │
 ├─ 0xA1 停止应答
 │    └─ if(ST_STOPPING&&未确认): 标已停→记"已取消"历史→回IDLE→notice刷新
 │
 ├─ 0xA0 实时气压(~10Hz)
 │    └─ 按 s_state 刷新 measuring(111)/stopping(111) 的压力文本
 │
 └─ 0xAD 错误帧
      ├─ notice_show(code)  → 写 notice 页（错误码/标题/说明）
      ├─ hist_add(错误)     → 记一条错误历史
      ├─ hmi_change_page(NOTICE)
      └─ s_state = ST_IDLE
```

## 8. 状态机（测量生命周期）

```c
typedef enum { ST_IDLE=0, ST_MEASURING, ST_STOPPING } bp_state_t;
static bp_state_t s_state = ST_IDLE;
```

```
        bp_start_measure()
   IDLE ───────────────► MEASURING
     ▲                     │  收到 0xAC 结果
     │                     ▼
     │                切结果页 / 记历史
     │                     │
     │   stop_measure()     │  收到 0xAD 错误
     ├──────────► STOPPING ─┤
     │   收到 0xA1 应答      │
     │   或 1.5s 超时        │
     └──────────────────────┘
```

- `bp_start_measure()`：发 唤醒(0xAA)→启动(0xA0)，置 `ST_MEASURING`，记录起始 tick，屏切 measuring 页。
- `stop_measure()`：发 0xA1，置 `ST_STOPPING`，弹 notice 页"已取消"。
- **超时保护**：若 1.5s 内没收到传感器 0xA1 应答，`app_loop` 强制回 `ST_IDLE`（防止卡死在 stopping）。

## 9. 屏刷新函数族（MCU → 屏 的方向）

所有写屏都走 `hmi_dacai.c` 的封装，最终经 `hmi_send_cb` → USART3(屏) 发出：

| 函数 | 作用 |
|------|------|
| `hmi_change_page(id)` | 切页：`EE B1 00 <页号16>` |
| `hmi_write_text(p,c,s)` | 写文本：`EE B1 10 <页><控件><串>` |
| `hmi_set_backlight(lv)` | 背光：0x60（**值越大越暗**，0=最亮） |
| `hmi_beep(ms)` | 蜂鸣：0x61（单位 10ms） |

本应用常用的"页面级刷新"函数：

- `status_set()`：把 上下文(101)/页脚(102)/提示(103,104) 公共状态条写到**所有页**（settings/maintenance/confirm 无此控件则跳过）。
- `status_refresh()`：按 `s_state` 调 `status_set()`，统一刷新所有页状态条。
- `idle_refresh()`：idle 页"上次结果(110)/上次信息(111)"。
- `result_show()`：结果页 + 步骤7 分级提示。
- `clock_broadcast()`：把当前时间写到各页 CLOCK(100)。
- `hist_show_page()`：历史页 4 行×6 列 + 页标；"状态"列对**有效记录**显示 `bp_classify_tag()` 血压分级（与结果页一致），心律不齐时追加“·不齐”。
- `settings_show_time()` / `bright_show()`：设置页显示。

## 10. 步骤7 · 血压正常/异常分级（落地点）

分级逻辑集中在三个分级函数（均定义在 `hist_show_page()` 之前，**结果页与历史页共用**）：

- `bp_level(sys, dia)` → 返回分级 **0=正常 / 1=偏低 / 2=偏高(1级) / 3=高血压(2级)**，取 SYS/DIA 中较高档（**唯一判定源**）。
- `bp_classify(sys, dia)` → 结果页**长提示**（"血压偏低，请关注" / "血压偏高，请注意" / "血压过高，建议就医" / "血压正常"），由 `result_show()` 写到结果页 **TIP_TITLE(103)**。
- `bp_classify_tag(sys, dia)` → 历史页**短标签**（"偏低 / 正常 / 偏高 / 高血压"），由 `hist_show_page()` 写到历史页“状态”列；心律不齐记录再拼“·不齐”（如“偏高·不齐”）。
- `bp_pr_note(pr)` → 脉率提示，拼进结果页 **TIP_DETAIL(104)**。

> ⚠ **一致性**：结果页与历史页**共用 `bp_level()`**，所以同一组数据（如 SYS=103 / DIA=50）在结果页显示"血压偏低，请关注"、在历史页显示"偏低"，两处判定必然一致（历史上曾因历史页只看测量类别而误显"正常"，已修）。

| 指标 | 偏低 | 正常 | 偏高(1级) | 高血压(2级) |
|------|------|------|-----------|------------|
| 收缩压 SYS | <90 | 90~139 | 140~159 | ≥160 |
| 舒张压 DIA | <60 | 60~89 | 90~99 | ≥100 |
| 脉率 PR | <60 偏慢 | 60~100 | — | >100 偏快（仅提示） |

- 总分级取 **SYS/DIA 中较高的一级**（见 `bp_level` 的 `lvl` 判定）。
- 脉率只做"偏快/偏慢"提示，**不计入血压分级**。
- 心率不齐（`s_last.irregular`，来自结果帧 SSYH.7）作为附加提示拼到结果页 TIP_DETAIL。
- 历史页“状态”列显示规则：**有效记录** → `bp_classify_tag()` 血压分级（与结果页同源），心律不齐(`state==1`)再追加“·不齐”（如“偏高·不齐”）；无效 / 取消(`state==2`) / 错误(`state==3`)记录 → “已取消 / 错误”。
  - 状态列控件(ROW*_STATE)宽 172px、字号 22px（约容 7 个全角字），“高血压·不齐”仅 6 字，无需改屏工程。
  - `hist_show_page()` 日期时间缓冲 `b` 由 `b[10]` 扩为 `b[16]`（“MM-DD HH:MM” 需 12 字节，原 10 字节会栈越界，顺手修复）。

## 11. 软 RTC 与时间编辑

- `clock_tick_1s()`：每 1s 用 `g_tick` 与基准换算"已过秒数"，满整天进位日期（闰年 2 月 29 天），并重置基准消除长累计误差。
- `time_edit_begin()` / `time_edit_render()` / `time_edit_step()` / `time_edit_commit()`：
  时间编辑页的"进入 / 渲染 / +/- 调整 / 提交"。提交时把编辑缓冲写回软 RTC 基准，并广播到各页时钟。


## 14. 二次开发 checklist

- **加一个新屏按钮**：在 `HMI_SCREEN_*` 的 switch 分支里加 `ctrl == 控件ID` 处理，必要时 `hmi_change_page()` 主动切页。
- **改分级阈值**：直接改 `app_bp.c` 顶部的 `BP_SYS_*` / `BP_DIA_*` / `BP_PR_*` 宏与 `bp_classify()`。
