# 血氧模块代码使用说明（STM32F407 + AFE4490 + CAN）

> 配套文档：`血氧模块_CAN通信开发流程框架图.md`（设计依据）
> 代码位置：`代码资料\血氧\SPO2`
> 目标：让你在最短时间内理清这套代码的**编程结构**与**运行逻辑**，知道改哪里、怎么看现象、出问题往哪儿查。
>
> **对齐说明（重要）**：本文描述的是**样机第一版固件**的实际实现状态。按《多参数监护仪_总开发合同与系统方案 v0.7》，本模块的正式对外链路是“**Node-A 作为 CANopen 设备节点 → Gateway-C → MQTT/TLS 上云**”，而现有固件用的是**过渡期的自定义 CAN 帧**（0x321/0x322/0x323/0x120）。本文第 8 节把这两层分开说明，迁移对照与目标设计见 `血氧模块_CAN通信开发流程框架图.md` 第 6.4 节。文中提到“CAN”时，除第 8 节外均指该 CAN 物理层与驱动层，不表示自定义应用协议是最终方案。

## 0. 30 秒看懂这套代码

整套代码只做一件事：**AFE4490 采 PPG 波形 → 算出脉率 PR 和血氧 SpO2 → 通过 CAN 报给 Gateway-C，同时刷新本模块的本地显示屏。**

```
                       ┌─────────────── 主循环（轮询，无 RTOS）───────────────┐
   AFE4490             │                                                     │
   ┌──────┐  DRDY上升沿 │  ① AFE4490_DataReady()? ── 是 ──> SPI 读 RED/IR     │
   │LED+  │ ───────────┼──> EXTI0 中断（只置标志）                            │
   │PD+ADC│             │  ② App_State_FeedSample(red, ir)  滤波→手指检测→累加 │
   └──────┘  SPI1       │  ③ CAN_PollCommand()              收命令入队         │
   500SPS               │  ④ App_State_Run()                状态机+命令+计算  │
                        │  ⑤ 定时发送 0x321(200ms) / 0x322(1s)                │
                        │  ⑥ 串口日志(1s) / LED 翻转(500ms) / 本地屏刷新       │
                        └─────────────────────────────────────────────────────┘
                                               │
                                    g_measurement（唯一数据源）
                                    ↙                        ↘
                        血氧独立显示屏（UART）        CAN1 ──> Gateway-C
                        （正式本地显示通道）          （正式链路为 CANopen；样机期暂用自定义帧）
```

**记忆口诀**：中断只置标志，SPI 只在主循环读，算法只写 `g_measurement`，CAN 只读 `g_measurement`，本地屏也读同一份 `g_measurement`。

**上手前必改的两处**（`CONFIG\board_config.h`）：

| 宏 | 默认 | 说明 |
|---|---|---|
| `CAN1_LOOPBACK_EN` | `1` | 回环自测用。**接真实总线前必须改成 0** |
| AFE 引脚（`AFE_PIN_*`） | SPI1 PA5/6/7 + PA4 CS + PA0 DRDY + PC0 PWDN + PC1 RST | **必须对照你的原理图核对** |

## 2. 上电启动时序

`USER\main.c`：

```c
SysTick_Init();          // 查询式延时初始化（Delay_ms/Delay_us 用）
LED_Init();
UART_Init_Config();      // USART1 PA9/PA10 115200，已重定向 printf
App_Main_Init();         // ★ 含 AFE 上电延时，必须在 Tick 启动之前
Tick_1ms_Start();        // 启动 1ms 时基中断（此后禁止再用 Delay_ms/Delay_us）
while (1) App_Main_Task();
```

`App_Main_Init()` 内部顺序（`APP\app_main.c`）：

```
Measurement_Init()      // 结果字段填 -1，探针状态置无手指
  ↓
CAN1_BSP_Init(500)      // GPIO/时钟/过滤器/波特率；回环或 Normal 由宏决定
  ↓
CAN_Protocol_Init()     // 清空命令队列
  ↓
AFE4490_Init()          // GPIO+SPI → 上电时序 → 寄存器配置 → EXTI0
  ↓
App_State_Init()        // 初始化滤波器/PR/SpO2，状态 = ST_BOOT
```

**关键约束**：`AFE4490_Init()` 内部有 150ms 量级的查询式延时（`AFE_PowerSequence`），而 `Delay_ms` 会改写 SysTick 的 LOAD/CTRL。所以 **AFE 初始化必须排在 `Tick_1ms_Start()` 之前**；运行期若要重新初始化（`CMD_AFE_REINIT`），驱动里已改用 `AFE_DelayMs()` 自动切换等待方式，不会破坏时基。

## 3. 主循环：App_Main_Task 的六步

`APP\app_main.c`，每次循环做 6 件事，顺序不能乱：

| 步骤 | 代码 | 说明 |
|---|---|---|
| ① 采样 | `AFE4490_DataReady()` → `AFE4490_ReadSample()` | DRDY 来了就读 SPI，更新 `sample_seq / timestamp_ms / red_raw / ir_raw` |
| ② 喂样本 | `App_State_FeedSample(red, ir)` | 滤波 + 手指检测 + 窗口累加，只有部分状态会消费样本 |
| ③ 收命令 | `CAN_PollCommand()` | 从 BSP 队列取帧，0x120 命令入队（ISR 里绝不执行命令） |
| ④ 跑状态机 | `App_State_Run()` | 出队执行命令 + 自检/计算/故障监测 |
| ⑤ 发送 | `App_State_ConsumeReportRequest()` / 200ms / 1000ms | 0x321、0x322、CMD_QUERY 立即上报 |
| ⑥ 调试 | `printf` 日志 / LED 翻转 | `APP_DEBUG_LOG=1` 时每秒一行摘要 |

串口日志格式（波特率 115200）：

```
st=6       spo2=98 pr=76 q=87 valid=1 fault=0 rx=12 tx=245
↑状态机枚举  ↑血氧   ↑脉率  ↑质量 ↑有效    ↑故障    ↑CAN收发计数
```

## 4. 数据是怎么流动的

### 4.1 采样链（500Hz）

1. AFE4490 每个 PRP（脉冲重复周期）完成 6 路转换，`ADC_RDY` 出现上升沿（约 250ns 脉冲）。
2. `EXTI0_IRQHandler` → `AFE4490_OnDrdyISR()`：**只做 `s_drdy_count++` 和置标志**，不做 SPI。
3. 主循环检测到 `AFE4490_DataReady()`，清标志后调 `AFE4490_ReadSample()`：
   - `ReadEnable()`（写 CONTROL0=0x000001）→ 连续读 `LED2VAL / ALED2VAL / LED1VAL / ALED1VAL` → `ReadDisable()`
   - 22 位补码符号扩展
   - `ir = LED2 − ALED2`，`red = LED1 − ALED1`（已扣环境光；**若实测两路接反，交换 `afe4490.c` 最后两行赋值即可**）
4. `App_State_FeedSample()` 做预处理：
   - `PPG_Filter_Update` 指数基线跟踪去 DC + 8 点滑动平均 → 得到 AC
   - `PPG_Filter_GetDC()` 得到 DC 基线 → 用于手指检测与灌注指数

### 4.2 计算链（每 4 秒窗口）

```
窗口内 2000 个样本（500Hz × 4s）
   │
   ├─ PR_Update(ir_ac)      → 自适应阈值找峰 → 峰间隔中值 → pr_bpm
   │
   └─ SpO2_Feed(...)        → 累加 AC² 与 DC
                                  ↓ 窗口满 → ST_CALCULATE
                            SpO2_Compute() → R 值 → spo2 + quality
                                  ↓
                            g_measurement（唯一出口）
```

## 5. 状态机：8 个状态

`APP\app_state.h` 的 `app_state_t`，同时也是样机期 0x322 心跳帧的 byte0（正式链路中对应 CANopen 的状态对象）。

| 状态 | 值 | 含义 | 进入/退出条件 | 对外上报状态（样机期 0x321 byte3） |
|---|---|---|---|---|
| `ST_BOOT` | 0 | 上电瞬态 | 立即转 `SELF_TEST` | — |
| `ST_SELF_TEST` | 1 | 自检 | SPI 回环失败 → `FAULT`；500ms 内 DRDY 计数 +10 → `WAIT_FINGER`；超时 → `FAULT` | `MS_WAIT` |
| `ST_WAIT_FINGER` | 2 | 等手指 | IR 直流 > `FINGER_DC_THRESHOLD` 连续 50 点 → `ACQUIRE` | `MS_NO_FINGER` |
| `ST_ACQUIRE` | 3 | 收第一个窗口 | 收满 2000 点 → `CALCULATE`；手指移除 → 回到 `WAIT_FINGER` | `MS_MEASURING` |
| `ST_CALCULATE` | 4 | 计算（瞬态） | 有效 → `DISPLAY`；质量不足 → `SIGNAL_WEAK` | — |
| `ST_DISPLAY` | 5 | 结果有效 | 继续收下一个窗口；手指移除 → `WAIT_FINGER` | `MS_OK` |
| `ST_SIGNAL_WEAK` | 6 | 信号差 | 继续收窗口，算好了回 `DISPLAY` | `MS_SIGNAL_WEAK` |
| `ST_FAULT` | 7 | 故障 | 等 `CMD_CLEAR_FAULT` 或 `CMD_AFE_REINIT` | `MS_WAIT` + `FLAG_FAULT` |

**三条重要行为**：

1. **手指一拔，结果立刻失效**——`FeedSample` 检测到 DC 掉下去就 `Measurement_Reset()` + `StartWindow()`，绝不会继续显示上一次的血氧值。
2. **`CALCULATE` 是瞬态**，算完立刻开下一个窗口，不会停在那里。
3. **运行期持续监测两种故障**：DRDY 计数比已消费样本多出 50 个以上 → `FAULT_SAMPLE_LOST`；CAN Bus-Off → `FAULT_CAN_BUSOFF`。

### 5.1 上游命令（样机期 0x120）

正式链路中命令来自 **Gateway-C**（经 CANopen SDO 写对象或 RPDO）；样机期用 0x120 自定义帧承载同一组语义：

| 命令 | 值 | 行为 |
|---|---|---|
| `CMD_START` | 0x01 | 允许测量（默认上电即允许） |
| `CMD_STOP` | 0x02 | 停止测量，结果立即置无效，回到 `WAIT_FINGER` |
| `CMD_AFE_REINIT` | 0x03 | 重写 AFE 寄存器 + 重新自检 |
| `CMD_CLEAR_FAULT` | 0x04 | 仅在 `FAULT` 态生效，清故障并重新自检 |
| `CMD_QUERY` | 0x05 | 立即回一帧 0x321 + 0x322（不等周期） |

命令走 4 深队列：`CAN RX 中断 → BSP 环形队列 → CAN_PollCommand 解析 → 命令队列 → App_State_Run 执行`。队列满则丢弃（命令可重发）。

## 6. 唯一数据源：g_measurement

`APP\app_measurement.h`。**算法层只写它，CAN 层只读它，不允许任何模块另存一套结果。**

| 字段 | 含义 | 无效值 |
|---|---|---|
| `sample_seq` / `timestamp_ms` | 样本序号 / 系统时间 | — |
| `red_raw` / `ir_raw` | 最近一次原始值（已扣环境光） | — |
| `spo2` | 血氧 0~100 | `MEAS_INVALID`(-1)，CAN 上为 `0xFF` |
| `pulse_rate` | **脉率 PR（BPM，PPG 测得）** | -1 / `0xFF` |
| `signal_quality` | 信号质量 0~100 | 0 |
| `probe_state` | `PROBE_NO_FINGER/OK/SIGNAL_WEAK` | — |
| `result_valid` | 结果是否可用 | 0 |
| `fault_code` | 故障码 | 0 |
| `result_seq` | 结果序号，每次更新 +1 | — |

**三个出口读同一份数据**：USART1 日志、血氧独立显示屏（UART）、CAN 发送层都从 `g_measurement` 取值，不允许任何一处另存一份 SpO2/PR 状态。这与合同 4.1 中“血氧独立显示屏”作为正式本地显示通道、以及 6.1 中“本地显示不依赖云端”的要求一致。

**建议新增字段（对齐合同 8.6）**：合同数据字典要求统一“参数名称、数据来源、单位、数据类型、有效/无效/离线状态、时间信息、算法版本或必要来源信息”。现有结构已覆盖时间与有效/无效，**建议补充 `uint16_t algo_version`**，随算法变更递增并随结果一起上报，便于云端区分数值变化来自病人还是算法换版。

> **为什么是 PR 不是 HR**：本节点只有 PPG 传感器，测的是**脉率**（外周脉搏每分钟次数）。心电心率 HR 由心电模块测。两者的数值在正常窦性心律下接近，但来源和失效条件不同（如脉搏短绌时 PR < HR），不要混用字段。

## 7. 算法层

### 7.1 PPG 预处理（`ALGO\ppg_filter.c`）
- 指数基线跟踪：`dc += (raw - dc) >> 5`，等效一阶高通，输出 AC。
- 8 点滑动平均抑制高频噪声。
- DC 单独输出，供手指检测（`FINGER_DC_THRESHOLD`）与灌注指数使用。

### 7.2 PR 脉率（`ALGO\pulse_rate.c`）
1. 峰值包络快升慢降；阈值 = 包络 / 2，且包络必须大于 `PR_MIN_AMPLITUDE`。
2. 越过阈值记一次峰，与上一峰的间隔换算瞬时速率。
3. 间隔必须落在 30~220 BPM 对应范围内才采用；**过短的伪峰直接忽略**，超长（>2 倍最大间隔）判定脉搏消失并置 -1。
4. 最近 4 个间隔取中值，`pr_bpm = 采样率 × 60 / 中值间隔`。

### 7.3 SpO2（`ALGO\spo2.c`）
- 窗口内累加 `AC²` 与 `DC`，求 RMS 作为 AC。
- 灌注指数 `PI% = AC_pp / DC × 100`（RMS×2.828 近似峰峰值），质量 `q = PI × 30`，封顶 100。
- `R = (AC_red/DC_red) / (AC_ir/DC_ir)`，要求落在 0.3~3.0。
- `SpO2 ≈ 110 − 25R`，限幅 50~100。**这是通用经验式，正式产品必须用血氧模拟器标定系数。**

## 8. CAN 接口速查

> **两层要分清**：8.1～8.5 是**样机第一版固件正在使用的过渡性自定义帧**，作用是让模块在没有 CANopen 协议栈时就能用 CAN 分析仪快速联调；**8.6 才是合同 v0.7 冻结的正式链路形态（CANopen → Gateway-C → MQTT/TLS 上云）**。两层的业务语义一致，但帧格式不同，不要把它们当成两套并行方案。

样机期帧格式：**11 位标准帧**，DLC 按报文定义，多字节字段**小端**。

### 8.1 0x321 测量结果（200ms 周期）

| 字节 | 内容 |
|---|---|
| 0 | SpO2（0xFF = 无效） |
| 1 | PR 脉率（0xFF = 无效） |
| 2 | 信号质量 0~100 |
| 3 | 测量状态：`0`等待 / `1`测量中 / `2`正常 / `3`信号差 / `4`无手指 |
| 4 | 标志位：bit0 结果有效 / bit1 探头在 / bit2 算法稳定 / bit3 故障 |
| 5 | 故障码 |
| 6~7 | `result_seq`（小端） |

### 8.2 0x322 心跳诊断（1000ms 周期）

| 字节 | 内容 |
|---|---|
| 0 | 模块状态（`app_state_t`） |
| 1 | 故障码 |
| 2~3 | 固件版本 主/次 |
| 4~5 | CAN 接收 / 发送计数低字节 |
| 6 | 运行计数 `alive`（每秒 +1，主屏看它是否在跳） |
| 7 | 保留 |

### 8.3 0x120 上游命令（事件触发）
只需 `data[0]` = 命令码（见 5.1），未定义码直接忽略。

### 8.4 0x323 波形（可选，默认关闭）
`CAN_WAVEFORM_EN=1` 才编译。`byte0` 通道/片段、`byte1` 序号、`byte2~7` 最多 3 个 int16 小端样本。低优先级发送，不得挤占 0x321/0x322。

### 8.5 故障码

| 值 | 含义 | 典型原因 |
|---|---|---|
| 0 | 无故障 | — |
| 1 | `AFE_NO_RESP` | AFE 上电/配置后 500ms 无 DRDY：PWDN/RESET 引脚不对、SPI 不通、时序引擎未启 |
| 2 | `AFE_SPI` | 寄存器写读回环失败：SPI 模式/片选/接线问题 |
| 3 | `SAMPLE_LOST` | 主循环跟不上 500Hz：主循环里加了长阻塞、SPI 太慢 |
| 4 | `CAN_BUSOFF` | 总线异常：波特率不一致、未接终端电阻、只有本节点在发 |

### 8.6 正式链路目标：CANopen（待迁移）

合同 8.1 / 8.3 / 8.7 冻结：Node-A、Node-B → Gateway-C 使用 **CANopen CC（CiA 301） over Classic CAN**，并优先复用标准机制，**不再自行设计通用通信协议**。因此第 8.1～8.5 节的自定义帧必须在接入 Gateway-C 前完成迁移。迁移对照：

| 样机期自定义帧 | CANopen 目标形态 |
|---|---|
| `0x321` 测量结果（200ms） | 血氧 **TPDO**：SpO2、PR、信号质量、探头状态、数据有效性、结果序号 |
| `0x322` 心跳诊断（1000ms） | **Heartbeat**（在线状态）+ **SDO**（固件版本、收/发计数等诊断量） |
| `0x323` 波形（可选） | 低优先级 TPDO，或按需 SDO 分段读取；是否上传由系统统一决定 |
| `0x120` 上游命令 | **SDO 写对象** 或 **RPDO**（开始/停止/复位/清故障/查询） |
| 故障码（byte5） | **EMCY**（关键故障）+ 对象字典中的 Fault 对象 |
| 模块状态（byte0/byte3） | CANopen **NMT 状态** + 状态类业务对象 |

迁移工作量评估与建议路径：

1. **不必推倒重来**。`app_state.c`、`app_measurement.c`、算法层完全不动；改动集中在“出口”。
2. 在 `DRIVER/CAN` 旁增加 `DRIVER/CANOPEN/`（`canopen_app.c` / `canopen_app_od.c` / `canopen_port.c`），把 `can_protocol.c` 中的编码逻辑替换为“写对象字典 → 触发 TPDO”。
3. `CAN_PollCommand()` 改为协议栈回调，命令仍进同一个队列由 `App_State_Run()` 执行（**保持“ISR 不执行业务”的纪律不变**）。
4. 对象字典的 **Index / Sub-index / PDO 映射 / 节点 ID / 波特率由 P 在《CANopen 对象字典与 PDO 映射设计》中冻结**，本工程只在 `CONFIG/od_index.h` 登记实际占用项。
5. 协议栈优先评估成熟开源实现（如 CANopenNode），**不自行重写 CANopen 核心协议**。
6. 迁移期间可保留一个编译开关，让同一份业务代码既能走自定义帧自测，也能走 CANopen 接入 Gateway-C。

> 上云链路（MQTT 3.1.1 over TLS、腾讯云 Broker、Backend、Nginx、Web 大屏）由 P 在 Gateway-C 与云端实现，**本模块不实现**；本模块只需保证对象里的数据语义与合同 8.6 数据字典一致。

## 9. 中断与任务边界（重要纪律）

| 中断 | 处理函数 | 只做什么 | 不做什么 |
|---|---|---|---|
| `SysTick_Handler` | `USER\stm32f4xx_it.c` | `g_msTick++` | 不做业务 |
| `EXTI0_IRQHandler` | → `AFE4490_OnDrdyISR()` | 计数 + 置标志 | **不读 SPI** |
| `CAN1_RX0_IRQHandler` | → `CAN1_BSP_RxIrq()` | 取帧入 8 深环形队列 | **不解析命令、不执行命令** |

主循环负责：SPI 读数、算法计算、命令执行、CAN 发送、日志。

**SysTick 二选一**：`Tick_1ms_Start()` 之后**禁止再调用 `Delay_ms()` / `Delay_us()`**（它们会改写 SysTick 的 LOAD/CTRL，破坏 1ms 时基）。运行期延时统一用 `GetTick_ms()` 差值，AFE 驱动里已封装为 `AFE_DelayMs()`。

## 11. 分阶段调试路径（按这个顺序走，别跳步）

| 阶段 | 做什么 | 判据 |
|---|---|---|
| **A 回环自测** | `CAN1_LOOPBACK_EN=1`，不接总线 | 串口每秒有日志；`tx` 计数在涨；`rx` 也涨（自发自收） |
| **B 波形验证** | `APP_DEBUG_RAW=1`，串口助手收 `red,ir`，粘到 Excel/串口波形助手 | 手指放上去能看到明显周期性脉动波，幅度合理 |
| **C 阈值标定** | 看无手指/有手指时 `ir_raw` 基线 | 定下 `FINGER_DC_THRESHOLD` |
| **D 接总线** | `CAN1_LOOPBACK_EN=0`，接 CAN 收发器 + 120Ω 终端电阻 + 同波特率伙伴节点 | CAN 分析仪能看到 0x321/0x322；或用 USB-CAN 工具 |
| **E 主屏联调** | 主屏发 0x120 命令 | `CMD_STOP` 后结果立刻变 0xFF；`CMD_QUERY` 立即回帧；拔手指后 byte3 变 4 |

## 12. 常见故障排查

| 现象 | 可能原因 | 怎么查 |
|---|---|---|
| 串口无任何输出 | 没进 main / 串口引脚错 | 看 LED 是否 500ms 翻转；确认 PA9/PA10 |
| 一直 `fault=1`（AFE_NO_RESP） | PWDN/RESET 引脚不对、SPI 不通、AFE 没上电 | 量 PC0 电压；示波器看 PA0 是否有 DRDY 脉冲；看 SCK 是否有波形 |
| 一直 `fault=2`（AFE_SPI） | SPI 模式/片选错 | 确认 CPOL=0/CPHA=1Edge；CS=PA4；SPI1 未被 Flash 初始化抢占 |
| 一直 `st=2`（等不到手指） | 阈值太高或探头没插好 | `APP_DEBUG_RAW=1` 看 `ir` 实际值，下调 `FINGER_DC_THRESHOLD` |
| `spo2=-1` 一直无效 | DC 太低或 R 超范围 | 看 `q`（质量）；调 LED 电流 / TIA 增益；确认红红外没接反 |
| PR 忽大忽小 | 波形噪声大或阈值不合适 | 先看阶段 B 的波形是否干净；加大 `PR_MEDIAN_LEN` 或 `PPG_MA_LEN` |
| 偶尔 `fault=3`（丢样） | 主循环被阻塞 | 主循环里不要加长 `printf` 或长延时；日志降频 |
| CAN 一直 Bus-Off | 波特率不一致 / 无终端电阻 / 总线上只有本节点 | 两端各接 120Ω；确认伙伴节点波特率一致且已上电 |
| 自发自收能通，接总线不通 | 还开着回环 | 确认 `CAN1_LOOPBACK_EN=0` |
| 拔掉手指仍显示旧值 | — | 已由 `Measurement_Reset()` 处理；若仍出现，检查是否在别处缓存了结果 |

## 14. 已知限制与待办

1. **未在本机编译过**：本机没有 Keil 编译器，请在 MDK 里 `Rebuild`，把报错发给我，我逐条修。
2. `FINGER_DC_THRESHOLD = 5000` 是估值，**必须上机实测标定**。
3. `SpO2 = 110 − 25R` 是通用经验式，**正式产品必须用血氧模拟器重新标定系数**。
4. 寄存器映射以 TI 数据手册为准：`0x0D~0x14` 是 ADC 转换窗口，`0x15~0x1C` 是 ADCRST 计数（与部分笔记“0x15~0x1C 为转换窗口”的说法不同）。
5. CAN1 引脚 PA11/PA12 与板卡其他功能是否冲突，需对照原理图确认。
6. 本工程无 RTOS，主循环必须在 2ms 内跑完一圈，否则 500Hz 采样会丢。
7. `HARDWARE\spi.c`（W25Q Flash）与 AFE 共用 SPI1，本工程未使用，不要调用其初始化。
8. **CAN 应用层仍是样机期自定义帧，尚未迁移到 CANopen**（合同 8.1 / 8.7 的正式链路要求）。接入 Gateway-C 前必须完成第 8.6 节的迁移；对象字典的 Index/PDO 映射需等 P 冻结《CANopen 对象字典与 PDO 映射设计》后才能落地。
9. **未纳入本工程的项**：MQTT/TLS、腾讯云、Nginx、Web 大屏、Gateway 离线缓存均由 P 负责，本模块不实现；本模块只需保证对外数据语义与合同 8.6 数据字典一致。
10. **本地屏尚未与本固件联调**：本工程目前只输出 USART1 日志和 CAN 帧，血氧独立显示屏（UART + VisualTFT 工程）的页面驱动与数值刷新还未接入 `g_measurement`，属于合同 4.1 / 验收条件中的必交项。
