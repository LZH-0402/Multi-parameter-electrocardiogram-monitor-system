# 基于 STM32F407 的血氧（SpO₂ / 脉率）监测模块项目书

## 摘要

本项目为"多参数心电监护仪系统"中的**血氧（SpO₂）子系统**，目标是完成从光电采集、信号解算、状态管理到人机交互的完整闭环。系统以 STM32F407ZGT6 为主控，前端采用 TI AFE4490 血氧模拟前端采集指尖透射式光电容积脉搏波（PPG），由 Arduino UNO 中转完成 AFE 驱动与 SpO₂ / 脉率（PR）算法，再通过 UART 把结果传给 STM32；STM32 汇总后驱动大彩（Dacai）组态串口屏，实现实时数值、实时波形、趋势回看、报警记录、参数设置、探头检测与暂停监护等功能。

项目采用标准外设库（SPL）开发，工程最终固件 `Code≈11.7 KB（RO-data=596 B / RW-data=172 B / ZI-data=3196 B）`，Keil AC5 编译零错误零警告，已在实机上完成端到端联调与验收（屏上实测 SpO₂ / PR / 信号质量 / PPG 波形 / 趋势均正常）。血氧与血压两套代码为独立仓库，共用同一块主控板与同一块串口屏，引脚与串口显式隔离、零冲突。

## 1 项目概述

### 1.1 项目背景与需求

血氧饱和度（SpO₂）与脉率（PR）是心电监护仪的核心生命体征参数。在"多参数心电监护仪系统"的整体架构中，血氧模块承担独立的采集、解算与展示职责，需要满足以下需求：

| # | 需求 | 说明 |
|---|------|------|
| R1 | 实时数值 | SpO₂（0~100%）、脉率（bpm）、灌注 / 信号质量（0~100）每 400 ms 刷新 |
| R2 | 实时波形 | PPG 脉搏波曲线在主界面滚动，约 90 点/s |
| R3 | 趋势回看 | SpO₂ / PR 历史曲线，2 秒/点，可选 1 / 5 / 30 分钟窗口 |
| R4 | 报警记录 | 越限**持续 3 秒**才记一条（防抖），滞回解除，最多 4 行，带蜂鸣提示 |
| R5 | 参数设置 | 报警下限（SpO₂）/ 上限（PR）可改并回写主界面；亮度、声音提示可调 |
| R6 | 时钟 | 屏右上角显示 `YYYY-MM-DD HH:MM:SS`，与血压工程格式一致 |
| R7 | 探头检测 | 拔掉指套后数值变 `--`，各页状态条变"探头未接入" |
| R8 | 暂停监护 | 暂停后**真正停测**（波形停、数值 `--`、监护时间冻结），按钮文字变"继续监护" |

**硬性约束**：

1. 主控为 **STM32F407ZGT6 神舟板**（板卡既定，标准外设库 SPL，非 HAL）；
2. 串口资源已被预分配：USART1 = 调试、USART2 = 串口屏、USART3 = **血压传感器（血氧不得占用）**；
3. 血氧与血压两套代码**独立仓库**，只共用物理串口屏和主控板。

### 1.2 功能设计

系统按"页"组织功能，共设计 **7 个界面**，覆盖完整操作链路：

| 画面 | 画面号 | 核心功能 |
|------|-------|---------|
| 主界面 | 0 | 显示 SpO₂ / PR / 信号质量 / PPG 波形 / 监护时间 / 采集状态；提供"暂停监护"入口 |
| 趋势 | 1 | SpO₂ 与 PR 两条历史曲线（2 s/点），1 / 5 / 30 分钟窗口切换，含最近值与时间刻度 |
| 报警记录 | 2 | 4 行 × 4 列记录表格，越限持续 3 s 记一条，最多 4 条，可清空 |
| 设置 | 3 | 报警下限 / 上限输入、亮度调节、声音提示开关 |
| 暂停监护弹窗 | 4 | 二次确认是否暂停，确认后真正停测 |
| 探头状态 | 5 | 探头接入 / 未接入状态与质量进度条 |
| 清空报警弹窗 | 6 | 二次确认清空报警记录 |

**系统架构**

```
指夹探头(660nm/880nm)
      │ 光电信号
      ▼
   AFE4490 模拟前端 ──SPI+DRDY──► Arduino UNO（读 AFE + 算 SpO₂/PR）
      │                              │ 二进制帧（17 B，≈90 帧/s）
      │                              ▼
      │                    STM32F407ZGT6（主控，SPL）
      │                    解帧 → 汇总 g_meas → 驱动屏 / 报警
      │                              │ RS232（USART2，115200）
      ▼                              ▼
               大彩 DC80480DN050 组态串口屏（7 个画面）
```

**设计要点**

1. **单一数据源**：UNO 解析出的测量结果统一写入结构体 `g_meas`，屏、报警、调试串口都只**读**这一份，禁止各模块另存一套数值。
2. **单一写者**：屏上每一个控件**只允许一个写者**（本工程为 MCU 独占写，屏端 Lua 脚本已停用），从根上杜绝"两边抢写同一控件"。
3. **节拍分离**：波形（≈90 Hz）、数值（400 ms）、趋势（2 s）、时钟（1 s）各自独立节拍，互不阻塞；串口中断只收字节，解析和刷新全部在主循环完成。
4. **分步验证**：`DEMO_STEP` 宏把整个系统拆成 4 步独立验证（心跳 → 屏链路 → UNO 链路 → 全链路），每一步都有独立的观察手段。

### 1.3 技术方案

| 层次 | 方案选择 | 选型理由 |
|------|---------|---------|
| 主控 | STM32F407ZGT6（168 MHz） | 性能充裕，6 路 USART，双板（血压/血氧）可复用同一套底层 |
| 血氧前端 | TI AFE4490 + Arduino UNO 中转 | UNO 盾板即 5 V 原生接口，自带现成 Arduino 驱动库，零电平转换；AFE 时序风险隔离在 UNO 端 |
| 人机界面 | 大彩 DC80480DN050 组态串口屏 | 组态化开发，界面与业务解耦；MCU 仅通过串口下发指令 |
| 驱动库 | ST 标准外设库（SPL） | 与课程教学环境一致，寄存器级可控，便于调试 |
| 工具链 | Keil MDK AC5（V5.14） | 与既有工程链一致，支持命令行批量编译 |
| 通信 | 3 路独立 UART | 屏、UNO、调试物理分离，互不干扰；与血压共用 USART1/2，互不抢占 |

**架构选型对比：为什么让 Arduino UNO 当"血氧协处理器"**

AFE4490 的数据获取有两条可行路线，项目书阶段做了对比：

| 对比项 | 方案一：STM32 SPI 直连 AFE4490 | **方案二：UNO 中转（采用）** |
|---|---|---|
| 电平 | 盾板原生 5 V 逻辑，上行 5 路需 3.3 V→5 V 升压（2×SN74AHCT125） | 盾板↔UNO 天然同为 5 V，**零电平转换** |
| 驱动 | 需把 Arduino 版 AFE4490 库移植到 SPL | 手头驱动库即 Arduino 库，**原样可用** |
| 引脚占用 | SPI1(PB3/4/5)+PA4+PA0+PC13+PG15，其中 PB3/PB4 与 JTAG 冲突 | **只占 USART6（PC6/PC7）**，其余全部释放 |
| 风险 | SPI 时序、DRDY 边沿、复位时序都要上示波器实测 | AFE 细节全部封在 UNO 端，风险集中且低 |
| 缺点 | —— | 多一块 UNO、多一路串口协议 |

**结论：联调与样机阶段采用方案二**。STM32 不碰 SPI，只做"收帧 → 汇总 → 显示/报警"，把最难啃的 AFE4490 时序问题隔离在一块 5 V 的 UNO 上。方案一作为后续升级路线保留（若需省掉 UNO、提高集成度，再按 2.4 节引脚表把 AFE4490 直连 STM32）。

**关键节拍**

| 节拍 | 周期 | 动作 |
|---|---|---|
| UNO 发帧 | ≈90 帧/s（17 字节/帧） | IR/RED 原始值 + SpO₂/PR 结果 |
| PPG 波形 | 每帧 1 点 | MCU 归一化后攒 16 点发一帧曲线 |
| 数值刷新 | 400 ms | SpO₂/PR/质量/状态 + 报警判定 |
| 趋势落点 | 2 s | 两条历史曲线各追加一点 |
| 软 RTC | 1 s | 推进年月日时分秒，每 5 分钟 `EE 81` 同步屏 |
| 自愈补发 | 3 s | 把 MCU 负责的文案整轮重写一遍，抗屏重绘冲掉 |

**与血压模块的资源共存**

血氧与血压在**同一块主控板**上运行，引脚与串口做了显式隔离，**零冲突**：

| STM32 资源 | 血氧模块 | 血压模块 |
|---|---|---|
| USART1（PA9/PA10） | 调试日志（共用一致） | 调试日志 |
| USART2（PA2/PA3） | 串口屏（共用一致） | 串口屏 |
| USART3（PB10/PB11） | **不碰** | 血压传感器 |
| USART6（PC6/PC7） | **血氧数据（UNO 中转）** | 不用 |
| SPI1 / PA4 / PA0 / PC13 / PG15 | 释放（仅方案一直连时才用） | 不用 |

## 2 硬件设计

### 2.1 硬件选型

| 序 | 器件 | 型号 / 规格 | 作用 | 选型理由 |
|---|---|---|---|---|
| 1 | 血氧模拟前端 | **TI AFE4490** 盾板（AFE44xx Shield） | LED 驱动 + 光电接收 + ADC，输出 PPG 原始值 | 片上集成 H 桥/TIA/ADC，是血氧专用 AFE，资料与 Arduino 库齐全 |
| 2 | 指夹探头 | 与盾板配套的 660 nm 红光 + 880 nm 红外双 LED 探头 | 透射式采血 | 盾板原装接口，即插即用 |
| 3 | 血氧协处理器 | **Arduino UNO R3**（ATmega328P，5 V） | 读 AFE4490、跑 SpO₂/PR 算法、串口发帧 | 盾板即 UNO R3 盾，堆叠即用；自带现成算法库 |
| 4 | 主控 | **STM32F407ZGT6** 神舟板（168 MHz） | 解帧、报警、驱动屏、人机交互 | 项目既定主控；串口资源丰富（6 路 USART） |
| 5 | 显示 | **大彩 DC80480DN050** 5" 800×480 串口屏（M 系列） | 全部图形界面 | 组态式开发（VisualTFT），MCU 只发指令，省 GUI 移植工作量 |
| 6 | 电平转换 | **SP3232**（板载 RS232 收发器） | STM32 TTL ↔ 屏 RS232 | 屏出厂为 RS232 电平 |
| 7 | 供电 | 神舟板 VOUT2 +5 V | UNO 与盾板取电 | 统一供电，少一根线 |

### 2.2 关键器件使用方法

**（1）AFE4490：一颗"片上血氧前端"**

AFE4490 内部没有 MCU，它只做三件事：

1. 用内部 H 桥**交替点亮**两颗 LED（红光 ≈660 nm / 红外 ≈880 nm）；
2. 光电二极管收到透射光 → 跨阻放大器（TIA）→ ADC 采样；
3. 内部时序引擎按**脉冲重复周期 PRP** 循环，一个 PRP 内依次完成 4 个相位：`LED2 亮` → `LED2 灭（测环境光）` → `LED1 亮` → `LED1 灭（测环境光）`，结果写进 6 个结果寄存器（**0x2A~0x2F**）。

> **要点**：环境光是**减出来的**，不是滤出来的——这就是为什么要读 4 个寄存器做差，而不是只读一个"亮度值"。

**（2）盾板与 UNO：堆叠即用**

盾板是标准 UNO R3 排母盾，**直接堆叠，无需飞线**。SPI 走 UNO 硬件 SPI，控制/中断脚由库 `S_afe44xx.cpp` 里的宏定义决定：

| 盾板丝印 | UNO 引脚（典型） | 说明 |
|---|---|---|
| SCK / MISO / MOSI | D13 / D12 / D11 | 硬件 SPI |
| !CS | D10 或 D9（以库宏为准） | 片选，低有效 |
| START | D8 或 D9（以库宏为准） | 实际接 AFE 的 **!RESET** 路径 |
| !PWDN/RESET | D8 或 D9（以库宏为准） | 掉电控制，运行时保持高 |
| !DRDY | D2（外部中断） | 数据就绪，UNO 在中断里置标志 |
| 5 V / GND | UNO 5 V / GND | 盾板逻辑 + LED 驱动供电 |

> ⚠️ 盾板丝印 `START` **不要**按"转换启动"理解——原理图上它接的是 AFE 的复位路径；`!PWDN/RESET` 才是掉电控制。两者都接普通 GPIO。

**（3）串口屏：RS232 电平，注意电平转换**

DC80480DN050 出厂默认 **RS232 电平**。接 STM32 的 TTL 前必须：经板载 **SP3232** 转 RS232（本工程采用），或短接屏背板 J5 跳线改为 TTL。屏通信参数：**115200 bps，8N1，关闭 CRC**。

### 2.3 接口设计与引脚分配

三路 UART 分工明确，物理层完全隔离：

| 串口 | 引脚 | 波特率 | 对接设备 | 电平 | 用途 |
|------|------|--------|---------|------|------|
| USART1 | PA9 (TX) / PA10 (RX) | 115200 | PC（CH340） | TTL via USB | 调试日志输出 |
| USART2 | PA2 (TX) / PA3 (RX) | 115200 | 大彩串口屏 | RS232（经 SP3232） | 屏指令收发 |
| USART6 | PC6 (TX) / PC7 (RX) | 57600 | Arduino UNO | TTL 直连 | UNO 帧收发 |

**关键电平分析（易错点，务必按引脚类型接线）**

UNO ↔ STM32 这一段是跨电压域直连，是本工程硬件设计的关键：

| 方向 | 发送端 | 电平 | 接收端 | 为什么可以直连 |
|---|---|---|---|---|
| UNO → STM32 | UNO D1（TX） | 5 V | PC7（USART6_RX） | PC7 是 **FT 脚（5 V 容忍）**，可直接接收 5 V |
| STM32 → UNO | PC6（USART6_TX） | 3.3 V | UNO D0（RX） | ATmega328P 输入高阈值 V_IH ≈ 0.6×VCC ≈ 3.0 V，3.3 V 满足 |
| 共地 | — | — | 任意 GND | **必须共地** |

> ⚠ **电平分析是本项目硬件设计的关键一步**：不是"5 V 接 3.3 V 一定烧"，而是要查 STM32F407 数据手册的**引脚类型表**——只有标 **FT** 的脚才能吃 5 V，标 TTa 的脚（如 PA4）绝不能。同理，3.3 V → 5 V 方向能不能省掉升压，取决于对端 V_IH 阈值。本工程 UNO→STM32 用 FT 脚直连，STM32→UNO 靠对端 V_IH 满足，全程**无需电平转换**。

> ⚠ UNO 的 D0/D1 同时接板载 CH340（USB 转串）。联调时 **UNO 由神舟板 5 V 供电、不连 USB**，否则 CH340 会和 STM32 抢 D0/D1。

**接线示意**

```
Arduino UNO                       STM32F407
  D1 (TX, 5V)  ──────────────────→ PC7 (USART6_RX, FT 脚)
  D0 (RX, 3.3V←) ←─────────────── PC6 (USART6_TX, 3.3V)
  GND           ────────────────── GND

STM32F407                        大彩串口屏
  PA2 (USART2_TX) → SP3232 → RS232 TX ─→ RX
  PA3 (USART2_RX) ← SP3232 ← RS232 RX ←─ TX
  （屏与板均为 DTE，需 TX↔RX 交叉）
```

**供电**

| 供电对象 | 来源 |
|---|---|
| AFE4490 盾板 | UNO 5 V 排针（堆叠取电） |
| Arduino UNO | 神舟板 VOUT2 的 +5 V |
| STM32 神舟板 | 自身 5 V / USB |
| 大彩串口屏 | 由 STM32 侧 RS232（SP3232）供电 |

### 2.4 备选路线：方案一的引脚表（AFE4490 直连 STM32，暂不采用）

若后续要把 UNO 去掉、把 AFE4490 直接挂到 STM32，引脚分配如下（已核对与血压零冲突）：

| 血氧板丝印 | STM32 引脚 | 说明 | 电平转换 |
|---|---|---|---|
| SCK | PB3 / SPI1_SCK | SPI 时钟 | 上行 5 路需 3.3 V→5 V 升压 |
| MISO | PB4 / SPI1_MISO | 血氧板→STM32 | **直连（PB4 为 FT 脚）** |
| MOSI | PB5 / SPI1_MOSI | STM32 写寄存器 | 同上行 |
| !CS | PA4（GPIO 输出） | 片选，空闲必须为高 | 同上行；PA4 是 TTa，绝不能接 5 V 输入 |
| !DRDY | PA0 / EXTI0 | 数据就绪中断 | **直连（PA0 为 FT 脚）** |
| START | PC13（GPIO 输出） | 实为 AFE !RESET | 同上行 |
| !PWDN/RESET | PG15（GPIO 输出） | 掉电控制，运行时保持高 | 同上行 |

最小 BOM：**2 片 SN74AHCT125**（8 通道用 5 路）。不建议用 BSS138 双向模块或 TXS0108E 跑 SPI（方向/速率不匹配）。注意事项：PB3/PB4 带 JTAG 标签，用 SPI1 时必须关全 JTAG、保留 SWD；PA0 兼作 WK_UP 按键；PC13 驱动能力弱（≤3 mA）。

### 2.5 使用方法

1. **上电前自检**：盾板已堆叠到 UNO，UNO 单独供电能在 PC 串口助手看到 SpO₂ 出数；
2. **上电**：板卡与屏分别供电，屏进入主界面，右上角开始显示走时；
3. **链路自检**：MCU 上电后向屏发送"查询当前画面"指令，屏应答即证明**接线、波特率、帧格式三项均正确**——这是最可靠的链路自检手段；
4. **佩戴探头**：将指夹探头夹于指尖，松紧适中，避免漏光；
5. **开始监测**：主界面实时显示 SpO₂ / PR / 波形 / 监护时间；
6. **查看趋势**：点"趋势"进入历史曲线页，选择 1 / 5 / 30 分钟窗口；
7. **查阅报警**：越限持续 3 s 后自动记录，可在报警记录页查看或清空；
8. **调整设置**：在设置页修改报警阈值、亮度与声音提示；长按暂停可真正停测，按钮文字变为"继续监护"。

## 3 软件设计

### 3.1 软件架构

固件采用分层结构，硬件相关与协议相关代码严格分离，`uno.c` 与 `dc_hmi.c` 均为**纯 C、不依赖任何 MCU SDK**，可移植到其他平台。

```
STM32F407_SPO2/
├── USER/main.c               DEMO_STEP 分步验证 + 主循环节拍调度
└── HARDWARE/
    ├── SYS/sys.c             SysTick → millis()（统一时基）
    ├── USART/usart.c         USART2(屏) / USART6(UNO) 初始化与收发
    ├── DEBUG/debug.c         USART1 调试心跳与抓包
    ├── UNO/uno.c             ★ UNO 帧解析状态机 → 写 g_meas
    └── HMI/
        ├── dc_hmi.c/.h       ★ 大彩屏指令集（下行组帧 / 上行通知解析）
        ├── hmi_ids.h         全部控件 ID 与"控件归属"权威定义
        └── app_bloodoxygen.c ★ 应用层：节拍调度 / 报警 / 软 RTC / 按键回调
```

设计原则：**中断只置标志、串口只在主循环解析、算法只写 `g_meas`、屏/报警/日志只读 `g_meas`**。各层通过回调解耦：UNO 解析出一帧后回调 `on_uno_frame()`，屏层接收字节后由 `hmi_rx_feed()` 组装成帧再回调 `hmi_rx_frame()`，应用层只在回调中处理业务逻辑。

### 3.2 AFE4490 的 SPI 时序与寄存器地址

> 说明：题目模板提到"iic、地址、协议、算法"。**本项目 AFE4490 用的是 SPI 而不是 IIC**（AFE4490 只有 SPI 接口，没有 I²C），所以本节按 **SPI 时序 + 寄存器地址 + 串口协议 + 算法** 展开，思路与 IIC 项目完全同构：都是"设备地址 + 寄存器读写 + 数据帧 + 解算算法"。

**SPI 参数**

| 参数 | 值 | 依据（TI 手册 SBAS602H） |
|---|---|---|
| 总线 | SPI，全双工 | — |
| 模式 | **Mode 0（CPOL=0, CPHA=0）**，MSB 先发 | "SCLK 空闲保持低电平；SIMO 在 SCLK 上升沿被锁存" |
| 时钟频率 | UNO 默认 4 MHz（上限 16 MHz） | 手册电气特性 |
| 帧长 | **固定 32 bit = 8 bit 地址 + 24 bit 数据** | 数据在第 32 个 SCLK 上升沿锁存 |
| 片选 | !CS 低有效，一次访问必须拉低满 32 个时钟 | — |

**"反常识"的三点（踩坑高发）**

1. **读和写是同一个地址字节，靠最高位区分**：地址字节的 bit7 = `SPI_READ`。写寄存器发 `0x00|addr`，读寄存器发 `0x01|addr`（即 `addr+0x80`）。忘记置这一位是 AFE4490 驱动"读出来永远是 0"的最常见原因。
2. **一帧必须凑满 32 bit**：少一个时钟都不锁存。
3. **MISO 不会自动进入高阻**：片选无效时 `SPISOMI / ADC_RDY / PD_ALM / LED_ALM / DIAG_END` 仍驱动。若同一 SPI 总线还挂别的器件，必须置 `CONTROL2.DIGOUT_TRISTATE = 1`，否则总线打架。

**关键寄存器**

| 地址 | 名称 | 作用 | 本工程典型值 |
|---|---|---|---|
| 0x2A~0x2D | LED2VAL / ALED2VAL / LED1VAL / ALED1VAL | 4 个相位的转换结果 | 只读 |
| 0x2F | TIAGAIN | TIA 跨阻增益 | `0x000000`（500 k，先调 LED 电流再调增益） |
| 0x30 | LEDCNTRL | LED2/LED1 电流 | `0x001414` ≈ 20 mA（按信号幅度调） |
| 0x01~0x04 | PRP / LED 打宽 / 占空比等时序组 | 采样周期与时序 | 库默认 |
| — | CONTROL0/1/2 | 模式、TRISTATE 等 | 库默认 |

> **DRDY（ADC_RDY，pin 28）**：AFE 每完成一个 PRP 就打一个 ≈250 ns 脉冲，意思是"6 个结果寄存器刚全部刷新，现在读不会读到半新半旧"。**中断服务函数只置标志，绝不在中断里读 SPI**——这是保证实时性又不出错的通用写法。

### 3.3 UNO → STM32 串口协议

**物理层**

| 项 | 值 |
|---|---|
| 串口 | USART6（PC6/PC7），TTL 直连 |
| 波特率 | **57600，8N1** |
| 帧率 | ≈90 帧/s |
| 带宽占用 | 17 B × 90 = 1530 B/s，占 57600 波特（5760 B/s）的 **≈27%**，余量充足 |

**帧格式（17 字节，源自 AFE4490_library Example-1 二进制帧）**

```
┌──────┬──────┬──────────┬──────┬──────────┬──────────┬──────┬──────┬──────┬──────┐
│ 0x0A │ 0xFA │ 0x0A 0x00│ 0x02 │  IR_data │ RED_data │ spo2 │  hr  │ 0x00 │ 0x0B │
│ 同步1 │ 同步2 │ 长度=10 │ DATA │ int32 LE │ int32 LE │u8   │ u8   │ 保留 │ 帧尾 │
└──────┴──────┴──────────┴──────┴──────────┴──────────┴──────┴──────┴──────┴──────┘
   0      1        2~3      4       5~8       9~12     13     14     15     16
```

- `IR_data`：int32 小端，对应 LED1VAL（红外）；
- `RED_data`：int32 小端，对应 LED2VAL（红光）；
- `spo2`：uint8，0~100；未算出 / 探头错误 = 0；
- `hr`：uint8，bpm；0 = 无效。

**同步策略（抗"数据里出现帧头字节"）**

IR/RED 是任意 32 bit 数据，**完全可能包含 `0x0A`/`0xFA`**。所以不能只找 2 字节头，本工程用**8 状态状态机**：

```
匹配 5 字节固定头 0A FA 0A 00 02 → 收 10 字节负载 → 校验帧尾 00 0B → 交付
任何一步不符 → 回到 S0_SYNC1 重新找头
```

双保险（固定 5 字节头 + 帧尾二次校验）使得误同步概率趋近于 0。

**健壮性设计：连"波特率配错"都能看出来**

串口中断里**先记账再判状态**：每个字节都累计到 `g_uno_rx_bytes`，并塞进一个**最近 32 字节环形缓冲**。这样即使波特率配错、同步不上，调试口也能看到"字节确实在进、进的是什么"——把"链路不通"和"解析错误"两类问题分开定位。`main.c` 还内置了**波特率自动探测**（按候选列表逐个试，选收到字节数最多的那个）。

### 3.4 大彩组态屏协议

**帧格式**

```
┌──────┬───────────────┬──────────────┐
│ 0xEE │  命令 + 参数   │ FF FC FF FF  │
└──────┴───────────────┴──────────────┘
 帧头                  固定帧尾（4B）
```

16 位与 32 位参数一律**高字节在前**（大端）。

**核心指令**

| 功能 | 帧结构 |
|------|--------|
| 切换画面 | `EE B1 00 <画面号:16> FF FC FF FF` |
| 查询当前画面 | `EE B1 01 FF FC FF FF` |
| 写文本 / 进度条 / 按钮状态 | `EE B1 10 <画面:16> <控件:16> <ASCII/GBK> FF FC FF FF` |
| 写整数 | `EE B1 07 <画面> <控件> <sign> <0x80|digits> <u32>`（需固件 ≥908，否则退回 B1 10 + sprintf） |
| 显隐 | `EE B1 03 <画面:16> <控件:16> <visible:8>` |
| 使能 | `EE B1 04 <画面:16> <控件:16> <enable:8>` |
| 曲线加数据 | `EE B1 32 <画面:16> <控件:16> <通道:8> <点数:16> <数据...> FF FC FF FF` |
| 曲线清空 | `EE B1 33 <画面:16> <控件:16> <通道:8>` |
| 历史曲线加点 | `EE B1 60 <画面:16> <控件:16> <各通道数据>`（**每点字节数由屏属性 `sample_data_foramt` 决定**） |
| 历史曲线使能 | `EE B1 61 <画面:16> <控件:16> <enable:8>` |
| 历史曲线一屏点数 | `EE B1 63 <画面:16> <控件:16> 00 <count:16>` |
| 设 RTC | `EE 81 <Sec><Min><Hour><Day><Week><Mon><Year>`（全 BCD） |

> ⚠ **实测这条屏不认"批量更新（B1 12）+ 刷屏开关（B3）"链路**（官方样例用的就是这条），会静默丢弃、控件永远显示 `--`。所以本工程写屏**一律用单条指令**。

**按钮事件两类（行为差异显著）**

- **切页型**（`button_type = 0`）：按下后**屏自己先跳页**，再上报事件。因此 MCU 收到的事件中，画面号是**目标页**而非源页。
- **瞬变型**（`button_type = 1`）：**屏不跳页**，只上报事件，必须由 MCU 主动下发切页指令将其送走。

**上行通知（MCU 解析）**

工程配置 `DeviceControlNotify="3"`（**按下和弹起都上报**）⇒ **一次点击会收到两帧**，因此所有"翻转型"动作（声音开关、暂停确认）必须只认 `state==1`，否则一次点击翻转两次等于没反应。

| 通知 | 帧格式 | 长度 |
|---|---|---|
| 画面切换 | `EE B1 01 <screen:16> FF FC FF FF` | **9 字节** |
| 按键 | `EE B1 11 <screen:16> <ctrl:16> 10 <state> FF FC FF FF` | 14 字节 |
| RTC 应答 | `EE F7 <Year><Mon><Week><Day><Hour><Min><Sec> FF FC FF FF` | 13 字节 |

> ⚠ 解析帧长门限必须 ≤9。曾把门限写成 11，导致 9 字节的"画面切换通知"整条被丢、`NotifyScreen()` 从未被调用——**不报任何错，纯靠"为什么切页后控件没刷新"反推出来**。

**屏上 7 个画面与控件 ID 分配**

| 画面 ID | 画面 | 关键控件（ID） |
|---|---|---|
| 0 | 主界面 | SpO₂(10) PR(11) 有效状态(12) 报警限值(13/15) 状态(14/16) 质量(17) PPG 波形(19) 采集状态(20) 监护时间(21) 暂停键(1) 继续键(6) |
| 1 | 趋势 | SpO₂ 历史(12) PR 历史(14) 时段文本(13) 最近值(10/11) 时间刻度(15~18) 时段按钮(1/2/3) |
| 2 | 报警记录 | 4 行 × 4 列(20~35) 条数(10) 空态(11) |
| 3 | 设置 | 阈值输入(1/2) 进度条/滑块(10/11) 亮度%(12) 声音状态(13) |
| 4 | 暂停监护 | 提示语(10) 确认(2) |
| 5 | 探头状态 | 探头状态(13) 质量进度条(16) |
| 6 | 清空报警记录 | 确认(2) |

> ⚠ **控件 ID 只在画面内唯一**：主界面的 12 是"有效状态"，趋势页的 12 是"SpO₂ 历史曲线"。写控件必须带对 `screen`，否则会写到别的画面去。

### 3.5 接收架构设计

固件采用 **中断收字节 + 环形缓冲 + 主循环解析** 的接收架构，解决高速收发下的丢字节问题。

**为什么不在中断里处理**

UNO 以 57600 bps 上报约 90 帧/s，屏以 115200 bps 双向通信。若在接收中断中直接打印调试信息（每字节约 7 个字符），期间后续字节来不及被读取，将触发 ORE（溢出）错误，导致整帧被打散、解析失败。

**实际架构**

```
UART 硬件接收
    ↓ 每收到一字节触发中断
on_uart_rx()：【仅记账 + 入队，不做任何打印】
    累计 s_rx_bytes；写入最近 32 字节环形缓冲（用于诊断）
    送入协议状态机（UNO 帧 / 屏帧各自独立）
    ↓
app_loop() 主循环：【在此打印 RX 诊断 + 执行业务逻辑】
    出队 → 协议解析器交付完整帧 → 回调处理
```

关键点：**中断只负责记账与入队，一切耗时操作（打印、解析、业务）都推迟到主循环**。此外，"先记账再判状态"使调试口能区分"链路不通"（字节不进）与"解析错误"（字节进但不同步），`main.c` 心跳里带 `hmi_rx=` / `uno_rx=` 计数，点一次按钮看计数跳增多少字节，即可判断通知是否到达、是几字节的帧。

### 3.6 测量算法与数据管理

算法层与主控无关，UNO 端跑的就是 AFE4490_library 自带的算法（`ppg_filter / pulse_rate / spo2`），STM32 端只消费结果。流程如下：

**（1）滤波：去 DC、留 AC**

```
dc += (raw - dc) >> 5      // 指数基线跟踪，等效一阶低通 → 得 DC 基线
ac  = raw - dc             // AC = 原始值 - 基线
ac  = 8 点滑动平均(ac)      // 平滑
```

- **DC** 用于手指检测与灌注指数；
- **AC** 就是脉搏波，供 PR 峰值检测与 SpO₂ 计算。

**（2）手指检测与状态机**

| 状态 | 判定 / 迁移 |
|---|---|
| ST_BOOT | 上电自检 → ST_WAIT_FINGER |
| ST_WAIT_FINGER | IR 直流连续 50 点 > `FINGER_DC_THRESHOLD`(5000) → ST_ACQUIRE |
| ST_ACQUIRE | 收满 2000 点（≈4 s 窗口）→ ST_CALCULATE；手指移除 → 回 ST_WAIT_FINGER |
| ST_CALCULATE | 算 PR + SpO₂ → 回 ST_ACQUIRE 继续滚动窗口 |

**关键行为**：手指一拔，DC 立刻掉下去 → `Measurement_Reset()` + 重新开窗 → **绝不会继续显示上一次的血氧值**。这对应需求 R7。

**（3）脉率 PR：峰值包络 + 中值滤波**

- 峰值包络"快升慢降"；阈值 = 包络 / 2，且包络必须大于 `PR_MIN_AMPLITUDE`（50）才认；
- 逐峰间隔做**中值滤波**（`PR_MEDIAN_LEN=4`）去野点，再平均得到 bpm。

**（4）血氧 SpO₂：R 值法**

经典双波长经验公式：

```
R = (AC_red / DC_red) / (AC_ir / DC_ir)        // 要求 R ∈ [0.3, 3.0]，否则判无效
SpO₂ = f(R)                                     // 库内置经验曲线
```

窗口内（`ALGO_WINDOW_SEC = 4`）累加 `AC²` 与 `DC`，用 RMS 作为 AC 分量。

**（5）信号质量与探头状态**

```
灌注指数 PI% = AC_pp / DC × 100          （RMS × 2.828 近似峰峰值）
信号质量 q   = PI × 30，封顶 100
探头状态     = spo2 == 0 ? "未接入" : "已接入"    （STM32 端判据，对应 R7）
```

### 3.7 应用层节拍与"控件归属"约定

**★ 本项目最重要的一条软件约定：屏上每个控件只能有一个写者。**

| 归属 | 控件 | 说明 |
|---|---|---|
| MCU 独占写 | 主界面 10~17/19/20/21/91、按钮 1 与 6 的显隐 | 数值、状态、波形、监护时间、探头 |
| MCU 独占写 | 趋势 12/14/13/10/11/15~18 + 按钮 1/2/3 选中态 | 历史曲线、时段、最近值、时间刻度 |
| MCU 独占写 | 报警记录 20~35 + 10/11；设置页 1/2/10/11/12/13 | 记录、阈值、亮度、声音 |
| MCU 独占写 | 屏 RTC（`EE 81`） | 控件 92 是 `rtc` 类型，写文本无效 |
| 屏原生 | 画面跳转 | 仅限 `button_type=0` 的按钮（switch=目标页） |
| **已停用** | 屏端 `main.lua` | 已换成空壳脚本（原版备份保留） |

配套的**健壮性机制**：MCU 每 3 秒把"自己负责的文案"整轮重写一遍（自愈补发），不依赖任何屏通知——即使屏发生重绘把 MCU 写的内容冲掉，3 秒内自动收敛回来。

**按钮配置约定**（从 VisualTFT 内部 schema 与官方例程核对得出）：

```
button_type  0=切换画面(屏自己跳页，但不可靠上报事件) / 1=开关描述(只上报、不跳页) ←要 MCU 干活的都用它
button_style 0=瞬变(点动) / 1=开关(切换型)
notify_disable 必须 = 0（否则不上报按键事件）
```

**（报警与软 RTC）**

- **报警**（移植自血压工程）：越限**持续 3000 ms** 才记一条（防抖动）；滞回解除（SpO₂ 回升 ≥92 才解除"偏低"、PR 回落 ≤115 才解除"偏快"）；新记录插最前，最多 4 条；SpO₂ 越限记"高级"、PR 越限记"中级"；写入报警记录页 + 蜂鸣 200 ms（声音开关打开时）。
- **软 RTC**：MCU 自维护年/月/日 + 当日秒数（含闰年），`task_clock()` 用 `millis()` 整秒推进，**保留不足 1 秒的余数**防累计误差；每 5 分钟 `EE 81` 同步到屏；星期用 Zeller 公式计算（0=周日）；起始日期改 `app_bloodoxygen.c` 顶部 `RTC_INIT_YEAR/MON/DAY`。

### 3.8 关于 SPI 与器件地址

本项目血氧采集链路**未使用 IIC / I²C 总线**：AFE4490 只提供 SPI 接口，STM32 与屏均走 UART。因此不存在 I²C 器件地址配置。

AFE4490 的"寄存器寻址"通过 SPI 地址字节完成：地址字节的 bit7 为 `SPI_READ` 位，写寄存器发 `addr`，读寄存器发 `addr | 0x80`。结果与多数 I²C 器件类似，仍是一组按地址排布的寄存器（0x00~0x3F 控制/时序，0x2A~0x2F 结果），区别仅在传输通道（SPI 32 bit 帧而非 I²C 起始/停止条件）。板载虽保留 SPI1 引脚（PB3/4/5 等），但当前采用 UNO 中转方案，SPI 全部由 UNO 端占用，STM32 侧完全不碰，故与 USART2/3 等资源无冲突。

### 4.2 遇到的典型问题

**问题一：暂停后按钮文字不变，监护时间永远停在 `00:00:01`** ⭐ 影响最大

- **现象**：点"暂停监护"→确认，屏上文案没变；监护时间变成 `00:00:01` 后再也不走。
- **排查**：先怀疑 MCU 没写、再怀疑屏没收到——都不是。最后读屏工程自带的 `main.lua`，发现它自己也维护一份 `paused` / `monitor_sec`：`start_timer(0, 1000, 0, 1)` 的第 4 参 `repeat=1` 是**重复次数**（0 才是无限），只触发一次，所以 `monitor_sec` 加到 1 就停；而每次切回主界面 `on_screen_change → refresh_main()` 都会用 **Lua 自己的 `paused=false`** 把 MCU 刚写进去的"已暂停"覆盖回"测量有效"。
- **根因**：屏端 `main.lua` 会执行并与 MCU **双写**同一批控件。曾一度误判"Lua 不执行"（把"上位机没预编译"当成"屏上不执行"），实际每次编译都会把工程根 `main.lua` 原样拷进 `dciot_build\private\main.lua`（md5 相同），`LUAPrecompile="0"` 只是"不在上位机预编译"，**不代表屏上不执行**。
- **修复**：**停用 `main.lua`（换空壳脚本，原版备份）+ MCU 独占写全部动态内容** + 加 3 秒自愈补发兜底。
- **经验**：**一台设备上同一批控件只能有一个写者**。两边都写，任何单侧调整都治不好。

**问题二：趋势曲线永远是一条死直线** ⭐ 最隐蔽

- **现象**：趋势页两条历史曲线是水平直线，不是测量数据。
- **根因**：屏控件属性 `sample_data_foramt="0"` = **UINT8（每点 1 字节）**，而 MCU 用 `HMI_HistorySampleU16()` 发 **2 字节/点**。屏按 1 字节解析，只吃掉高字节——SpO₂=97 即 `0x0061`，屏只取 `0x00` ⇒ 曲线恒为 0，贴着量程下限画成直线；剩下的 `0x61` 不是帧头 `EE`，被当噪声丢掉。
- **修复**：把屏属性改成 `2`（UINT16），与 MCU 对齐。
- **经验**：**"每个采样点占几个字节"由屏控件属性决定，MCU 发的字节数必须与之匹配**。不匹配时屏不会报错，只是数据整体错位，极难从现象反推。

**问题三：切页后 MCU 写的内容全被冲掉**

- **现象**：切到某个画面，MCU 该写的东西没显示。
- **根因**：屏**每次跳转都会按控件默认属性重绘**，把 MCU 之前写的内容清掉。
- **修复**：`NotifyScreen()` 里安排"切页后补发 4 轮"（约 +120/420/720/1020 ms 各一轮），错开屏重绘时序；再加 3 秒周期自愈。

**问题四：`NotifyScreen()` 从未被调用**

- **现象**：切页回调一次都没进过。
- **根因**：`HMI_Poll()` 的帧长门限写成了 11 字节，而"画面切换通知"只有 **9 字节**——整条被当噪声丢掉。**不报任何错误**。
- **修复**：门限 11 → 9。
- **经验**：帧长门限别写"看起来够大"的值，要先列出所有上行帧的长度。

**问题五：设置页"声音提示"点一次等于没反应**

- **现象**：点声音开关，状态不翻转。
- **根因**：`DeviceControlNotify="3"` = **按下和弹起都上报**，一次点击收到两帧；原代码把边沿判断放在函数中段，两次都执行了翻转 → 净变化为 0。
- **修复**：把 `if (!state) return;` 提到 `NotifyButton()` **第一行**，只处理按下沿。

**问题六：两个"确认"键只跳页、不上报事件**

- **现象**：屏跳到了弹窗的目标页，但 MCU 不知道用户点了确认，无法执行"暂停/清空"逻辑。
- **根因**：按钮配成了 `button_type=0`（切换画面）+ `switch=目标页`，这种配置下屏自己跳页，**不会可靠上报按键事件**。
- **修复**：确认类按钮改成 `button_type=1 + switch=""`（只上报），跳页由 MCU 收到通知后发 `EE B1 00`；取消/返回键保留 `button_type=0` 原生跳页，作为"卡在弹窗页"的兜底出口。

**问题七：屏不认"批量更新"链路**

- **现象**：控件永远显示 `--`，指令发了很多却没有一条生效。
- **根因**：官方样例用的"批量更新（B1 12）+ 刷屏开关（B3）"链路，这块屏**静默丢弃**。
- **修复**：改用**单条指令** `EE B1 10 <screen> <ctrl> <数据>` 逐个写。

**问题八：工具链的坑（AC5 + 中文 + 多编码）**

- **现象**：包含 UTF-8 中文字符串的源文件在 Keil AC5 下产生大量 `unrecognized token` 与 `missing closing quote` 错误。
- **根因**：AC5 编译器对 UTF-8 编码的窄字符串字面量支持不完善；且屏工程内**三种编码混用**（屏字库 GBK、`.tft` 文件 UTF-8、`main.lua` GBK+CRLF），批处理脚本若不加区分会直接崩溃。
- **修复**：所有面向屏显示的中文字符串一律改为 **GBK 的 `\xNN` 十六进制转义**，源文件保持纯 ASCII；宏结尾绝不紧跟十六进制数字（AC5 的 `\x` 转义会"贪心多吃一位"）；Python 脚本显式指定编码读写。

### 4.3 项目难点分析

1. **跨三个电压域的接口设计**：盾板 5 V ↔ UNO 5 V（天然匹配）、UNO 5 V ↔ STM32 3.3 V（靠 FT 脚 + 对端 V_IH 阈值省掉电平转换）、STM32 TTL ↔ 屏 RS232（SP3232）。每一根线都要查数据手册的引脚类型表，**不能凭"5 V 接 3.3 V 一定烧"的直觉**——实际上 PB4/PA0/PC7 都是 FT 脚，可以直接吃 5 V。

2. **多主冲突的架构性规避**：屏端 Lua 与 MCU 双写同一批控件，问题表现"五花八门"（按钮文字不变、时间停走、切页被重置），根因却只有一个。**用"控件归属表 + 单一写者 + 自愈补发"三件套从架构上根治**，而不是逐个现象打补丁。

3. **一条 115200 串口上的多节拍带宽预算**：波形（90 Hz、每帧 16 点合并发送）、数值（400 ms × 6 条指令）、趋势（2 s × 2 点）、RTC（5 min 一条）叠加起来必须远低于串口容量。做法：波形攒 16 点发一帧、文本只在变化时发（如"监护时间"只在整秒变化才发）、时间刻度只在分钟变化时重写。

4. **隐蔽的"静默失败"**：本项目三次踩到"不报错、就是不工作"——帧长门限 11 丢掉 9 字节帧、批量更新链路被静默丢弃、历史曲线字节宽度不匹配。三者最后都靠**对比官方驱动源码 + 逐字节核对协议**解决。

5. **调试手段前置设计**：`DEMO_STEP` 把系统拆成 4 步独立验证；串口中断"先记账再判状态"+ 最近 32 字节环形缓冲，让"链路不通"和"解析错误"能分开定位；USART1 心跳里带 `hmi_rx=` / `uno_rx=` 计数，点一次按钮看计数跳增多少字节，就能判断通知有没有到、是几字节的帧。

### 4.4 已知限制与后续改进方向

**当前限制**

| 项目 | 现状 | 影响 |
|------|------|------|
| 时间保持 | 软件 RTC，掉电后从默认时刻重启 | 需每次上电手动校准 |
| 趋势/报警存储 | 存于屏 RAM 与 MCU RAM，复位即清空 | 无法跨会话追溯 |
| 探头检测 | 仅判 `spo2==0`，无更细的脱落/弱信号分级 | 弱信号时仍显示数值 |
| 波形显示 | PPG 实时波形与历史趋势已接入 | 历史波形回放未做 |
| 集成度 | 多一块 UNO 中转、多一路串口 | 功耗与体积偏大 |
| 版本管理 | 本地文件，无 VCS | 不利于多人协作与回溯 |

**改进方向**

1. 启用 STM32 内置 RTC（外接 32.768 kHz 晶振 + 备份电池），实现掉电走时。
2. 将趋势与报警记录迁移至内部 Flash / 板载 EEPROM，实现持久化存储。
3. 按方案一引脚表把 AFE4490 直连 STM32（需 2 片 SN74AHCT125 + 移植驱动），去掉 UNO 提高集成度。
4. 在结果结构里补 `uint16_t algo_version` 随结果上报，便于云端区分数值变化来自病人还是算法换版。
5. 血氧/血压结果走 CAN 上报主节点（血压工程已有 CAN 框架可复用）。
6. 引入版本管理（Git），并对协议层与算法层补充单元测试。

---

## 5 总结

本项目以 STM32F407 为核心，借助 Arduino UNO 中转完成 AFE4490 驱动与 SpO₂/PR 解算，实现了血氧监测模块从光电采集、协议解析、状态管理到人机交互的完整闭环。工程通过 Keil AC5 编译零错误零警告，固件规模约 11.7 KB，具备以下特点：

- **架构分层清晰**：传感器、屏、应用三层均为纯 C 实现，互不依赖 MCU SDK，可跨平台复用；
- **资源隔离彻底**：与血压模块共用主控板与串口屏，但引脚与串口显式隔离、零冲突；
- **交互模型健壮**：以"控件归属表 + 单一写者 + 自愈补发"根治组态屏双写冲突，关键流程均设超时与补发兜底；
- **调试手段前置**：分步验证宏、计数型心跳、环形缓冲抓包，使"链路不通"与"解析错误"可分离定位。

项目过程中积累的经验——**跨电压域接线先查引脚类型表而非凭直觉**、**一台设备同一批控件只能有一个写者**、**警惕组态屏的静默失败与隐式行为约定**、**为每个状态转移设计超时兜底**——对后续同类嵌入式开发具有直接的参考价值。
