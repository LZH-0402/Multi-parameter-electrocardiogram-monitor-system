## 一、结论先说：根因是屏端 main.lua 与 MCU 在抢着写同一批控件

你报的两个现象，**不是两个 bug，而是同一个根因**：

> 屏工程自带的 `main.lua` **是会执行的**，
> 它和 MCU 各自维护了一份"暂停状态 / 监护时长"，互不同步，
> 于是双方不停地把对方写的文字覆盖掉。

| 你看到的现象 | `main.lua` 里对应的代码 | 为什么是这个结果 |
|---|---|---|
| 监护时间永远 `00:00:01` | `on_init()` 里 `start_timer(0,1000,0,1)`；`on_timer()` 里 `monitor_sec = monitor_sec + 1` 并写控件 21 | 官方 API 的 `repeat` 是**重复次数、0 才无限**，传 1 **只触发一次** → `monitor_sec` 永远停在 1；而每次进主界面 `on_screen_change → refresh_main()` 都会把 `"监护时间 "..fmt_hms(1)` 写进去 = **监护时间 00:00:01** |
| 暂停后按钮文案不变（还是"测量有效 / 脉搏波采集中"） | `refresh_main()` 用 **Lua 自己的 `paused`** 决定写什么 | MCU 写的是"已暂停 / 暂停中"，但 Lua 的 `paused` 没被同步，它每次切页都写回"测量有效 / 脉搏波采集中"，**把 MCU 的写入冲掉** |

### 为什么上一轮我判断错了

上一轮的证据是"`luac.exe` 不存在 + 编译产物里搜不到 Lua 痕迹 ⇒ Lua 不执行"。**这条推理是错的**，错在把"上位机没预编译"当成了"屏上不执行"。正确证据链：

1. 每次编译都会把工程根目录的 `main.lua` **原样拷进** `dciot_build\private\main.lua`
   —— 两者 md5 完全相同（`3ad194f6ef22bb6adee423a380ebfb6a`），说明脚本是**随工程下发到屏上**的。
2. `SPO2_Hospital.tftprj` 里 `LUAPrecompile="0"`，而这个字段在 `VisualTFT.exe` 内部 schema 里的
   中文名正是 **"预编译LUA"**（`CTYPE="CHECKBOX"`）—— 0 = **不在上位机预编译**，
   由屏上电后自行解释 `main.lua`。所以"产物里没有 Lua 二进制"本来就是正常的，不是证据。
3. 现象与 `main.lua` 源码**逐条对得上**（见上表），尤其是 `00:00:01` 这个非常规整的数字。

### 顺带查出并修掉的三个连带问题

4. **`NotifyScreen()` 从来没被调用过**（"切页后补发文案"机制形同虚设）
   `dc_hmi.c` 的 `HMI_Poll()` 里帧长门限写的是 `>= 11` 字节，而"画面切换通知"帧
   `EE B1 01 <screen:16> FF FC FF FF` 只有 **9 字节**，被整条丢掉。已改为 `>= 9`。
5. **设置页"声音提示"按一次翻转两次（等于没反应）**
   `tftprj` 里 `DeviceControlNotify="3"` = "按下和弹起都上报"，一次点击会收到**两帧**。
   原代码的边沿判断写在函数中段，导致翻转型动作被执行两次。已把 `if (!state) return;`
   提到函数第一行。
6. **两个"确认"键配成了"切换画面"型按钮**
   依据 VisualTFT 内 `button_type` 枚举：`0=切换画面 / 1=开关描述(只上报)`。
   官方例程里凡是要上报事件的按钮一律是 `button_type=1 + button_style=0 + switch=""`。
   原"确认"键是 `button_type=0` + `switch="主界面"`，**只跳页、不上报**，
   MCU 收不到通知自然翻不动状态。已改成只上报、由 MCU 发 `EE B1 00` 跳页。

## 五、如果还有问题，用这一条诊断

MCU 的 USART1 调试口每秒会打印一行，例如：

```
tick 42 | hmi_rx=1863 | uno_rx=45210 frames=2510 | spo2=98 pr=72 ir=18321 | paused=0
```

**看 `hmi_rx` 这个数**（屏 → MCU 的上行字节总数）：

| 现象 | 含义 | 下一步 |
|---|---|---|
| 点按钮时 `hmi_rx` **跳增 14 左右** | 按键通知正常到达 | 那就纯是文案刷新时序问题，把现象告诉我 |
| 点按钮时 `hmi_rx` **完全不变** | 屏没上报按键事件 | 查 `tftprj` 的"按钮事件通知"（`DeviceControlNotify`）是否为 `3`，以及该按钮的"事件通知"属性是否为"是"（对应 `notify_disable="0"`） |
| 切页时 `hmi_rx` **完全不增** | 屏没上报画面切换 | 查 `DeviceScreenNotify` 是否为 `1`；同时确认新屏固件已下载 |
| `hmi_rx` **一直是 0** | 屏 → MCU 这条线根本没通 | 查 PA3(RX) 接线与共地（注意 TX/RX 是否交叉），波特率是否为 115200 |

告诉我 `tick` 行的实际内容 + 你点的按钮，我就能继续定位。
