# 血氧模块 · 代码开发设计步骤

> 目标：用 **STM32F407ZGT6（标准库 SPL，非 HAL）** 完成"真实血氧测量 → 大彩串口屏显示"的闭环。
> 架构采用 **方案二（Arduino UNO 中转）**：AFE4490 由 UNO 读取并算出 SpO₂/PR，再通过串口把数据交给 STM32，STM32 只负责"收数 + 驱动屏幕"。
> 约束（来自你的要求）：
> - STM32 用 **标准外设库 SPL**；
> - 血压 / 血氧是 **两个独立工程**，代码分开写；
> - 屏幕统一走 **USART2**（与血压工程一致）。

参考工程：

- UNO 测血氧 / 波形示例：`F:\...\血氧\AFE4490_library\`（`examples/Example-1-*` 二进制帧、`examples/Example-2-*` 算 SpO₂）

## 0. 前提结论（务必先读）

1. **UNO ↔ STM32 之间不需要任何电平转换芯片。**
   - UNO 是 5V 逻辑；AFE4490 盾板是 5V 盾板（VCC 接 UNO +5V）。
   - UNO `TX`（5V）→ STM32 `PC7`（USART6_RX，**FT 脚，耐 5V**）✓
   - STM32 `TX`（3.3V）→ UNO `RX`，ATmega328P 的输入高电平阈值 V_IH≈0.6×5V≈3.0V，3.3V 能被可靠读为高 ✓
   - 共地即可。
2. **STM32 不直接读 AFE4490**（SPI 全部由 UNO 完成）。STM32 只解析 UNO 发来的串口帧，因此 PB3/4/5、PA4、PA0 等 AFE-SPI 引脚在 STM32 侧根本不出现，**与血压工程零引脚冲突**。
3. 屏幕 `DC80480DN050` 出厂默认 **RS232 电平**：要么经 **SP3232 转 RS232** 再接屏（推荐，与血压一致），要么在屏上 **短接 J5 切 TTL** 后直连 3.3V TTL。屏工程波特率已设为 **115200**（DeviceBaudRate=7），STM32 USART2 必须配 115200/8N1，否则收不到按键通知、显示异常。

## 1. 总体架构与数据流

```
        SPI(2MHz,MODE0)               UART(115200,无电平转换)          UART(115200)
  ┌──────────┐                ┌────────────┐                  ┌──────────────┐        ┌────────┐
  │ AFE4490  │  SCK/MOSI/MISO │   Arduino   │  D1(TX,5V)      │  STM32F407   │ PA2/PA3 │ 大彩   │
  │ 盾板     │◄───CS/D2/...──►│    UNO      │─────────────────►│  (SPL)       │────────►│ 串口屏 │
  │(手指探头)│                │ 算SpO₂/PR  │  PC7(RX,FT)      │ 解析+显示    │        │USART2 │
  └──────────┘                └────────────┘                  └──────────────┘        └────────┘
                                       ▲                             │
                                       └──── PC6(TX,3.3V)→D0(RX) ────┘ (当前不发命令,留作扩展)
```

- **UNO 职责**：读 AFE4490（AFE4490_library）→ 每 8ms 出一帧 → 串口发出 `IR / RED / SpO₂ / PR`。
- **STM32 职责**：USART6 收帧解析 → 维护 `measurement_t` → 用移植后的 `dc_hmi` 把数值/波形/趋势写屏；USART2 同时接收屏的按键上行通知。
- **关键节拍**：UNO 约 125Hz 发帧 → STM32 每帧推一个波形点（与屏 PPG 曲线 125Hz 采样匹配）；数值 400ms 刷新一次；趋势 **2s 追加一点**（2026-10-10 由 60s 改）。

## 2. 硬件接线（最终版）

### 2.1 AFE4490 盾板 ↔ Arduino UNO（官方 ProtoCentral 引脚，5V 盾板）

| AFE4490 盾板 | Arduino UNO | 功能 |
|---|---|---|
| GND | GND | 地 |
| VCC | +5V | 供电（盾板吃 5V） |
| DRDY | D2 | 数据就绪（示例里未真正挂中断，轮询即可） |
| MISO | D12 | SPI 从出 |
| SCK | D13 | SPI 时钟 |
| MOSI | D11 | SPI 从入 |
| CS0 | D7 | 片选（示例 CS=7） |
| START | D5 | 转换启动 |
| PWDN | D4 | 掉电/复位（示例 PWDN=4） |
| DIAG_END / LED_ALM / PD_ALM | NC | 悬空 |

> 示例里 `#define AFE44XX_CS_PIN 7 / AFE44XX_PWDN_PIN 4 / AFE44XX_INTNUM 0`，与上面一致，`INTNUM=0` 即 D2。

### 2.2 UNO ↔ STM32F407（串口，**无电平转换**）

| 方向 | UNO | STM32F407 | 电平说明 |
|---|---|---|---|
| UNO→STM32（收，必需） | D1 (TX, 5V) | **PC7 (USART6_RX, FT)** | PC7 是 FT 脚，直接耐 5V ✓ |
| STM32→UNO（发，暂不用） | D0 (RX) | **PC6 (USART6_TX, 3.3V)** | UNO V_IH≈3.0V，3.3V 可读 ✓ |
| 地 | GND | GND | 共地 |

> 先保留 PC6→D0 的接线，未来可发"启停测量/切换模式"等命令；当前固件 STM32 不向 UNO 发数据。

### 2.3 STM32 ↔ 大彩屏（USART2，与血压一致）

| 方向 | STM32F407 | 大彩屏 | 电平处理 |
|---|---|---|---|
| STM32→屏 | PA2 (USART2_TX) | 屏 RX | 见下 |
| 屏→STM32 | PA3 (USART2_RX) | 屏 TX | 见下 |

- **方案①（推荐，与血压工程统一）**：PA2/PA3 经 **SP3232** 转 RS232 再接屏。抗干扰好，长距离稳。
- **方案②（省芯片）**：屏上 **短接 J5** 把屏切为 TTL，PA2/PA3 直接 3.3V TTL 接屏 RX/TX。
- 波特率 **115200 / 8 / N / 1**；屏工程已设 DeviceBaudRate=7。
- ⚠️ 真屏提醒：出厂是 RS232，**用 TTL 必须短 J5**，否则既收不到按键通知也发不出显示。

### 2.4 引脚分配 & 与血压工程的对照（证明独立、无冲突）

| 工程 | 功能 | 引脚 |
|---|---|---|
| 血氧（本工程） | 屏 USART2 | PA2 / PA3 |
| 血氧（本工程） | UNO 串口 USART6 | PC6 / PC7 |
| 血氧（本工程，可选调试） | 调试 printf USART1 | PA9 / PA10 |
| 血压（另一工程） | 调试 USART1 | PA9 / PA10 |
| 血压（另一工程） | 屏 USART2 | PA2 / PA3 |
| 血压（另一工程） | 传感器 USART3 | PB10 / PB11 |

**结论**：两个工程各自独立编译、各自烧录到各自板子（或同一板子不同时刻烧不同固件）。AFE 的 SPI 引脚只在 UNO 侧出现，STM32 侧完全不碰，零冲突。两者"概念上"都把屏挂在 USART2，是因为屏协议一致、便于复用 `hmi_ids.h` 与 `dc_hmi` 代码，但硬件上各接各的屏。

## 3. Arduino UNO 固件设计（基于 AFE4490_library 示例）

### 3.1 库的真实行为（已读 `src/S_afe44xx.cpp`）

- `get_AFE44XX_Data()` 每次调用读 `LED1VAL`(IR) 与 `LED2VAL`(RED)。
- 内部 `dec` 计数器：每 **20 次调用**才存 1 个样本进 100 长缓冲（即下采样 20×）。缓冲满 100 后调用 `Spo2.estimate_spo2()` 算出 `spo2`，并置 `buffer_count_overflow=true`。
  - 原始节奏：loop `delay(8)` → 125Hz；存样本 = 125/20 ≈ 6.25Hz；100 样本 ≈ **16 秒**才更新一次 SpO₂（太慢）。
  - **建议修改**：把 `dec==20` 的条件去掉（或改成每 1~2 次调用存 1 个），让 SpO₂ 约 **1 秒**更新一次。改动只在 `S_afe44xx.cpp` 的 `get_AFE44XX_Data()` 里，库其它不动。
- `heart_rate`：**每次调用**都更新（内部 `statHRMAlgo` 连续跑），所以 PR 是连续可用的。
- `spo2 == -999` 表示 **探头错误 / 信号差**（Probe error）。

### 3.2 串口帧格式（直接沿用 Example-1，兼容 `afe_bridge.py`）

> ⚠️ **波特率勘误（重要）**：AFE4490_library 原始 **Example-1 用的是 `Serial.begin(57600)`**（见该 .ino 第 42 行），**不是 115200**。
> - Example-1 = **57600**，发 17 字节二进制帧 ← 本工程要用的那个；
> - Example-2 = 115200，但只打 ASCII 文本（`Sp02 : 98% ...`）；
> - Example-3 = 57600，只打 ASCII 文本（仅 RED 值）。
>
> 若 UNO 烧的是**未改动的 Example-1**，则 STM32 USART6 必须配 **57600**。本工程固件现已内置
> **USART6 波特率自动探测**（依次试 57600 / 115200 / 9600，取解析出有效帧最多的那个），
> 因此 UNO 侧改不改 `Serial.begin` 都能跑；但**首选让 STM32 去适配 UNO**，少动一端。

我们**不改 Example-1 的二进制帧**，并明确解析契约：

```
帧长 17 字节：
  [0] 0x0A          同步1
  [1] 0xFA          同步2
  [2] 0x0A          数据长度低 (DATA_LEN=10)
  [3] 0x00          数据长度高
  [4] 0x02          类型 = DATA
  [5..8]  IR_data   int32 小端 (来自 LED1VAL)
  [9..12] RED_data  int32 小端 (来自 LED2VAL)
  [13]   spo2       uint8  (0~100；未算出或探头错误时为 0)
  [14]   hr         uint8  (bpm；0 表示无效)
  [15] 0x00         保留
  [16] 0x0B         帧尾
```

- 每帧都带最新 `IR/RED`（125Hz 用于波形）；`spo2/hr` 仅在 `buffer_count_overflow` 被置位后才被刷新（约每 1s 一次，取决于 3.1 的改动），其余时间保持上次值。
- `spo2==0` 在 STM32 端即视为"无效/探头错误"，用于驱动屏上的 `--` 与探头状态页。
- 该帧无 CRC；同步靠"5 字节头 + 帧尾 00 0B 双重校验"，足够本场景使用（详见 4.5）。

### 3.3 UNO 主循环（改自 `Example-1-Raw-PPG-plot-openview.ino`）

```cpp
#include <SPI.h>
#include "S_afe44xx.h"

#define AFE44XX_CS_PIN   7
#define AFE44XX_PWDN_PIN 4

AFE44XX afe44xx(AFE44XX_CS_PIN, AFE44XX_PWDN_PIN);
afe44xx_data afe44xx_raw_data;

// 直接复用 Example-1 的帧定义
#define CES_CMDIF_PKT_START_1 0x0A
#define CES_CMDIF_PKT_START_2 0xFA
#define CES_CMDIF_TYPE_DATA   0x02
#define CES_CMDIF_PKT_STOP    0x0B
const uint8_t HDR[5] = {CES_CMDIF_PKT_START_1, CES_CMDIF_PKT_START_2,
                         0x0A, 0x00, CES_CMDIF_TYPE_DATA};
uint8_t DataPacket[10];

void setup() {
  Serial.begin(115200);          // 统一 115200，与 STM32 USART6 一致
  SPI.begin();
  afe44xx.afe44xx_init();
}

void loop() {
  delay(8);                      // ~125Hz
  afe44xx.get_AFE44XX_Data(&afe44xx_raw_data);

  memcpy(&DataPacket[0], &afe44xx_raw_data.IR_data, 4);   // int32 LE
  memcpy(&DataPacket[4], &afe44xx_raw_data.RED_data, 4);

  if (afe44xx_raw_data.buffer_count_overflow) {
    if (afe44xx_raw_data.spo2 == -999) { DataPacket[8] = 0; DataPacket[9] = 0; } // 探头错误
    else { DataPacket[8] = (uint8_t)afe44xx_raw_data.spo2;
           DataPacket[9] = (uint8_t)afe44xx_raw_data.heart_rate; }
    afe44xx_raw_data.buffer_count_overflow = false;
  }

  Serial.write(HDR, 5);
  Serial.write(DataPacket, 10);
  Serial.write((uint8_t)0x00); Serial.write(CES_CMDIF_PKT_STOP);  // 00 0B
}
```

> 调试期：把上面 `Serial.begin` 换成 `57600` 也可，但要和 STM32 USART6 波特率保持一致。也可临时 `Serial.print("Sp02 : ")`（Example-2 风格）用电脑串口监视器肉眼验证算法。

### 4.2 时钟 + SysTick（替代 HAL_GetTick）

- 系统时钟 168MHz（HSE 8M → PLL，标准库 `SystemInit`/PLL 配置保持模板原样）。
- 在 `stm32f4xx_it.c` 里用 SysTick 提供毫秒计时，替代 HAL 的 `HAL_GetTick()`：

```c
volatile uint32_t uwTick = 0;
void SysTick_Handler(void) { uwTick++; }
uint32_t millis(void) { return uwTick; }
// 初始化：SysTick_Config(SystemCoreClock / 1000);
```

应用层所有 `HAL_GetTick()` 全部替换成 `millis()`。

### 4.3 USART2 驱动（屏，SPL）—— 替换 `dc_hmi.c` 里的 HAL

```c
// usart.c（节选）
void USART2_Screen_Init(uint32_t baud)
{
  GPIO_InitTypeDef  g; USART_InitTypeDef u; NVIC_InitTypeDef n;
  RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOA, ENABLE);
  RCC_APB1PeriphClockCmd(RCC_APB1Periph_USART2, ENABLE);   // USART2 在 APB1

  GPIO_PinAFConfig(GPIOA, GPIO_PinSource2, GPIO_AF_USART2); // PA2 TX
  GPIO_PinAFConfig(GPIOA, GPIO_PinSource3, GPIO_AF_USART2); // PA3 RX
  g.GPIO_Pin = GPIO_Pin_2 | GPIO_Pin_3;
  g.GPIO_Mode = GPIO_Mode_AF; g.GPIO_Speed = GPIO_Speed_50MHz;
  g.GPIO_OType = GPIO_OType_PP; g.GPIO_PuPd = GPIO_PuPd_UP;
  GPIO_Init(GPIOA, &g);

  u.USART_BaudRate = baud; u.USART_WordLength = USART_WordLength_8b;
  u.USART_StopBits = USART_StopBits_1; u.USART_Parity = USART_Parity_No;
  u.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
  u.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
  USART_Init(USART2, &u);
  USART_Cmd(USART2, ENABLE);

  USART_ITConfig(USART2, USART_IT_RXNE, ENABLE);   // 收屏的上行通知
  n.NVIC_IRQChannel = USART2_IRQn; n.NVIC_IRQChannelPreemptionPriority = 1;
  n.NVIC_IRQChannelSubPriority = 1; n.NVIC_IRQChannelCmd = ENABLE;
  NVIC_Init(&n);
}

// 屏驱动调用：把一帧发给屏（轮询版，简单可靠；要提速可改 DMA）
void hmi_tx(const uint8_t *p, uint16_t n)
{
  uint16_t i;
  for (i = 0; i < n; i++) {
    USART_SendData(USART2, p[i]);
    while (USART_GetFlagStatus(USART2, USART_FLAG_TXE) == RESET);
  }
}

// 中断：把屏来的字节交给 dc_hmi 的帧收集
void USART2_IRQHandler(void)
{
  if (USART_GetITStatus(USART2, USART_IT_RXNE) != RESET) {
    uint8_t b = USART_ReceiveData(USART2);
    HMI_RxByte(b);                 // dc_hmi.c 提供
    USART_ClearITPendingBit(USART2, USART_IT_RXNE);
  }
}
```


**帧解析状态机**（放在 `app_bloodoxygen.c` 或独立 `uno_parser.c`）：同步靠"5 字节头 + 帧尾 00 0B"，即使 IR/RED 里出现 0x0A 也不会误同步，因为头是 5 字节固定序列，且末尾再校验 00 0B。

```c
typedef enum { S0_SYNC1, S1_SYNC2, S2_LENL, S3_LENH, S4_TYPE,
               S5_PAYLOAD, S6_FOOT1, S7_FOOT2 } ps_t;
static ps_t st = S0_SYNC1;
static uint8_t pl[10]; static uint8_t pl_i; static uint8_t foot1;

extern measurement_t g_meas;
extern uint8_t g_new_frame;          // 主循环用来知道"有新风"

static int32_t rd_i32LE(const uint8_t *p){
  return (int32_t)((uint32_t)p[0] | ((uint32_t)p[1]<<8) |
                   ((uint32_t)p[2]<<16) | ((uint32_t)p[3]<<24));
}

void UNO_ParseByte(uint8_t b)
{
  switch (st) {
    case S0_SYNC1: if (b==0x0A) st=S1_SYNC2; break;
    case S1_SYNC2: st = (b==0xFA) ? S2_LENL : S0_SYNC1; break;
    case S2_LENL:  st = (b==0x0A) ? S3_LENH : S0_SYNC1; break;  // LEN_L=10
    case S3_LENH:  st = (b==0x00) ? S4_TYPE : S0_SYNC1; break;
    case S4_TYPE:  st = (b==0x02) ? S5_PAYLOAD : S0_SYNC1; pl_i=0; break;
    case S5_PAYLOAD:
      pl[pl_i++] = b;
      if (pl_i >= 10) st = S6_FOOT1;
      break;
    case S6_FOOT1: foot1 = b; st = S7_FOOT2; break;
    case S7_FOOT2:
      if (foot1==0x00 && b==0x0B) {        // 00 0B 校验通过
        g_meas.ir_raw  = rd_i32LE(&pl[0]);
        g_meas.red_raw = rd_i32LE(&pl[4]);
        g_meas.spo2        = (int16_t)pl[8];   // 0 表示无效/探头错误
        g_meas.pulse_rate  = (int16_t)pl[9];
        g_meas.result_valid = (pl[8] != 0) ? 1 : 0;
        g_meas.probe_state  = (pl[8] != 0) ? 1 : 0;   // 0=未接入/错误
        g_meas.signal_quality = (pl[8] != 0) ? 100 : 0; // 见 8.1 可优化
        g_new_frame = 1;
      }
      st = S0_SYNC1;
      break;
  }
}

void USART6_IRQHandler(void)
{
  if (USART_GetITStatus(USART6, USART_IT_RXNE) != RESET) {
    UNO_ParseByte((uint8_t)USART_ReceiveData(USART6));
    USART_ClearITPendingBit(USART6, USART_IT_RXNE);
  }
}
```

> 1. 每次编译都会把工程根目录的 `main.lua` **原样拷进** `dciot_build\private\main.lua`

官方例程的写法可以直接对照：`Project_DEMO_800480M070\时间.tft` 的 `Button2(id=8)` 就是
`button_type=1 + button_style=0 + switch=""`，官方 `NotifyButton()` 里用
`if(screen_id==8 && control_id==8 && state==1) ReadRTC();` 处理它。


**软 RTC（与血压工程同源做法）**：MCU 自维护 `年/月/日 + 当日秒数`（含闰年判断）；
`task_clock()` 用 `millis()` 整秒推进（**保留不足 1s 的余数**，防累计误差）；
**每 5 分钟**用 `HMI_SetRTCTime()`（`EE 81`）把时间同步给屏。
起始日期改文件顶部 `RTC_INIT_YEAR / RTC_INIT_MON / RTC_INIT_DAY` 即可。
星期用 Zeller 公式算（**0 = 周日**，与屏 RTC 指令一致）。

**报警记录（移植自 `afe_bridge.py` 的 `AlarmWatcher`）**：
越限**持续 3s** 才记一条（防抖动）；回落到**滞回阈值**（SpO₂ ≥ 92 / PR ≤ 115）才解除；
新记录插到最前、最多保留 4 条；写入报警记录页并 `HMI_Beep(200)`（声音开关打开时）；
SpO₂ 越限记 **高** 级、PR 越限记 **中** 级。

**关键函数**

```c
uint8_t g_paused;              /* 暂停状态：由暂停弹窗"确认"键的通知翻转；主界面"继续监护"键直接置 0 */
void app_hmi_init(void);       /* 开机一次：清记录 / 背光 80% / 趋势 5 分钟(150 点)
                                  / 曲线采样使能 EE B1 61 / 同步屏 RTC
                                  + 铺一遍 12/13/15/20/21 与两按钮显隐 */
void on_uno_frame(void);       /* 收到帧推一个波形点（g_paused 时直接 return） */
void task_hmi_value(void);     /* 每 400ms：数值 10/11/17 + 探头 91 + 报警判定 14/16；
                                  暂停时数值写 "--" 而不是整个函数 return */
void task_hmi_trend(void);     /* 每 2s：历史曲线 12/14 各追加一点（暂停/无效时跳过）
                                  + 刷趋势页"最近值"10/11 与时间刻度 15~18 */

```

> **关于"监护时间一直停在 1 秒"（已定论）**：屏端 `main.lua` 里写的是
> `start_timer(0, 1000, 0, 1)`，官方 Lua API 的 `repeat` 参数是**重复次数、0 才无限**，
> 传 1 只会触发一次 → `on_timer` 只把 `monitor_sec` 加到 1 就再也不触发；
> 而 `refresh_main()`（`on_init` + 每次 `on_screen_change`）都会把
> `"监护时间 " .. fmt_hms(1)` 写进控件 21 —— 于是屏上永远显示 `监护时间 00:00:01`。
> 修法：**停用 `main.lua` + MCU 每秒写 `21`**（均已实现），不再依赖屏端定时器。

**回调（由 `dc_hmi.c` 的 `HMI_Poll()` 调进来）**

- `NotifyButton()`：**第一行就是 `if (!state) return;`**（只处理按下沿，否则一次点击
  翻转两次）。然后：设置页 `3` 翻转声音开关并刷新设置页；主界面 `6`（继续监护）置
  `g_paused=0`；暂停页 `2` 翻转 `g_paused` 并**由 MCU 发 `EE B1 00` 跳回主界面**；
  清空页 `2` 清空记录并发 `EE B1 00` 跳回报警记录页；趋势页 `1/2/3` 切时段
- `NotifyScreen()`：屏每次跳转都会按控件默认属性重绘，这里安排 4 轮补发
  （约 +120/+420/+720/+1020 ms），把 MCU 负责的文案与按钮显隐重新铺一次
  —— **注意**：该回调此前因为 `HMI_Poll()` 的帧长门限写成 11 字节而从未被触发
  （"画面切换通知"帧只有 9 字节），门限已改为 9
- `NotifySlider()` / `NotifyText()`：同步 `12` 亮度百分比、`13/15` 报警限值文案
  （同时 `EE B1 63` 设点数、写时段文本 13）
- 另有一道**周期性自愈**：`task_hmi_value()` 每 3 秒把 MCU 负责的文案整轮重写一遍，
  不依赖任何通知，保证被覆盖/丢失后能在 3 秒内自动收敛
- `NotifySlider()`：设置页 `11` → `HMI_SetBackLight((100-value)*255/100)`
  （**`EE 60` 的 0 = 最亮，必须反相映射**）。
- `NotifyText()`：设置页 `1` → SpO₂ 下限（钳位 70~99）；设置页 `2` → PR 上限（钳位 60~200）。

### 4.7 `main.c` 主循环

```c
#include "stm32f4xx.h"
#include "usart.h"
#include "dc_hmi.h"
#include "hmi_ids.h"
#include "app_bloodoxygen.h"

extern measurement_t g_meas;
extern uint8_t g_new_frame;

int main(void)
{
  SystemInit();                              /* 168MHz */
  SysTick_Config(SystemCoreClock / 1000);    /* 1ms tick -> millis() */
  USART2_Screen_Init(115200);                /* 屏（血氧屏 DeviceBaudRate=7 -> 115200） */
  USART6_UNO_Init(UNO_BAUD);                 /* UNO；固件内另有 uno_autobaud() 兜底 */

  HMI_Init();
  HMI_SetScreen(SCR_MAIN);
  HMI_ScreenUpdateEnable(1);
  app_hmi_init();                            /* 清记录 / 背光 / 趋势时段 / 同步屏 RTC */

  while (1) {
    HMI_Poll();                              /* 处理屏上行通知（按钮/滑块/文本） */
    if (g_new_frame) { g_new_frame = 0; on_uno_frame(); }   /* 推一个波形点 */
    task_hmi_value();                        /* 400ms 数值刷新 + 报警判定 */
    task_hmi_trend();                        /* 2s 趋势追加一点 */
    task_clock();                            /* 1s 软 RTC + 周期同步屏 */
    g_meas.monitor_sec = millis() / 1000;
  }
}
```

> ⚠️ **AC5 中文串陷阱（本项目实测踩到）**：本工程源码是 **UTF-8**，若在字符串字面量里
> 直接写中文，编译器会把 **UTF-8 字节**编进固件，而屏字库是 **GBK** → **屏上乱码，且编译不报错**。
> 因此**所有上屏汉字一律用 GBK 的 `\xNN` 转义**（见 `app_bloodoxygen.c` 顶部 `S_*` / `S_TRD_*` 宏）。
> 自检：`python -c "print(open('OBJ/STM32F407_Template.axf','rb').read().find('记录时段'.encode('gbk'))>=0)"`
> 应打印 `True`，且 UTF-8 版本不存在。

| 7 | **趋势曲线是一条死直线、不是测量数据** | **采样位宽不匹配**：屏 `趋势.tft` 的 `sample_data_foramt=0`（UINT8/每点 1 字节），而 MCU 用 `HMI_HistorySampleU16()` 每点发 2 字节（SpO₂=97 → `00 61`），屏只吃掉高字节 `0x00` → 曲线恒为 0、贴量程下限画成直线。改 `sample_data_foramt=2`（UINT16）对齐；同时节奏 60s→2s、时段按钮改 1/5/30 分钟 | `趋势.tft` + `task_hmi_trend()` + `hmi_ids.h` |

### 5.2 屏 RTC 控件（`type="rtc"`）属性速查

> 来源：VisualTFT 内置属性表（`Property` 定义，权威）。控件 92 `txt_clock` 即此类型。

| 属性 | 取值 | 说明 |
|---|---|---|
| `format` | `3;0;1;2;5;4;6;7;8` | 依次对应：**HH:MM:SS** / **20XX-MM-DD** / **20XX-MM-DD HH:MM:SS** / 20XX-MM-DD HH:MM:SS 星期几 / 星期几(中英) / HH:MM:SS(计时) / MM:SS(计时) / SS(计时) / 自定义 |
| `format_string` | 串 | 自定义格式串。**`%y`=年(4 位,20XX)、`%n`=月、`%d`=日、`%h`=时、`%m`=分、`%s`=秒、`%w`=星期**。例：`20XX-MM-DD HH:MM:SS` 对应的串就是 `%y-%n-%d %h:%m:%s` |
| `input` | `0;1;2;3` | 允许编辑：**0=否** / 1=编辑日期与时间 / 2=编辑日期 / 3=编辑时间。**非 0 时触摸时钟区会弹出日期时间设置框** |
| `timer` / `increase` | 秒 / `0 倒计时;1 顺计时` | 仅计时类格式用到 |
| `zone` | `-12~+12` | 时差 |
| `lang` | `0 中文;1 英文` | — |

**本项目取值**：`format="1"` + `format_string="%y-%n-%d %h:%m:%s"` + `input="0"` + `xOffset=592 width=192`
→ 显示 **`2026-01-01 00:00:00`**，与血压工程（`str_app4` + `%02d:%02d:%02d`）**格式一致**。
`input="0"`：时间由 MCU 通过 `EE 81` 统一维护；**不开放屏上编辑**（否则用户手改会被 MCU 每 5 分钟的同步覆盖，看起来像 bug）。

**RTC 相关指令（`InstructConfig.xml` 官方定义）**

| 指令 | 长度 | 名称 | 帧 |
|---|---|---|---|
| `0x81` | 13 | SetRTCTime | `EE 81 <Sec> <Min> <Hour> <Day> <Week> <Mon> <Year> FF FC FF FF`（BCD，星期天=0） |
| `0x82` | 6 | ReadRTCTime | `EE 82 FF FC FF FF` → 屏回 `EE F7 <Year> <Mon> <Week> <Day> <Hour> <Min> <Sec> FF FC FF FF` |
| `0x85` | 15 | SetRTCDisplay | 运行时改 RTC 显示方式 |

## 6. 联调与验证步骤

> ✅ **实测结论（2026-10-10，本样机已通过）**
> 端到端全链路已跑通：AFE4490 → UNO(Example-1@57600) → STM32(USART6) → 大彩屏(USART2@115200)。
> 实测：USART1 `tick | uno_rx=211465 frames=12439 | spo2=98 pr=72 ir=246728`；屏上主界面 **SpO₂=98 / PR=86 / 信号质=100 / T 计时正常**，PPG 波形有清晰脉搏波与降中峡。
>
> **过程中确认的两条关键硬件事实（务必记住）**：
> 1. **屏不吃"批量更新 B1 12 + 刷屏开关 B3"** —— 官方 `app_spo2.c` 的 refreash 路径在这块 DC80480DN050 上静默丢帧，控件永远显示 `--`。
>    **必须用单条 `EE B1 10 <screen:16> <ctrl:16> <str>` 逐控件写。**（`task_hmi_value()` 已按此实现）
> 2. **UNO 侧波特率 = 57600**（原始 Example-1 的 `Serial.begin(57600)`），不是 115200。
>    固件已内置 USART6 波特率自动探测（57600/115200/9600，第一个解析出有效帧即锁定）。
>
> 排障开关：`main.c` 的 `UNO_RAW_DUMP` 置 1，可把 UART6 收到的原始字节以 hex 打到 USART1（交付版默认 0）。

1. **UNO 单独验证（先排除 AFE/算法问题）**
   - 盾板叠 UNO，接手指探头。原始 Example-1 的串口监视器波特率要设 **57600**，应看到 `Intilaziting AFE44xx..` / `Inited...`。
   - 想肉眼看数值可临时换 Example-2（115200，打印 `Sp02 : 97% ,Pulse rate :72 bpm`）；但它**不发二进制帧**，仅供算法验证。
2. **STM32 USART6 收数验证（不接屏也行）**
   - `DEMO_STEP=3`，`UNO_RAW_DUMP=1`，USART1(115200) 应打印 `uno_rx=`/`frames=` 持续增长，`UNO raw:` 出现 `0A FA 0A 00 02 .. 00 0B`。
   - 重点确认：**PC7 接的是 UNO D1(TX)、必须共地**、UNO 已上电；波特率用固件自动探测即可。
3. **屏 USART2 验证（不接 UNO 也行）**
   - `DEMO_STEP=2`：写死 `98/72/95/OK` 上屏（走单条 `EE B1 10`），屏显示即链路通。
   - 确认电平：SP3232 接法 OR 屏已短 J5；波特率 115200；PA2→屏RX、PA3→屏TX。
4. **端到端联调**
   - `DEMO_STEP=4`：UNO 上电 → STM32 解析 → 屏显示 SpO₂ / PR / PPG 波形 / 趋势。
   - 观察波形是否滚动、数值 400ms 级刷新、趋势每 2s 冒一个点（曲线应随 SpO₂/PR 上下起伏）。
5. **异常路径**
   - 拔/松探头 → 屏主界面数值变 `--`、各页状态条 91 变 **"探头未接入"**、探头状态页提示信号差。
   - 切到趋势页点 1分钟/5分钟/30分钟 → 历史曲线一屏点数与时段文本、底部时间刻度随之变化。
6. **新增界面功能验证（对应 5.1 六项诉求）**
   - **暂停**：主界面点"暂停监护"→ 暂停页点"确认"→ 应**真正停测**（波形停、数值变 `--`）；
     回到主界面时：
     * 左下角按钮文字应变成 **"继续监护"**（对应 5.3 ①）
     * 波形下方文案应变 **"暂停中"**、右上小字应变 **"已暂停"**（对应 5.3 ②）
     * **"监护时间"应停在暂停那一刻不再走**（对应 5.3 ③）
     点 **"继续监护"** → 立即恢复：按钮文字回到"暂停监护"、文案回"脉搏波采集中"、
     监护时间从暂停处继续走。
   - **趋势**：进趋势页后 **10~20 秒内**两条曲线就应从右往左生长（每 2s 一点）；
     屏息/活动让 SpO₂、PR 变化时曲线应随之上下起伏（**不是一条平直的死线**）；
     点 1分钟/5分钟/30分钟，时段文本与底部时间刻度 HH:MM 应同步变化；
     左列"最近值"应等于主界面当前 SpO₂/PR。
   - **报警记录**：把 SpO₂ 下限设到高于当前值（如 99）并屏息几秒 →
     越限**持续 3s** 后应新增一条记录（时间/事件/级别/状态），并听到提示音；
     恢复后点"清空"应清空 4 行并显示"暂无报警记录"。
   - **设置**：设置页改 SpO₂ 下限 / PR 上限 → 主界面报警限值文案（`13`/`15`，由 MCU 写）随之变；
     越限判定阈值也按新值生效。拖亮度滑块 → **屏背光真的变亮/变暗**且 `12` 百分比跟着变；
     点"声音提示"开关 → `13` 文案在"已开启/已关闭"间切换，下次报警有/无蜂鸣。
   - **时间**：顶栏时钟应显示 **`年-月-日 时:分:秒`**，与血压工程一致。
   - **探头**：拔下指套几秒后 → 各页状态条 91 变 **"探头未接入"**；夹回后恢复"探头已接入"。

**常见问题排查表**

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 屏不显示 / 收不到按键 | 电平错（RS232 当 TTL 没短 J5） | 短 J5 或用 SP3232 |
| 屏显示乱码 | 屏口波特率不符 | USART2 改 115200（血压屏才是 9600） |

| 数值刷新慢 | 库 `dec==20` 未改 | 按 3.1 把 SpO₂ 更新提到 ~1s |

## 7. 与血压工程的边界（再次强调"分开"）

- **两个独立工程、分别烧录**：`STM32F407_SPO2`（本工程）与血压工程互不包含。
- **可复用的"软资产"**（不是硬件冲突）：
  - `hmi_ids.h`：两工程屏控件 ID 体系一致，可直接拷贝。
  - `dc_hmi.c` 的拼帧/解帧逻辑：把 HAL+USART3 改成 SPL+USART2 即可两处共用。
  - `Notify*` 按键回调模板（暂停确认 / 清空报警 / 趋势时段 / 亮度滑块）：逻辑一致，照搬。
- **不要做的事**：不要把 AFE 的 SPI 引脚（PB3/4/5/PA4/PA0/PC13/PG15）接到 STM32 上 —— 那是 UNO 的活；STM32 侧只保留 USART2(屏) + USART6(UNO) + （可选）USART1(调试)。

## 8. 待办 / 可优化

1. **signal_quality 真值**：当前 STM32 端用"有效即 100"的占位值。真值可用 IR 的交流分量/直流分量比（灌注指数 PI）估算，或在 UNO 侧算好放进"扩展帧"。
2. **SpO₂ 更新提速**：按 3.1 修改 `S_afe44xx.cpp` 的 `dec` 计数，把刷新从 ~16s 提到 ~1s。
3. **扩展帧（可选）**：若想要 STM32 端直接拿到 quality/probe 而不靠推导，可在 UNO 帧里把 `DATA_LEN` 从 10 扩到 12，追加 `quality`/`probe` 两字节（同步改 STM32 解析的 `pl[10]/pl[11]` 与 `S5_PAYLOAD` 长度）。注意 `afe_bridge.py` 仅调试用，同步改即可。
4. **历史曲线断电保存**：当前趋势只在 RAM，掉电丢；如需报警记录/趋势长期保存，用内部 Flash 或 EEPROM 落盘（参考血压工程做法）。
5. **DMA 收 UNO**：当前 RXNE 中断逐字节收；数据量大时可改 USART6 **IDLE + DMA + 环形缓冲**（与血压工程 USART 接收架构一致）以降低中断开销。
6. **报警阈值持久化**：当前 `s_spo2_low/s_pr_high/s_sound_on/背光` 只在 RAM，掉电复位；如需记忆可落 Flash（参考血压工程）。
7. **软 RTC 掉电保持**：当前上电从 `RTC_INIT_*` 起走；要真实走时可读 STM32 后备域 RTC 或屏 RTC（`EE 82` 读回）作为初值。
