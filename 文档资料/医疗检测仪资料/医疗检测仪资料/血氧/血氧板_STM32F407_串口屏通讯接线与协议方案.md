# 血氧板 + STM32F407ZGT6 + M 系列串口屏通讯方案（第一版）

## 1. 目标和结论

数据链路：

    血氧板 AFE4490
      └─ SPI + DRDY + 片选 + 复位/掉电控制
            ↓
    STM32F407ZGT6
      ├─ 读取 RED/IR 原始数据
      ├─ 计算 SpO2、PR、信号质量和探头状态
      └─ 通过现有 RS232 串口刷新串口屏

USART3 继续给血压模块使用，血氧板不占用 USART3。串口屏继续使用已经调通的 RS232 连接，不改现有屏幕线。

### 1.1 联调修订结论（已对照血压模块项目书核对）

**① 电平转换：可以免，但取决于血氧板 LOGIC SELECT 怎么设（见第 2.1 节）**

- **最优（零电平转换）**：把血氧板右上角 `3.3v/5v` 选择位改到 **3.3v**（VCCB≈3.3V）。此时 7 根信号全是 3.3V，可**完全直连 STM32，不加任何电平转换**；仅血氧板 `Vin` 仍接 5V 供电，只改逻辑电平选择位。改后用万用表确认 VCCB 对 Gnd≈3.3V 再接线。
- **若板子焊死在 5V（不改板）**：下行两根 `MISO→PB4`、`!DRDY→PA0` 所连 STM32 脚均为 **FT（5V 容忍）**，可**直接接收 5V，省掉下行电平转换（原方案的 LVC125A）**；只剩上行 5 路（SCK/MOSI/!CS/START/!PDN）需要 3.3V→5V 升压，除非血氧板 B 侧电平转换芯片输入是 TTL 阈值（VIH=2.0V，则 3.3V 也能识别，可进一步省掉）。详见第 2.1 节。

**② 引脚冲突：与血压模块交叉核对，结论是无冲突，无需为避开血压改引脚**

| 模块 | 占用引脚 | 说明 |
|---|---|---|
| 血氧板（本方案） | PB3/PB4/PB5（SPI1）、PA4（!CS）、PA0（!DRDY/EXTI0）、PC13（START/!RESET）、PG15（!PDN） | SPI + GPIO |
| 血压模块 | PA9/PA10（USART1 调试）、PA2/PA3（USART2 屏）、PB10/PB11（USART3 传感器） | 3 路 UART |

两组引脚**完全不重叠**。串口分工也一致：屏走 USART2（PA2/PA3）、血压传感器走 USART3（PB10/PB11，保留给血压）、调试走 USART1（PA9/PA10）；血氧板只用 SPI 和 GPIO，**不占用任何 USART**。因此当前引脚分配已满足"两者不冲突"，第 3、5 节保持原分配并补充核对备注即可。

> 更正说明：原第 2.1 节"不能因为某一个输入脚可能是 FT 脚就把所有信号直接接 5V"的判断，经数据手册引脚类型表核对后**需更正**——本方案下行两根线所接的 **PB4、PA0 确实都是 FT 脚**，所以这两根可以安全直连 5V；但 **PA4（!CS）是 TTa（仅 3.3V 容忍）**，它在本方案里是 STM32→血氧板的输出（只会输出 3.3V），不会引入 5V，故安全——只是提醒它绝不能反过来接成 5V 输入。
>
> 可选优化（非必须）：SPI1 占用了 PB3/PB4（JTAG 的 JTDO/NJTRST），联调时需关闭全 JTAG、保留 SWD。若想彻底避开调试口冲突，可把 SPI 改到 **SPI2（PB13/SCK、PB14/MISO、PB15/MOSI）**，这三个脚空闲且均为 FT，且不涉及 JTAG；相应固件把 SPI1 句柄换成 SPI2 即可。

> **③ 架构选择（联调阶段推荐）**：本项目联调阶段推荐走 **【方案二：Arduino UNO 中转】**（见 1.2）——AFE4490 盾板原生插 UNO（5V 逻辑），且你手头的 AFE4490 驱动库就是 Arduino 库，让 UNO 当"血氧协处理器"算好 SpO2/PR 再串口发给 STM32，**几乎不碰电平转换、不用移植 SPI 驱动**。原"SPI 直连 + 电平转换"方案（第 2~4 节）降为**备选**，仅在后续把 AFE 库移植到 STM32 时才用。

## 1.2 方案二：Arduino UNO 中转架构（推荐联调路径）

### 1.2.1 数据链路

    AFE4490 盾板 ──堆叠──► Arduino UNO（读 AFE4490、算 SpO2/PR）
            │ 串口 TTL 直连（UNO 5V ↔ STM32 3.3V，电平已核对）
            ▼
       STM32F407（USART6 / PC6-PC7 收数据）
            │ 现有 RS232
            ▼
       大彩串口屏；USART3 仍接血压模块（不冲突）

### 1.2.2 详细引脚接线

**（A）AFE4490 盾板 ↔ Arduino UNO：直接堆叠，不飞线**

盾板是标准 UNO R3 排母盾，直接插到 UNO 上即可。盾板用到的 UNO 资源（SPI 走 UNO 硬件 SPI，控制/中断脚在库头文件里定义，移植或查错时以 `AFE4490_library/src/S_afe44xx.cpp` 为准）：

| 盾板丝印 | UNO 引脚（典型，需按你的库核对） | 说明 |
|---|---|---|
| SCK | D13（UNO SPI SCK） | 盾板→UNO，5V 逻辑 |
| MISO | D12（UNO SPI MISO） |  |
| MOSI | D11（UNO SPI MOSI） |  |
| !CS | D10 / D9（库定义） | 片选，低有效 |
| START | D8 / D9（库定义） | 实际走 AFE 复位路径 |
| !PWDN/RESET | D8 / D9（库定义） | 掉电控制 |
| !DRDY | D2（外部中断，典型） | UNO 中断读数据 |
| 5V | UNO 5V 排针 | 盾板逻辑 + LED 驱动供电 |
| GND | UNO GND | 共地 |

> 注：具体 !CS/START/!PDN/!DRDY 对应的 Dx 以你库中 `S_afe44xx.cpp` 及其头文件的宏定义为准；上表是该类盾板的常见接法，插上即生效、无需飞线。

**（B）Arduino UNO ↔ STM32F407：一路串口直连（新增链路，关键）**

UNO 与 STM32 都是 TTL，但电平不同：UNO 是 5V，STM32 是 3.3V。按数据手册引脚类型表核对，STM32 这边的**接收脚（RX）必须选 FT（5V 容忍）**才能直连 UNO 的 5V TX；STM32 的发送脚（TX，3.3V）→ UNO 的 RX 可直接连（ATmega328P 输入高阈值 VIH = 0.6×VCC ≈ 3.0V，3.3V 满足）。

推荐用 **USART6**（PC6/PC7，已核实均为 FT）：

| 方向 | UNO 引脚 | 信号电平 | STM32 引脚 | 备注 |
|---|---|---|---|---|
| UNO → STM32 | D1（TX，5V） | 5V | **PC7（USART6_RX，FT）** | 5V 进 FT 脚，可直连，无需电平转换 |
| STM32 → UNO | **PC6（USART6_TX，3.3V）** | 3.3V | D0（RX） | 3.3V→UNO 直连（UNO 识别高电平阈值≈3.0V） |
| 共地 | UNO GND | — | STM32 任意 GND | 必须共地 |

- PC6/PC7 在神舟板 P8/P9 排针上可取（见原理图，PC6=U6_TX、PC7=U6_RX 区域，作普通 GPIO 用）。
- 备选空闲串口（RX 脚均已核实为 FT，可直连 5V）：UART4（PA0/PA1 或 PC10/PC11）、UART5（PC12/PD2）。
- **严禁用 USART1/2/3**：已分别给调试日志、屏、血压传感器占用。
- **电平结论：UNO↔STM32 这一路串口不需要任何电平转换。** 只有盾板↔UNO 是盾板原装 5V 设计、天然匹配。

> UNO D0/D1 同时也是板载 USB 转串（CH340）引脚。联调时建议 UNO 由神舟板 5V **外部供电、不连 USB**，以免 CH340 与 STM32 抢 D0/D1；若需要用 UNO 的 USB 串口监视调试，则把 STM32 链路改到 **SoftwareSerial（如 D2/D3）**，不要占 D0/D1。

**（C）供电**

| 供电对象 | 来源 | 说明 |
|---|---|---|
| AFE4490 盾板 | UNO 的 5V 排针 | 堆叠取电，无需另接 |
| Arduino UNO | 神舟板 VOUT2 的 +5V（J5 区：VOUT2 的 2/4/6 脚=+5V，1/3/5 脚=GND） | 或 UNO 自带 USB/DC；联调建议由神舟板统一供 5V，少一根线 |
| STM32 神舟板 | 自身 5V/USB | 不变 |
| 大彩串口屏 | STM32 RS232（SP3232） | 不变 |

### 1.2.3 UNO ↔ STM32 串口协议（建议）

UNO 端把 `spo2_measurement_t` 通过串口发给 STM32。建议帧格式（独立一路 USART6，不与屏/血压协议混淆；用 DMA+IDLE 空闲中断收帧，无需帧尾）：

    帧头  LEN  CMD  SpO2  PR  quality  probe  valid  CKSUM
    A5 5A  <N>  0x51 1B    1B   1B       1B     1B     1B

- 波特率：**115200，8N1**（与血压模块同速，方便复用现有 DMA+IDLE 接收框架）
- `LEN` = 后续数据字节数（上例为 5）
- `CMD` = 0x51（自定义血氧数据帧）
- `CKSUM` = (LEN + CMD + SpO2 + PR + quality + probe + valid) & 0xFF
- 无效数值：SpO2/PR 发 0xFF 占位，STM32 端显示 `--`
- 仅传结果，不传原始波形；如后续要 PPG 曲线，UNO 可另行按 20~50 Hz 发波形点，STM32 走曲线控件

### 1.2.4 STM32 侧资源变化与血压冲突

走方案二后，STM32 **不再使用 SPI1（PB3/4/5）、PA4、PA0、PC13、PG15**，这些脚全部释放；SpO2 只占 **USART6（PC6/PC7）** 一路空闲串口：

| STM32 资源 | 方案一（SPI 直连） | 方案二（UNO 中转，推荐） | 与血压冲突 |
|---|---|---|---|
| SPI1 PB3/4/5、PA4、PA0、PC13、PG15 | 占用 | **释放** | 方案一已无冲突；方案二更彻底 |
| USART1 PA9/10 | 调试日志 | 调试日志 | 无 |
| USART2 PA2/3 | 屏 | 屏 | 无 |
| USART3 PB10/11 | 血压传感器（保留） | 血压传感器（保留） | 无 |
| USART6 PC6/7 | 未用 | **血氧数据（新增）** | 血压不用，无冲突 |

结论：方案二下 SpO2 与血压模块**引脚零冲突**，且比方案一更省心——不用移植 AFE 库、不碰电平转换、JTAG/SWD 完全自由。

### 1.2.5 推荐初始化顺序（UNO 中转）

1. 盾板堆叠到 UNO，UNO 烧入"读 AFE4490 + 算 SpO2/PR + 串口发帧"的 sketch（基于你现有 `AFE4490_library`）。
2. UNO 通过 PC6/PC7 ↔ D0/D1 接 STM32 并共地；UNO 由神舟板 5V 供电（联调期不连 USB）。
3. STM32 初始化 USART1（调试）、USART2（屏）、USART3（血压）保持不变。
4. STM32 新增初始化 USART6（115200/8N1），DMA+IDLE 收 UNO 帧，解析出 SpO2/PR/质量/状态。
5. 主循环：血压逻辑 + 血氧帧解析共用同一份 `spo2_measurement_t`，统一刷屏（屏仍走 USART2/RS232）。
6. 验证顺序：先单验 UNO 能稳定出 SpO2（PC 串口助手）→ 再验 STM32 收到帧 → 最后合入屏显示并与血压同屏。

### 1.2.6 上电前核对清单（UNO 中转）

- [ ] 盾板已堆叠到 UNO，UNO 单独供电能跑出 SpO2（先在 PC 串口助手验证）
- [ ] UNO D1(TX,5V)→STM32 PC7(RX,FT)；STM32 PC6(TX,3.3V)→UNO D0(RX)；GND 共地
- [ ] 确认用的是空闲串口（USART6/UART4/UART5 之一），未占用 USART1/2/3
- [ ] UNO 5V 由神舟板 VOUT2 提供（或自带电源），与 STM32 共地；联调期 UNO 不连 USB
- [ ] STM32 USART6 波特率 115200/8N1，与 UNO 一致
- [ ] 屏(USART2)、血压(USART3)、调试(USART1) 仍各司其职，血氧走 USART6，互不抢外设
- [ ] 先单验 UNO 出数 → 再验 STM32 收帧 → 最后合屏

## 2. 上电前的硬件设置

照片对应 pc_afe44xx_shield_v3 这一类 AFE44xx 板。板上有电平转换，接 STM32 前先做两件事：

1. 图片中右上角 `3.3v`、`5v` 标记旁的焊接/0 欧电阻选择位，就是 LOGIC SELECT 的 VCCB 选择位置。它选择的是**数字信号电平**，不是单纯的供电输入。
2. 如果选择位可以切换，强烈推荐 VCCB 接 `3.3v`（选法 A，见 2.1），上电后用万用表确认 VCCB 对 Gnd 约为 3.3 V，之后 7 根线全直连、无需电平转换。
3. 若你的板子已焊死在 `5v` 无法切换，则按第 2.1 节"选法 B"处理：下行两根 MISO/!DRDY 因所接 PB4/PA0 是 FT 脚可直连，仅上行 5 路需 3.3V→5V 升压。
4. 血氧板用 `5v` 和 `Gnd` 供电。STM32F407 神舟板原理图的 VOUT2 是 5 V 输出排针：
   - VOUT2 的 2、4、6 脚：+5V
   - VOUT2 的 1、3、5 脚：GND

不要把血氧板的 Vin 接到 STM32 的 5 V。VCCB 设为 3.3V（选法 A）时所有信号可直接连；固定 5V（选法 B）时，MISO/!DRDY 因 PB4/PA0 为 FT 脚仍可直连，仅上行 5 路需升压。上电后先测 VCCB 对 Gnd：选法 A 应≈3.3V，选法 B 若为 5V 则按 2.1 选法 B 接线。

### 2.1 电平转换方案（两种选法）

**选法 A（推荐，零电平转换）：把血氧板 LOGIC SELECT 改到 3.3V**

血氧板右上角 `3.3v/5v` 选择位决定的是数字逻辑电平 VCCB。若把它改到 `3.3v`（仅改这个 0Ω/焊点，不影响 `Vin` 的 5V 供电），则排针侧所有信号都是 3.3V，**7 根线全部直连 STM32 GPIO，无需任何电平转换**。改完务必用万用表确认 VCCB 对 Gnd≈3.3V 再接线。这是联调最省事、风险最低的方案。

**选法 B（板子焊死在 5V、不改板）：保留上行升压，省掉下行降压**

保持 5V 焊接状态。经核对 STM32F407 数据手册引脚类型表：

- 下行两根 `MISO→PB4`、`!DRDY→PA0`：PB4、PA0 均为 **FT（5V 容忍）** 脚，可直接接收 5V 输入，**不需要下行电平转换（原方案的 LVC125A 可省）**，直接连 STM32。
- 上行 5 路 `SCK/MOSI/!CS/START/!PDN`：STM32 输出 3.3V，要被 5V 侧识别为"高"通常需要 3.3V→5V 升压。除非血氧板 B 侧电平转换芯片输入是 **TTL 阈值（VIH=2.0V）**（需查该芯片手册确认），否则保留升压。
- 因此选法 B 的最小 BOM：**只保留上行升压**，例如 `2 片 SN74AHCT125`（共 8 通道，用 5 路）接在 STM32 3.3V 侧 → 血氧板 5V 侧；`MISO`、`!DRDY` 直接连。

通用要求（两种选法都适用）：

- 不建议使用只为 I2C 设计的 BSS138 双向模块，也不建议用 TXS0108E 直接跑 SPI（方向/速率不匹配）。
- 若用分立芯片：`SN74AHCT125` 的 VCC 接 5V、OE 接 GND 常使能；转换器 GND、STM32 GND、血氧板 GND 三者相连。
- 先接 GND 和电源，再接信号。上电后先测 VCCB 对 Gnd：选法 A 应≈3.3V；选法 B 若实测 MISO/!DRDY 高电平超过 3.6V，说明所选脚并非 FT，则这两根也必须加降压，严禁直连。

固定 5V（选法 B）逐线接法（STM32 引脚见第 3 节，不改变 USART3 分配）：

| 方向 | STM32 3.3V 侧 | 电平转换 | 血氧板 5V 侧丝印 |
|---|---|---|---|
| STM32 → 血氧板 | PB3 / SPI1_SCK | AHCT125 通道 | SCK |
| STM32 → 血氧板 | PB5 / SPI1_MOSI | AHCT125 通道 | MOSI |
| STM32 → 血氧板 | PA4 / !CS | AHCT125 通道 | !CS |
| STM32 → 血氧板 | PC13 / START（实际为 !RESET） | AHCT125 通道 | START |
| STM32 → 血氧板 | PG15 / !PWDN/RESET（实际为 !PDN） | AHCT125 通道 | !PWDN/RESET |
| 血氧板 → STM32 | PB4 / SPI1_MISO | **直连（PB4 为 FT 脚，可承受 5V）** | MISO |
| 血氧板 → STM32 | PA0 / EXTI0 | **直连（PA0 为 FT 脚，可承受 5V）** | !DRDY |

## 3. 血氧板到 STM32 的逐线接法

下表是信号的逻辑对应关系。选择位为 3.3V 时可直接连接；你的固定 5V 板必须在每根信号线上插入第 2.1 节的电平转换器。

以下排针编号来自 STM32F407_原理图.pdf 第 4 页。

| 血氧板照片丝印 | STM32F407 GPIO/外设 | 神舟板排针位置 | 接线说明 |
|---|---|---|---|
| SCK | PB3 / SPI1_SCK | P8-45，板上 PB3 | SPI 时钟 |
| MISO | PB4 / SPI1_MISO | P8-48，板上 PB4 | 血氧板数据输出到 STM32 |
| MOSI | PB5 / SPI1_MOSI | P8-47，板上 PB5 | STM32 写 AFE 寄存器 |
| !CS | PA4 普通 GPIO 输出 | P9-35，板上 PA4 | 片选，空闲必须为高 |
| !DRDY | PA0 / EXTI0 输入 | P9-38，板上 PA0 | 数据就绪中断；边沿按实测波形配置 |
| START | PC13 普通 GPIO 输出 | P9-44，板上 PC13 | 实际连接 AFE !RESET；默认高，复位时低脉冲再拉高 |
| !PWDN/RESET | PG15 普通 GPIO 输出 | P8-46，板上 PG15 | 实际连接 AFE !PDN；运行时保持高 |
| Gnd | GND | 接 STM32 VOUT2 任一 GND | 两块板必须共地 |

这组引脚的板载复用要同时处理：PB3/PB4 带 JTAG 标签，使用 SPI1 时关闭全 JTAG、保留 SWD；PA4 带 STM_DAC 标签，不能再初始化为 DAC；PA0 带 WK_UP 标签，调试期间不要把 WK_UP 按键当普通按键使用。若你的工程正在使用这些功能，再把对应普通 GPIO 改到未占用排针，并同步修改固件宏定义。

**与血压模块冲突核查（联调版）**：上述 7 个引脚 `{PB3,PB4,PB5,PA4,PA0,PC13,PG15}` 与血压模块占用的 `{PA9,PA10,PA2,PA3,PB10,PB11}` **完全不重叠**，且串口分工一致（屏 USART2、血压传感器 USART3、调试 USART1），血氧板不使用任何 USART，故**无需为避开血压改动引脚**。补充注意：① `PA0` 兼作板载 WK_UP 唤醒键，接 !DRDY 后该按键不可用；② `PC13` 属备份域、驱动能力弱（≤3mA、低速），作 !RESET 输出够用，但勿作大电流负载；③ 若改走可选的 SPI2（PB13/14/15），则 PB3/PB4 的 JTAG 冲突彻底解除。

照片中的 START 不要按普通“转换启动”理解；该板原理图中它是 AFE 的复位路径。!PWDN/RESET 是掉电控制路径，所以这两个脚分别接 GPIO。

### 不接的血氧板引脚

第一版只需要上表 7 根信号线和电源/地：

- DIAG_END：先悬空
- LED_ALM：先悬空
- PD_ALM：先悬空
- 板上的 D10/D9/D8 等 Arduino 数字脚：不用另外接
- 板上的 Vin：不接

## 4. SPI 参数和 AFE 数据读取

第一版按本地 AFE4490 库的参数移植：

- 主机：STM32 SPI1
- 引脚：PB3/PB4/PB5
- 数据位：8 bit
- 位序：MSB first
- SPI 模式：SPI_MODE0
- 频率：先用 2 MHz
- 片选：!CS 低有效
- 一个寄存器访问：1 字节地址 + 3 字节数据

!DRDY 中断服务函数只置标志或计数，不在中断里读 SPI。主循环看到标志后读取 LED2VAL、ALED2VAL、LED1VAL、ALED1VAL，再按现有算法得到 SpO2、PR、质量和探头状态。

建议使用统一结果结构：

    typedef struct {
        int16_t spo2;          /* 0~100；无效为 -1 */
        int16_t pulse_rate;    /* PR，单位 bpm；无效为 -1 */
        uint8_t quality;       /* 0~100 */
        uint8_t probe_state;   /* 0 未接入，1 接入，2 信号差 */
        uint8_t result_valid;  /* 0 无效，1 有效 */
        uint8_t fault_code;
    } spo2_measurement_t;

数值无效时显示 --，不要继续显示上一笔有效值。

## 5. 与血压模块、串口屏的资源分配

| 功能 | 串口/引脚 | 处理 |
|---|---|---|
| 血压模块 | USART3，通常为 PB10=USART3_TX、PB11=USART3_RX | 保留，血氧不得使用 |
| 串口屏 | 当前已经调通的 RS232 通道 | 保留现有接线和串口句柄 |
| 血氧板 | SPI1 + GPIO + EXTI | 不使用 USART3 |

神舟板原理图中，RS232/RS485 区域的 P3 提供 USART2_TX/USART2_RX。如果你的屏幕现在接在这个通道，就继续使用 USART2；如果当前工程已使用其他串口，只保留当前实际可通信的那个串口。

F:\VisualTFT\SPO2_Hospital\mcu\dc_hmi.c 示例默认声明 huart3，这只是示例。移植时必须把 HMI 驱动的 UART 句柄改成当前串口屏所用的串口，不能占用血压模块的 USART3。

#### 5.1 与血压模块引脚冲突矩阵（联调核对）

| 功能 | 引脚 | 血压模块是否占用 | 结论 |
|---|---|---|---|
| SPI1_SCK | PB3 | 否（血压 USART3 用 PB10/PB11） | 无冲突 |
| SPI1_MISO | PB4 | 否 | 无冲突 |
| SPI1_MOSI | PB5 | 否 | 无冲突 |
| !CS | PA4 | 否 | 无冲突 |
| !DRDY | PA0 | 否 | 无冲突 |
| START/!RESET | PC13 | 否 | 无冲突 |
| !PDN | PG15 | 否 | 无冲突 |
| 屏 UART | USART2（PA2/PA3） | 血压屏也用 USART2 | 共用，一致 |
| 血压传感器 UART | USART3（PB10/PB11） | 血压占用 | 保留，血氧不碰 |
| 调试 UART | USART1（PA9/PA10） | 血压调试用 | 共用，一致 |

**结论**：血氧板与血压模块**引脚零冲突**，当前分配直接可用于联调，无需为避开血压改动引脚。注意屏（USART2）与调试（USART1）是两套固件共用同一物理串口，联调时由单一 HMI 驱动/日志模块统一收发，不要在两份代码里各开一个 UART 句柄抢同一个外设。

#### 5.2 方案二（UNO 中转）下的资源占用与冲突

走 1.2 的 UNO 中转方案时，STM32 不再占用 SPI1 及 PA4/PA0/PC13/PG15，仅新增一路空闲串口（USART6 或 UART4/5）收 UNO 数据：

| STM32 资源 | 占用方 | 与血压模块冲突 |
|---|---|---|
| USART1（PA9/PA10） | 调试日志 | 无（血压也用它做调试，共用一致） |
| USART2（PA2/PA3） | 大彩串口屏 | 无（共用一致） |
| USART3（PB10/PB11） | 血压传感器（保留） | 无（血氧不碰） |
| USART6（PC6/PC7）或 UART4/5 | **血氧数据（UNO 中转）** | 无（血压不用这些串口） |
| SPI1 / PA4 / PA0 / PC13 / PG15 | 释放（方案一备选才用） | 释放 |

结论：方案二下 SpO2 与血压模块**引脚零冲突**，且比方案一更省心（不移植 AFE 库、不碰电平转换、JTAG/SWD 自由）。

## 6. 串口屏传输协议

SPO2_Hospital 工程采用：

- 波特率：115200
- 格式：8N1
- CRC：关闭
- 帧头：EE
- 帧尾：FF FC FF FF
- 16/32 位数值：高字节在前

### 6.1 主界面控件 ID

| 数据 | 画面 ID | 控件 ID |
|---|---:|---:|
| SpO2 | 0 | 10 |
| PR | 0 | 11 |
| 有效状态 | 0 | 12 |
| 信号质量 | 0 | 17 |
| PPG 实时曲线 | 0 | 19 |
| 采集状态 | 0 | 20 |
| 监护时间 | 0 | 21 |

### 6.2 写文本

格式：

    EE B1 10 <画面ID:2字节> <控件ID:2字节> <文本> FF FC FF FF

向主界面控件 10 写入 SpO2=98：

    EE B1 10 00 00 00 0A 39 38 FF FC FF FF

文本不带 00 结尾。第一版建议用文本写入，兼容性比整数专用指令更好。

### 6.3 写 PPG 实时曲线

工程主界面曲线控件为 画面0/控件19，量程为 0~255：

    EE B1 32 <画面ID> <控件ID> <通道> <点数:2字节> <数据> FF FC FF FF

先完成 SpO2/PR 数值刷新，再加入曲线。曲线数据建议每次发送 8~32 个点，避免占满串口。

### 6.4 刷新频率

- SpO2、PR、质量、状态：每 400~500 ms 刷新一次
- PPG 曲线：约 20~50 Hz，按串口余量调整
- 屏幕触摸通知：串口中断只收字节，主循环调用现有 HMI_Poll() 解析

屏幕、日志和血压模块都读取同一份 spo2_measurement_t，不要各自保存一套数值。

## 7. 推荐的软件初始化顺序

1. 初始化时钟和 GPIO。
2. 初始化血压模块 USART3，保持原驱动不变。
3. 初始化现有串口屏 RS232 串口，确认屏幕通信仍正常。
4. 初始化 SPI1：PB3/PB4/PB5、Mode 0、2 MHz。
5. 配置 PA4 为 !CS，默认高。
6. 配置 PC13、PG15 为输出，默认高。
7. 配置 PA0 为输入/EXTI，按示波器观察到的 !DRDY 脉冲边沿配置。
8. 按 AFE 库时序：!PWDN/RESET 保持高，必要时对 START 输出低脉冲复位，再写入 AFE 寄存器。
9. 先输出 RED/IR 原始值到调试日志。
10. 原始波形稳定后，再启用 SpO2/PR 算法和屏幕刷新。
