# 血氧模块 · 代码执行过程与数据链路说明

> 适用工程：`STM32F407_SPO2`（Keil MDK V5.14 / Arm Compiler 5 / 标准库 SPL，非 HAL）
> 主控：STM32F407ZGT6 @ 168MHz
> 编写日期：2026-10-11
> 配套文档：《血氧模块_代码开发设计步骤.md》《血氧模块项目书.md》

---

## 0. 一句话总览

本工程是一条**三级串行数据链**：

```
AFE4490(光电采集) ──SPI──▶ Arduino UNO(算 SpO2/PR) ──UART@57600──▶ STM32F407(USART6)
                                                                      │
                                                          ┌──────────┴──────────┐
                                                      解析/业务逻辑          屏下行驱动
                                                                      │
                                                                  UART@115200
                                                                      │
                                                             大彩串口屏(USART2)
```

- **上行（采集方向）**：AFE4490 → UNO → STM32，UNO 通过 USART6 以 17 字节二进制帧把原始 ADC + 算好的 SpO2/PR 发给 STM32。
- **下行（显示方向）**：STM32 → 屏，通过 USART2 以 `EE … FF FC FF FF` 私有协议帧写文本/曲线/控件。
- **上行回传（交互方向）**：屏 → STM32，按键/切页/滑块通过 USART2 回传通知帧，由 MCU 处理业务逻辑（页面跳转、报警、设置等）。
- **调试方向**：STM32 USART1 打印心跳/抓包，仅用于开发排障。

## 1. 硬件与物理链路（传输的物理介质）

| 链路 | 物理串口 | 引脚 | 波特率 | 电平 | 用途 |
|------|----------|------|--------|------|------|
| UNO → STM32 | USART6 | PC6(TX,当前未用)/PC7(RX) | 57600 | TTL（UNO 5V，PC7 为 FT 脚可吃 5V） | 收 UNO 帧 |
| STM32 → 屏 | USART2 | PA2(TX)/PA3(RX) | 115200 | RS232（经 SP3232 转） | 屏下行驱动 |
| 屏 → STM32 | USART2 | PA3(RX) | 115200 | RS232（经 SP3232 转） | 按键/切页通知 |
| STM32 → PC | USART1 | PA9(TX)/PA10(RX) | 115200 | TTL（直连 USB-TTL） | 调试打印 |

> 屏为**大彩 DC80480DN050（5″ 800×480，DeviceType=21011）**，出厂默认 RS232 电平，TTL 接入前必须经 SP3232 转电平；`DeviceEnableCRC="0"`，下行帧**不带 CRC**。
> 屏工程 `SPO2_Hospital` 的 `DeviceBaudRate="7"` = 115200；血压工程同一型号屏才是 9600，已通过 `main.c` 的自动探测机制兜底。

## 2. 数据链路一：AFE4490 → UNO（采集与预处理，**代码不在本工程**）

- 由 Arduino UNO 跑 `AFE4490_library` 的 **Example-1** 完成：AFE4490 通过 SPI 采集 IR/RED 两路 PPG 光电信号，库内做算法得到 SpO2、脉率(PR)。
- UNO 以 **`Serial.begin(57600)`** 持续发出每帧 17 字节的二进制遥测帧（详见第 3 节帧格式）。
- 这部分固件运行在 UNO 上，本 STM32 工程**只消费**其输出，不负责采集与算法。

---

## 3. 数据链路二：UNO → STM32（帧解析）★核心

### 3.1 接收方式（中断驱动 + 字节流状态机）

- `USART6` 开 `RXNE` 中断，每收到 1 字节进 `USART6_IRQHandler()`（`usart.c`），调用 `UNO_ParseByte(b)`（`uno.c`）。
- **中断里只做"记账 + 入环形缓冲 + 状态机推进"**，不做任何耗时的业务处理，解析完成的完整帧结果写进全局结构体 `g_meas`，并通过 `g_new_frame` 标志通知主循环。

### 3.2 UNO 帧格式（17 字节，小端）

```
偏移   内容
[0]    0x0A          同步1
[1]    0xFA          同步2
[2]    0x0A          数据长度低（DATA_LEN = 10）
[3]    0x00          数据长度高
[4]    0x02          类型 = DATA
[5..8]  IR_data      int32 小端（AFE4490 LED1VAL，红外通道）
[9..12] RED_data     int32 小端（AFE4490 LED2VAL，红光通道）
[13]   spo2          uint8（0~100；0 表示无效/探头错误）
[14]   hr            uint8（脉率 bpm；0 表示无效）
[15]   0x00          保留
[16]   0x0B          帧尾
```

- **同步策略**：先匹配 5 字节头 `0A FA 0A 00 02`，再收 10 字节负载 + 帧尾 `00 0B` 二次校验。即使 IR/RED 数据里出现 `0A/FA` 也不会误同步（头是固定 5 字节序列，且末尾再次校验）。
- 帧率约 **90 帧/秒**（实测），即每秒解析约 90 组 SpO2/PR/PPG。

### 3.3 解析状态机（核心代码：`uno.c` 的 `UNO_ParseByte`）

状态：`S0_SYNC1 → S1_SYNC2 → S2_LENL → S3_LENH → S4_TYPE → S5_PAYLOAD(收10字节) → S6_FOOT1 → S7_FOOT2`

在 `S7_FOOT2` 校验 `foot1==0x00 && b==0x0B` 成功后：
- 小端拼出 `ir_raw`/`red_raw`（`rd_i32_le`）；
- 取出 `spo2`、`pulse_rate`；
- `result_valid = (spo2 != 0)`，`probe_state` 同源，`signal_quality` 暂以占位值（见 6.4）；
- 置 `g_new_frame = 1`（主循环消费后清 0）。

> 诊断辅助：`g_uno_rx_bytes`（累计原始字节）、`g_uno_frames`（成功帧计数）、`UNO_Snapshot()`（取最近 32 字节环形缓冲）用于通过 USART1 判断"UNO 到底有没有在发"。

**核心代码位置**：`HARDWARE/UNO/uno.c`（`UNO_ParseByte`、`rd_i32_le`）；结构体定义见 `HARDWARE/UNO/uno.h` 的 `measurement_t`。

## 4. 数据链路三：STM32 → 屏（下行驱动）★核心

### 4.1 发送方式

- 底层发送 `hmi_tx()`（`dc_hmi.c` 弱定义，**真正实现在 `usart.c`，用 USART2 轮询发送**）：逐字节 `USART_SendData` + 等 `TXE` 标志。
- 帧组装采用"先攒缓冲 `s_tx[320]`，`end_cmd` 时一次性发出"的模式（`begin_cmd`/`put8`/`put16`/`put32`/`putstr`/`end_cmd`）。

### 4.2 屏私有协议帧格式

```
下行：EE <cmd> [sub] <screen:16> <ctrl:16> <param...> FF FC FF FF
上行：EE <cmd> <ctrl_msg> <screen:16> <ctrl:16> <type:8> <param...> FF FC FF FF
```
- 16/32 位参数**高字节在前**；字符串不带 `\0`。
- 帧尾固定 `FF FC FF FF`；本工程**不启用 CRC**（`DeviceEnableCRC="0"`）。

### 4.3 常用下行指令（`dc_hmi.c` 实现）

| 功能 | 指令 | 函数 |
|------|------|------|
| 切换画面 | `EE B1 00 <screen>` | `HMI_SetScreen` |
| 查询当前画面（屏应答） | `EE B1 01` | `HMI_GetScreen` |
| 写文本/进度条/按钮值 | `EE B1 10 <screen> <ctrl> <数据>` | `HMI_SetText` / `HMI_SetProgress` / `HMI_SetButton` |
| 控件显隐 | `EE B1 03 <screen> <ctrl> <visible>` | `HMI_SetControlVisible` |
| 控件使能 | `EE B1 04 <screen> <ctrl> <enable>` | `HMI_SetControlEnable` |
| 实时曲线追加点 | `EE B1 32 <screen> <ctrl> <ch> <len:16> <data...>` | `HMI_GraphAddData` |
| 实时曲线清屏 | `EE B1 33 …` | `HMI_GraphClear` |
| 历史曲线使能 | `EE B1 61 …` | `HMI_HistoryEnable` |
| 历史曲线窗口点数 | `EE B1 63 …` | `HMI_HistoryTimeLength` |
| 历史曲线追加一点 | `EE B1 60 <screen> <ctrl> <value:16>` | `HMI_HistorySampleU16` |
| 批量更新（本屏**不认**，见 4.4） | `EE B1 12 … / EE B3` | `HMI_BatchBegin/…` |
| 设置屏 RTC | `EE 81 <Sec Min Hour Day Week Mon Year>(全BCD)` | `HMI_SetRTCTime` |
| 读屏 RTC | `EE 82` | `HMI_ReadRTC` |
| 背光 | `EE 60 <level>`（0=最亮/255=最暗） | `HMI_SetBackLight` |
| 蜂鸣 | `EE 61 <n>`（n×10ms） | `HMI_Beep` |

### 4.4 关键坑位（已实测）

- **该屏不认"批量更新(B1 12)+刷屏开关(B3)"链路**，会静默丢弃 → 本工程所有写屏一律走单条 `EE B1 10`，不依赖批量指令。
- 中文字符串因 AC5 不支持字符串字面量含非 ASCII（`#870-D`），屏上汉字一律用 **GBK `\xNN` 转义**（见 `app_bloodoxygen.c` 的 `S_*` 宏）。

**核心代码位置**：`HARDWARE/HMI/dc_hmi.c`（全部下行指令拼帧 + 波形映射 + 上行帧解析）；发送真正实现在 `HARDWARE/USART/usart.c` 的 `hmi_tx`。

## 5. PPG 波形处理（原始 ADC → 0~255 → 屏曲线）★核心

### 5.1 处理流程（`dc_hmi.c` 的 `HMI_WavePush → wave_map_and_push`）

1. 主循环每收到 1 帧调用 `on_uno_frame()`（`app_bloodoxygen.c`），把 `g_meas.ir_raw >> 8`（取高 24 位降量纲）送入 `HMI_WavePush`。
2. `wave_map_and_push()` 做固定增益映射：
   - **去直流**：`dc += (raw - dc) >> 6`（慢 EMA，alpha≈1/64，只跟踪基线）。
   - **交流分量**：`ac = raw - dc`。
   - **固定增益放大**：`defl = (ac * WAVE_FIXED_GAIN) >> 8`，`WAVE_FIXED_GAIN=400`（≈×1.56，常量可调）。
   - **基线贴底**：`v = WAVE_BASELINE + defl`，`WAVE_BASELINE=40`（静息基线贴近细带底部，脉搏波**向上拱起**，比居中更直观）；越界夹到 0~255。
3. 映射结果（uint8，0~255）攒进 `s_wave.pts[]`，**攒够 `HMI_WAVE_CHUNK=16` 点** 自动调用 `HMI_WaveFlush()`，发一条 `EE B1 32` 曲线追加帧到主界面 `graph_ppg`(id=19)。
4. 屏端 `graph` 控件只支持**向左滚动**（不支持扫描刷新），每点 1 字节，量程 0~255。

> 注：`dc_hmi.h` 头部旧注释写"滑动窗口极值归一化、窗口=sample_count(300)"，描述的是**早期版本**；当前实现为**固定增益 + 基线贴底**（见 5.1），以实际代码为准。

**核心代码位置**：`HARDWARE/HMI/dc_hmi.c` 第 7 节（`WAVE_*` 常量、`wave_map_and_push`、`HMI_WavePush`、`HMI_WaveFlush`）；触发在 `app_bloodoxygen.c` 的 `on_uno_frame`。

## 6. 上行通知（屏 → MCU）★核心交互

### 6.1 接收方式

- `USART2` 开 `RXNE` 中断，每字节进 `USART2_IRQHandler()`（`usart.c`），调用 `HMI_RxByte(b)`（`dc_hmi.c`）——中断里**只收集字节**（以 `EE` 起头、`FF FC FF FF` 收尾），不解析。
- 主循环周期调用 `HMI_Poll()` 取走整帧并解析（避免在中断里做业务）。

### 6.2 上行帧类型

| 类型 | 长度 | 格式 | 解析后回调 |
|------|------|------|-----------|
| 画面切换通知 | **9 字节** | `EE B1 01 <screen:16> FF FC FF FF` | `NotifyScreen` |
| 控件数据通知（按钮/文本/进度条/滑块） | **14 字节** | `EE B1 11 <screen:16> <ctrl:16> <type:8> <param...>` | `NotifyButton`/`NotifyText`/`NotifyProgress`/`NotifySlider` |
| 屏 RTC 上报 | **13 字节** | `EE F7 Year Mon Week Day Hour Min Sec FF FC FF FF`（BCD） | `NotifyRTC` |

> 坑位：`HMI_Poll` 帧长门限必须 **≤ 9**（2026-10-10 修过：原写 11 会把 9 字节的画面切换通知整条丢弃，导致 `NotifyScreen` 从不调用）。

### 6.3 交互逻辑要点（`app_bloodoxygen.c`）

- 本屏 `DeviceControlNotify="3"`（按下+弹起都上报）→ **一次点击收到两帧**；翻转型动作（`g_paused` 翻转、声音开关）**只在 `state==1`（按下沿）执行**，否则一次点击翻转两次=没反应。
- 按钮分工：`button_type=0` 的按钮（暂停/取消/返回/报警记录行）由**屏原生跳页**；`button_type=1`（继续监护/确认暂停/确认清空/声音/时段）**只上报、不跳页**，跳页由 MCU 发 `HMI_SetScreen(EE B1 00)` 完成。
- 切页/跳页后屏按控件默认属性重绘 → MCU 用 `request_resync()` 安排 4 轮补发 + 每 3 秒一次"自愈补发"，保证 MCU 独占写的文案不丢失。

**核心代码位置**：帧收集 `dc_hmi.c` 的 `HMI_RxByte`/`HMI_Poll`；业务回调 `HARDWARE/HMI/app_bloodoxygen.c` 的 `NotifyButton`/`NotifyScreen`/`NotifySlider`/`NotifyText`/`NotifyRTC`。

## 7. 应用层业务逻辑与数据存储 ★核心

### 7.1 核心数据结构（全部为 **RAM 全局变量**，无外部 Flash/EEPROM 存储）

- `measurement_t g_meas`（`uno.h`）—— UNO 解析结果缓存：
  `red_raw / ir_raw / spo2 / pulse_rate / signal_quality / probe_state / result_valid / monitor_sec`。
- `uint8_t g_new_frame` —— 新帧到达标志（主循环消费后清 0）。
- `uint8_t g_paused` —— 暂停监护标志（`app_bloodoxygen.c`）。
- 设置项：`s_spo2_low=90`(SpO2 报警下限)、`s_pr_high=120`(脉率报警上限)、`s_bright_pct=80`(背光%)、`s_sound_on=1`(声音开关)。
- 软 RTC：`s_year/s_mon/s_day/s_sec_of_day` + 起始 `RTC_INIT_YEAR/MON/DAY`。
- 监护时长：`s_monitor_sec`（暂停时冻结）。
- 报警记录：`alm_rec_t s_recs[4]`（最新在 [0]，最多 4 条），`s_event_total` 累计条数；每通道用 `s_alm_active`/`s_alm_pending_on`/`s_alm_pending_at` 做"持续 3s 才记一条 + 滞回解除"判定。

### 7.2 主循环调度（`main.c`，`DEMO_STEP=4` 全功能）

每拍：
1. `if (g_new_frame)` → 清标志 + `on_uno_frame()`（推 1 个 PPG 波形点，约 90/s；暂停时内部忽略）。
2. `task_hmi_value()` —— **每 400ms**：刷新 SpO2/PR/质量数值、状态文案、报警判定；**暂停时冻结显示**最后一次有效值（新增 `s_frozen_spo2/s_frozen_pr` 缓存，仅"未暂停且有效"时刷新）。
3. `task_hmi_trend()` —— **每 2s**：向屏历史曲线追加 1 点（SpO2/PR，UINT16），暂停/无效时不留洞。
4. `task_clock()` —— **每 1s**：软 RTC 整秒推进（保留毫秒余数防累计误差）+ 累加监护时长（暂停冻结）+ 每 5 分钟用 `EE 81` 同步屏 RTC。
5. `g_meas.monitor_sec = millis()/1000`（诊断用）。
6. `HMI_Poll()` 处理屏上行按键/切页通知（≥DEMO_STEP 2 即启用）。

### 7.3 报警逻辑（`app_bloodoxygen.c`）

- `alm_watch(who, bad, val, rel_ok)`：`bad` 持续 `ALM_HOLD_MS=3000ms` 才 `alm_emit` 记一条；回到滞回阈值（`SpO2≥92` / `PR≤115`）才解除。
- `alm_emit` 生成 `tm/ev/lv/st` 四条文本，插入 `s_recs[0]`（后移旧记录），`s_event_total++`，整轮写屏 `alm_push_rows()`，声音开启时 `HMI_Beep(200)`。
- 主界面状态文本 `MAIN_TXT_SPO2_ST/PR_ST`：正常 / 血氧偏低 / 脉率偏快。

### 7.4 数据存储结论

- **本工程所有生理数据、报警记录、设置项、时间均只存在于 MCU 的 RAM 中，掉电即丢**；趋势曲线由屏端 `historygraph` 控件自带缓存（≤1024 点）保存，同样掉电丢失。
- 如需"关机不丢报警记录/设置"，需后续增加片内 Flash 或 EEPROM 存储（当前未实现）。

**核心代码位置**：`HARDWARE/HMI/app_bloodoxygen.c`（业务逻辑、数值/趋势/时钟/报警/设置/通知回调全在此）；时间基准 `HARDWARE/SYS/sys.c` 的 `millis()`（`SysTick_Config(168000)`→1ms 中断累加 `uwTick`）。

## 10. 关键协议速查（贴墙版）

### UNO → STM32（17B，57600，小端）
```
0A FA 0A 00 02 | IR:i32LE(5..8) | RED:i32LE(9..12) | spo2:u8(13) | hr:u8(14) | 00(15) | 0B(16)
```
匹配头 `0A FA 0A 00 02` + 尾 `00 0B` 双校验；`spo2==0` 视为无效。

### STM32 → 屏（下行，115200，高字节在前，无 CRC）
```
EE <cmd> [sub] <screen:16> <ctrl:16> <param...> FF FC FF FF
```
- 写文本：`EE B1 10 <screen> <ctrl> <字符串>`
- 曲线点：`EE B1 32 <screen> <ctrl> <ch> <len:16> <每点1字节...>`
- 历史点：`EE B1 60 <screen> <ctrl> <value:16>`（UINT16，与屏 `sample_data_foramt=2` 对齐）
- 设 RTC：`EE 81 <Sec Min Hour Day Week Mon Year>(全BCD)`
- 背光：`EE 60 <level(0亮/255暗)>`；蜂鸣：`EE 61 <n×10ms>`

### 屏 → STM32（上行，115200）
```
EE B1 01 <screen:16> FF FC FF FF                        （切页，9B）
EE B1 11 <screen:16> <ctrl:16> <type:8> <param...> FF FC FF FF  （控件，14B）
EE F7 Year Mon Week Day Hour Min Sec FF FC FF FF        （RTC，13B，BCD）
```

## 11. 典型一次完整数据流（以"测到一次有效脉搏"为例）

1. AFE4490 采到光信号 → UNO 算法算出 SpO2/PR + 原始 IR/RED。
2. UNO 每帧 17 字节 @57600 经 USART6 进 `USART6_IRQHandler` → `UNO_ParseByte` 状态机解析 → 写入 `g_meas`，置 `g_new_frame=1`。
3. 主循环见 `g_new_frame` → `on_uno_frame()` 把 `ir_raw>>8` 送 `HMI_WavePush` → 固定增益+基线贴底映射 → 攒 16 点发 `EE B1 32` 让 PPG 波形向左滚动。
4. 每 400ms `task_hmi_value` 把 `g_meas.spo2/pr` 经 `EE B1 10` 写主界面文本；同时 `alm_update` 做报警判定。
5. 每 2s `task_hmi_trend` 把 SpO2/PR 经 `EE B1 60` 追加到趋势历史曲线。
6. 每 1s `task_clock` 推进软 RTC 并经 `EE 81` 同步屏时间、累加监护时长经 `EE B1 10` 写"监护时间"。
7. 用户点"暂停监护"→ 屏回 `EE B1 11…` 通知 → `NotifyButton` 翻转 `g_paused` → 波形/数值/趋势冻结，状态文案改"已暂停/暂停中"。
8. 若 SpO2 持续 <90 满 3s → `alm_emit` 记一条 → 写报警记录页 + `EE 61` 蜂鸣 200ms。
