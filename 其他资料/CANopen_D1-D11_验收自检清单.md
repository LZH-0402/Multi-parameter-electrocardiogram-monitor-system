# Node-A CANopen D1–D11 验收自检清单（NA-11 / NA-12 可观测条件）

> 配套脚本：`其他资料/verify_canopen_d1d11.py`（解析一段 CANopen TPDO 报文记录，自动核查下表大部分项）。
> 本清单把《NodeA_未完成任务清单》NA-11 / NA-12（CANopen 部分）的**每项可观测条件**落成可勾选项。
>
> **当前状态**：D1–D11 代码已全部落地、整工程编译 0E/0W；下表「当前状态」列标注 🟡 的，均需 **Gateway-C 硬件联调**（CAN 收发器/分析仪）后实测勾选。
> **验证手段**两种：
> - **A. 总线抓包**：CAN 分析仪（CANalyst / ZCANPRO / PCAN 等）抓 Node-A 总线，或 Gateway-C 侧 RPDO 落盘后导出。PDO 帧节奏、COB-ID、数据长度只能从总线看。
> - **B. 调试串口**：USART1(115200) 打印 `epoch / tick / 2120 各值 / 2130 flags / boot_generation`，可独立核对定点单位、epoch、位图（但 PDO 节奏与 COB-ID 仍需总线）。
>
> **如何抓包**：见清单末尾「日志格式」与脚本 `--demo` 示例。

| D2 | TPDO 重排为参考 5 路布局 | `0x181`→2110 波形、`0x381`→2120 标量、`0x481`→2100 时钟、`0x681`→2130 有效性；`0x281` 为预留**不发** | 四路映射内容与索引严格对应；0x281 帧计数为 0 | A | 🟡 | [ ] |

## 四、自动脚本使用说明

```bash
# 1) 用 CAN 分析仪把 Node-A 总线录成文本日志（candump 风格或简化风格均可），例如：
#    (123456.789) can0  181   [8]  00 00 E4 9C 00 00 00 00
#    (123456.797) can0  381   [8]  00 00 26 9F 00 00 00 00
#    或简化：  181 0000E49C00000000
#            381 0000269F00000000

# 2) 跑校验（自动输出 D1–D11 各项 PASS/WARN/FAIL）
python verify_canopen_d1d11.py capture.log --verbose

# 3) 无硬件时，用 --demo 生成 2 秒合成日志并自检（验证脚本本身可用）
python verify_canopen_d1d11.py --demo
```

**脚本自动覆盖**：D1(COB-ID 集合)、D2(映射长度)、D3/D4(0x481/0x681 长度)、D5(0x181 长度)、D6(波形节奏)、D7(epoch 范围与递增)、D8(定点/归一化范围)、D9(bit31=0 与各有效位)、D10(标量节奏)、D11(bit3 时效)；NA-11c/d、NA-12a/c/d 部分覆盖。**需人工确认**：真实传感器接入下的位图语义一致性、24h 长稳、uwTick 回绕现场。

### 日志格式（脚本接受两种）
1. **candump 风格**：`(秒.毫秒) canX  COBID   [DLC]  字节 字节 ...`（时间戳可选）
2. **简化风格**：`[时间戳 ]COBID  十六进制数据`（数据可连续或空格分隔）

脚本用纯标准库（`argparse` / `struct` / `re`），无需安装第三方包。
